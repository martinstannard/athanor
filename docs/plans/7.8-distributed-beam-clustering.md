# Implementation Plan — §7.8 Multi-Host Distributed BEAM Clustering (`Athanor.Cluster`)

> **Status: proposed — not yet implemented.**
> Planning artefact only. All paths, functions, topics and behaviours below were verified against the
> current tree (`lib/athanor/{bus,agent,orchestrator,tools,application,config,daemon,tui}.ex`,
> `lib/mix/tasks/{athanor,athanor.daemon}.ex`, `mix.exs`, `test/athanor/*`, `docs/*`). Anything not
> derivable from the code is marked **[OPEN]**.

## 0. Review pass (findings grounded in the current tree)

A read of the realised §7.7 daemon plus the PubSub/registry core surfaced concrete constraints that
shape the whole design. They are not bugs to be "fixed" upstream — they are the reason clustering
needs a plan — but each one is a hard requirement the plan below must satisfy. This table indexes
them.

| # | Finding (verified in the current tree) | Impact on clustering | Addressed in |
|---|---|---|---|
| F1 | `Athanor.Bus.broadcast/2` calls `Registry.dispatch(Athanor.PubSub, topic, …)` (`lib/athanor/bus.ex`). | A `broadcast`/`publish_event`/`send_command` **only reaches subscribers registered on the local node**; a conductor on `host-a` never hears a worker's `{:child_done}` if the worker runs on `host-b`. | §4.1, §6.1 |
| F2 | `Registry.dispatch/3` yields only *local* registrants; `send/2` to a remote pid works fine (`lib/athanor/bus.ex`). | The primitive (Erlang message passing) is already cross-node; only **membership discovery** and **fan-out** are node-local. This is the core lever. | §4.1 |
| F3 | `Athanor.AgentRegistry` is a plain node-local `Registry` (`lib/athanor/application.ex`); `Orchestrator.lookup/1` does `Registry.lookup(Athanor.AgentRegistry, id)`. | `lookup/1`, `session_output/1`, `send_session/2` cannot see a remote session; each node is blind to its peers' sessions. | §2.1, §5.4 |
| F4 | `Orchestrator.generate_id/1` seeds its counter from `Registry.count(Athanor.AgentRegistry)` (also duplicated inline in `Tools.execute("launch_subagent", …)`). | Two hosts can mint the **same** id (`worker-3-ab12`), so a single TUI namespace would collide. | §3.3, §5.3 |
| F5 | `Orchestrator.spawn_session/1` always calls `DynamicSupervisor.start_child(Athanor.AgentSupervisor, spec)` locally. | There is no code path that starts a session on another node. | §5.3 |
| F6 | `Agent.notify/2` → `Bus.publish_event/3`; the conductor's wakeup is a `handle_info({:agent_event, _child, {:child_done, …}}, %{role: :conductor})` clause. | Parent wakeups and inbox commands are exactly the messages F1 breaks; the *handler* is already correct and needs no change once fan-out is fixed. | §4.3, §5.3 |
| F7 | `Tools.execute("bash", …, cd:)` runs `System.cmd("bash", ["-c", cmd], cd: cd)` **in the executing process** (spawned by the owning `Athanor.Agent`); `read_file`/`write_file`/`edit_file` use `resolve_path/2` against the same `cd`. | A session's tools always run on **that session's node**. `cd` is that host's filesystem. There is **no** path translation and none is proposed. | §1, §5.3, §10 |
| F8 | `Athanor.Daemon` hard-codes `@default_cookie :athanor_local_secret_cookie`, starts the node with `:longnames`, and names TUI clients `athanor_tui_<hex>@127.0.0.1` (`lib/athanor/daemon.ex`). | The default cookie is a published constant; `:longnames` + a loopback name block LAN short-name clusters (`athanor@host-b`). Both must become configurable and the weak cookie must be rejected off-host. | §5.1, §6.4, §8 |
| F9 | `Daemon.fetch_full_sessions/1` runs `:erpc.call(target_node, Orchestrator, :list_sessions, [])` against **one** node. | The TUI can hydrate only the daemon it attached to, not the peer hosts. | §5.4 |
| F10 | `Daemon.connect_or_start_daemon/1` **auto-starts a local** daemon when the target is unreachable. | Multi-host needs "connect to a configured peer host", not "spawn another local daemon". | §5.1 |
| F11 | Sessions are `:temporary` children of the **local** `DynamicSupervisor` and are **not linked** to a (possibly remote) `parent_id`. | If a conductor's node dies, its remote workers keep running with no parent → orphans. Nothing reaps them. | §5.5 |
| F12 | `:pg` (OTP process groups) is **not** running by default — verified: `Process.whereis(:pg) == nil` and `:pg.join/2` raises `no process` until `:pg.start_link/0` is called (OTP 28, Elixir 1.19.5). | Any `:pg`-based backend must start the scope explicitly as a supervised child; it is not a free win. | §2.3, §4.1 |
| F13 | `Daemon.attach_subscriber/2` already spawns a monitored relay **on the target node** that subscribes to `"deck:events"` and forwards `{:agent_event, id, event}` to a remote client pid. | The remote-attach pattern is proven and reusable; with a cluster-wide bus one relay suffices for the whole cluster. | §4.1, §5.4 |
| F14 | `:peer` is available (verified: `function_exported?(:peer, :start, 1) == true`). | Multi-node tests can boot real peer VMs, not mocks. | §9 |
| F15 | There is **no `config/` directory**; every default is a `Athanor.Config` module attribute + env var + `Application.get_env(:athanor, …)`. | Cluster config must follow the same idiom; no `config/*.exs`. | §8 |

## 1. Scope & Non-goals

### In scope
- **Node identity & membership**: a new `Athanor.Cluster` GenServer that validates node name/type and
  cookie, bootstraps `Node.connect/1` for a configured peer list, tracks `:net_kernel` up/down
  events, and exposes a resolved member list (`host-a`, `host-b`, `host-c`, …).
- **Distributed PubSub**: a backend abstraction inside `Athanor.Bus` so the *same*
  `subscribe/1` / `broadcast/2` / `publish_event/3` / `send_command/2` API fans out across the
  cluster, with the current single-node `Registry` path preserved as the default.
- **Cluster-wide session visibility**: a new `Athanor.Cluster.Sessions` module that fans
  `Orchestrator.list_sessions/0` / `session_output/1` across members via `:erpc`, merges and tags the
  results with `:node`, and powers a multi-host TUI deck.
- **Remote worker placement**: `launch_subagent` (tool + orchestrator) gains a `node:`/`host:` target;
  a remote spawn is executed on the peer's own `Athanor.AgentSupervisor` (so ownership and tool
  execution stay correct) and the parent is woken through the cluster bus.
- **Failure semantics**: `:nodedown` handling, synthetic `{:child_done, status: "fail"}` for remote
  children on a lost host, and a `Athanor.Cluster.Reaper` for orphaned sessions.
- **Security posture**: strong-cookie enforcement, name/type rules, and a documented trust model.
- **Cluster-aware Daemon/TUI**: configurable node name/type, host-aware client names, a peer target
  instead of "auto-start local", cluster hydration, and host-badged deck rows.
- Unit + multi-node integration tests built on `:peer`.

### Non-goals (explicitly excluded)
- **Not** implementing §7.2 Goal / §7.3 Watchers / §7.4 Store / §7.5 Memory / §7.6 MCP — although
  §7.2's `GoalManager` (and any future Watcher) becomes cluster-visible for free once `Bus` is
  distributed, and §7.4's transcripts are the natural place for per-node session metadata.
- **Not** sharing or translating filesystems across hosts. `cd`, `read_file`, `write_file`,
  `edit_file` and `bash` remain strictly host-local (F7). A `cd` handed to a remote worker is
  interpreted **on that host**; coordinating equal paths across hosts is out of scope (see §7.1 and
  §10 risk 7).
- **Not** implementing service discovery (mDNS/Consul/K8s). Cluster membership is an **explicit node
  list** in v1 (gossip/auto-discovery is flagged **[OPEN]**, §10).
- **Not** implementing elastic/Horde-style distributed supervision in v1; per-node supervision +
  cross-node orchestration is the recommended model and Horde is documented as an alternative
  (§6.2).
- **Not** implementing TLS distribution (`-proto_dist inet_tls`) in v1; v1 requires a trusted
  network/overlay and a strong cookie (§6.4, §10).
- No changes to `Athanor.LLM`, the agent loop, or `Athanor.Markdown`.
- **Single-node behaviour must remain byte-identical**: with `cluster_nodes` empty the system must
  take exactly today's code path and existing tests must pass unchanged.

## 2. Architecture

### 2.1 New modules

| Module | Kind | Responsibility |
|---|---|---|
| `Athanor.Cluster` | `GenServer` | Node identity/cookie validation, `Node.connect/1` bootstrap + reconnect, `:net_kernel` up/down tracking, explicit member list, `resolve/1` (host string → node), `/hosts` status. |
| `Athanor.Cluster.Member` | struct + pure funcs | A peer record: `node`, `host`, `status` (`:connected \| :connecting \| :down \| :rejected`), `connected_at`, `last_error`. |
| `Athanor.Cluster.Sessions` | module (pure + RPC) | Cluster-wide enumeration: fan `Orchestrator.list_sessions/0` / `session_output/1` over `[Node.self() \| Node.list()]` with a bounded `:erpc` timeout; tag each map with `:node`; merge. |
| `Athanor.Cluster.Reaper` **[proposed, phase 5]** | `GenServer` | Periodically GCs **orphaned** sessions whose `parent_id` has no live, reachable owner anywhere in the cluster. |
| `Athanor.Bus.Backend` **[proposed]** | behaviour | `join/2`, `leave/2`, `members/1`, `register/2`, `dispatch/3` — lets `Bus` swap its fan-out implementation without changing the public API. |
| `Athanor.Bus.Local` **[proposed]** | module | Current implementation (`Athanor.PubSub` `Registry`, `keys: :duplicate`). Default. |
| `Athanor.Bus.Distributed` **[proposed]** | module | `:pg`-backed implementation (`:pg.join/2`, `:pg.get_members/1`). Selected only when clustering is enabled. |

### 2.2 Changes to existing modules
- `Athanor.Bus` — keep every public function (`subscribe/1`, `unsubscribe/1`, `broadcast/2`,
  `publish_event/3`, `send_command/2`) and its return contracts **identical**; delegate the
  register/dispatch internals to `Athanor.Config.pubsub_backend/0`'s module. `publish_event/3` and
  `send_command/2` need **no** change beyond calling the backend (F1/F2/F6).
- `Athanor.Application` — add `Athanor.Cluster`; when the distributed backend is selected, add an
  explicitly-started `:pg` child (F12). Keep `Athanor.AgentRegistry` / `Athanor.PubSub` /
  `Athanor.AgentSupervisor` exactly as-is.
- `Athanor.Orchestrator` — add a `node:` option to `spawn_session/1` and `launch_subagent/4`
  (remote spawn via `:erpc`); add `lookup/2` (node-aware), `list_cluster_sessions/0`; leave
  `lookup/1`, `list_sessions/0`, `session_output/1`, `send_session/2` local-by-default so existing
  tests are untouched. Harden `generate_id/1` against cross-node collisions (F4).
- `Athanor.Agent` — add `node: Node.self()` to `snapshot_meta/1` and `get_state/1` so the deck can
  badge the host; **no** change to the loop, PubSub subscriptions, or `maybe_publish_child_done/2`.
- `Athanor.Tools` — extend `launch_subagent` schema/exec with an optional `node`; add a read-only
  `list_hosts` conductor tool; make `list_sessions` optionally cluster-wide. Workspace tools are
  **unchanged** (they stay host-local by design).
- `Athanor.Daemon` — make name/type configurable (`:shortnames`/`:longnames`), derive the node name
  from `Athanor.Config.node_name/0`, accept an explicit peer target instead of always auto-starting a
  local daemon (F8/F10), and make `fetch_full_sessions/1` cluster-aware by delegating to
  `Athanor.Cluster.Sessions` (F9).
- `Athanor.Config` — add cluster accessors (§8).
- `Athanor.TUI` — render a `@host` suffix on session rows and the status bar; hydrate from
  `Athanor.Cluster.Sessions`; accept `@host`-qualified targets in `/spawn` and `/conductor`; add a
  `/hosts` command.
- `lib/mix/tasks/athanor.cluster.ex` **[proposed]** — a thin `mix athanor.cluster --status/--join
  <node>/--leave <node>` operator task mirroring `Mix.Tasks.Athanor.Daemon`.

### 2.3 Supervision placement (extends design §2)

```text
Athanor.Supervisor (:one_for_one)                     # ONE PER NODE — e.g. on host-a
├── Athanor.AgentRegistry     (Registry, :unique)      # existing: LOCAL sessions on this node only
├── Athanor.PubSub            (Registry, :duplicate)   # existing: kept for the :local backend
├── Athanor.AgentSupervisor   (DynamicSupervisor)      # existing: LOCAL sessions only
├── Athanor.Cluster           (GenServer)             [NEW]  # membership + identity/cookie guard
├── Athanor.PG                (:pg scope)             [NEW, only if backend == :distributed]
└── Athanor.Cluster.Reaper    (GenServer)             [NEW, phase 5]

# Logical cluster view (three independent VMs joined by Node.connect/1):
#   athanor@host-a  ─┐
#   athanor@host-b      ├─ :pg scope "athanor" replicates every Bus topic across all three
#   athanor@host-c        ─┘
#   ...each node runs its OWN Athanor.Supervisor and its OWN local AgentSupervisor.
```

Ordering rationale: `Athanor.Cluster` starts **after** `Athanor.PubSub`/`Athanor.AgentRegistry`
(so the local bus is live before peers can broadcast to us — important because, on connect, a peer may
immediately fan out) and **before** `Athanor.AgentSupervisor` only in the sense that we do **not**
want to accept remote fan-out before we can serve it — the existing tree already starts both
`Registry` children before the `DynamicSupervisor`, and clustering preserves that order.
`Athanor.PG` must precede `Athanor.Cluster` if the distributed backend is chosen, because `Cluster`
may join membership groups (F12).

> **[OPEN]** `:pg`'s default scope is not auto-started (F12). Two shapes are viable:
> (a) a `%{id: Athanor.PG, start: {:pg, :start_link, []}}` child (verified `:pg.start_link/0` exists
> on OTP 28), or (b) a **named scope** via `:pg.start_link(:athanor)`. Recommend (a) with the default
> scope so `:pg.join/2` / `:pg.get_members/1` (arity-2/1, the stable API) are used. Confirm whether
> the project targets an OTP where `:pg` is kernel-started before relying on it.

### 2.4 PubSub topics / handlers (delivery becomes cluster-wide, names unchanged)

| Topic | Publisher | Subscriber | Payload |
|---|---|---|---|
| `"agent:<id>:inbox"` | TUI / Conductor / `Orchestrator` (**any node**) | `Athanor.Agent` (`<id>`) **on its own node** | `{:bus_command, {:prompt, text} \| {:enqueue_prompt, text} \| :cancel}` |
| `"agent:<id>:events"` | `Athanor.Agent` | blocking `wait: true` callers **on any node**, watchers | `{:agent_event, id, event}` |
| `"conductor:<id>:children"` | `Athanor.Agent` whose `parent_id == id` | parent Conductor (`<id>`) **even if on another host** | `{:agent_event, child_id, {:child_done, report} \| event}` |
| `"deck:events"` | every `Athanor.Agent` | TUI relay(s), loggers | `{:agent_event, id, event}` |
| `"cluster:members"` **[NEW]** | `Athanor.Cluster` | `Athanor.Cluster.Sessions`, `/hosts` subscribers, tests | `{:cluster_event, {:member_up \| :member_down, node}}` |

The topic **grammar does not change**; only the delivery fabric does. This is the single most
important property of the design: every existing subscriber keeps its clauses, and `Bus` remains a
thin façade (F1/F2/F6).

## 3. Data Structures

### 3.1 `Athanor.Cluster.Member` **[proposed]**

```elixir
defmodule Athanor.Cluster.Member do
  @moduledoc "A peer Athanor node in the cluster (design §7.8)."

  @type status :: :connected | :connecting | :down | :rejected

  @enforce_keys [:node]
  defstruct [:node, :host, status: :connecting, connected_at: nil, last_error: nil]

  @type t :: %__MODULE__{}
end
```

`host` is a display label derived from the node name (`:"athanor@host-b"` → `"host-b"`), used by the
TUI and by `Cluster.resolve/1`.

### 3.2 Cluster-aware session snapshot

`Orchestrator.list_sessions/0` already returns maps shaped
`%{id, pid, title, role, parent_id, status, model, message_count, last_assistant}`. The cluster
enumerator returns the same shape **plus** two keys, so nothing downstream must be rewritten:

```elixir
%{
  id: "worker-host-b-3f2a",
  pid: #PID<...>,            # a REMOTE pid; usable with send/GenServer.call across the cluster
  node: :"athanor@host-b",   # [NEW] owning node
  host: "host-b",            # [NEW] display label
  title: "Audit tests",
  role: :worker,
  parent_id: "conductor-main",
  status: :idle,
  model: "deepseek-v4.1-flash",
  message_count: 12,
  last_assistant: "…"
}
```

> Cross-node `send/2` and `GenServer.call(remote_pid, :get_state)` **already work** over Erlang
> distribution (F2). The only reason a remote session is invisible today is that the *registry*
> (F3) and the *broadcast* (F1) are node-local — not because pids are unusable. This plan exploits
> that: the cluster index stores **remote pids**, and `Agent.get_state(pid)` succeeds across nodes
> with no new RPC surface (subject to a bounded timeout, §5.4).

### 3.3 ID scheme (collision fix, F4)

Today `Orchestrator.generate_id/1` and the inline generator in
`Tools.execute("launch_subagent", …)` both derive their counter from the **local**
`Registry.count(Athanor.AgentRegistry)`. Under a cluster that is guaranteed to collide. Proposed
scheme (pure-string, no registry dependency):

```elixir
# Orchestrator.generate_id/1  [CHANGED]
defp generate_id(prefix) do
  suffix = Base.encode16(:crypto.strong_rand_bytes(3), case: :lower)
  "#{prefix}-#{node_short()}-#{suffix}"      # e.g. "worker-host-b-3f2ab1"
end

defp node_short, do: Athanor.Cluster.host(Node.self())   # "host-b" | "local"
```

When clustering is disabled, `node_short/0` returns `"local"` and ids stay unique within the single
node; existing tests that assert on explicit ids remain valid.

> **Backwards-compatibility note.** `test/athanor/orchestrator_test.exs` passes explicit ids
> (`"worker-audit"`, `"conductor-test"`), and `Daemon` uses the literal `"conductor-main"`; none of
> those go through `generate_id/1`, so the change is safe. The generated-id shape changes only for
> implicit spawns. **[OPEN]** §10 OQ2 — whether to keep `node` in the id *string* or carry it as
> metadata only.

## 4. Message & PubSub Protocol

### 4.1 The core change: cross-node fan-out in `Athanor.Bus`

Today (`lib/athanor/bus.ex`), all three of these are local by construction:

```elixir
# subscribe/1
{:ok, _} = Registry.register(@pubsub, topic, [])
# broadcast/2
Registry.dispatch(@pubsub, topic, fn entries -> for {pid, _} <- entries, do: send(pid, message) end)
```

`Registry.dispatch/3` only ever yields processes registered **on the calling node** (F1/F2). To make
topics cluster-wide we introduce a backend and select it by config:

```elixir
defmodule Athanor.Bus do
  alias Athanor.Config

  defp backend, do: Config.pubsub_backend()        # Athanor.Bus.Local | Athanor.Bus.Distributed

  @spec subscribe(String.t()) :: :ok
  def subscribe(topic) when is_binary(topic) do
    backend().join(topic, self())
    :ok
  end

  @spec broadcast(String.t(), term()) :: :ok
  def broadcast(topic, message) when is_binary(topic) do
    backend().dispatch(topic, message)
    :ok
  end
  # publish_event/3 and send_command/2 are UNCHANGED — they call subscribe/broadcast.
end
```

```elixir
defmodule Athanor.Bus.Local do
  @moduledoc "Single-node backend: the existing Athanor.PubSub Registry (keys: :duplicate)."
  @behaviour Athanor.Bus.Backend
  @pubsub Athanor.PubSub

  @impl true
  def join(topic, pid), do: {:ok, _} = Registry.register(@pubsub, topic, [], pid: pid)

  @impl true
  def dispatch(topic, message) do
    Registry.dispatch(@pubsub, topic, fn entries ->
      for {pid, _} <- entries, do: send(pid, message)
    end)
  end
end

defmodule Athanor.Bus.Distributed do
  @moduledoc "Cluster backend: :pg process groups (verified API: :pg.join/2, :pg.get_members/1)."
  @behaviour Athanor.Bus.Backend

  @impl true
  def join(topic, pid), do: :pg.join(topic, pid)

  @impl true
  def dispatch(topic, message) do
    for pid <- :pg.get_members(topic), do: send(pid, message)
  end
end
```

Key properties:
- **API frozen.** `Bus.subscribe/1`, `broadcast/2`, `publish_event/3`, `send_command/2` keep their
  exact signatures and `:ok` returns; `Athanor.Agent`, `Athanor.Orchestrator`, `Athanor.Tools`,
  `Athanor.Daemon`, `Athanor.TUI` need **zero** call-site changes for fan-out.
- **`send/2` to a remote pid is native.** `:pg.get_members/1` returns pids on **all connected
  nodes**; each is `send/2`-able (F2).
- **Single-subscribe safety.** `:pg.join/2` is idempotent per `{group, pid}`, unlike the
  `:duplicate` `Registry` (this is exactly the C4 hazard noted in the §7.2 plan) — a small
  improvement that comes for free.
- **`:pg` must be started** (F12): the distributed backend is only selectable when the `:pg` scope
  child is running; `Athanor.Application` adds it conditionally (§2.3).

> **[OPEN]** `:pg` membership is *eventually consistent*: after `Node.connect/1` returns, `:pg`
> members from the peer may take a few milliseconds to appear (F12/§5.1 join barrier). Also, on a
> net-split `:pg` keeps both sides' views and reconciles on heal — this is acceptable for Athanor's
> fire-and-forget PubSub, but must be documented (§10 risk 1). The alternative backends
> (Phoenix.PubSub `PG2` adapter, explicit per-topic relays) are compared in §6.1.

### 4.2 Subscription lifecycle

- `Athanor.Agent.init/1` already calls `Bus.subscribe("agent:#{id}:inbox")` (and conductors also
  `Bus.subscribe("conductor:#{id}:children")`). Under the distributed backend these join the `:pg`
  groups cluster-wide, so **no `Athanor.Agent` change is needed** to receive remote commands.
- `Athanor.Daemon.attach_subscriber/2` spawns a relay on the target node that subscribes to
  `"deck:events"` (F13). Under `:pg`, that single relay now sees **every host's** deck events, so one
  relay per attached TUI client is enough — the relay code is unchanged.
- `Tools.execute("launch_subagent", wait: true, …)` subscribes to `"agent:<child_id>:events"` before
  spawn and `await_subagent/2`s on `{:turn_complete, output}`; with `:pg` this works even when the
  child is spawned on a peer.

### 4.3 Event catalogue (additions only)

| Event | Channel | Payload |
|---|---|---|
| `{:child_done, report}` | `"conductor:<cid>:children"` | Existing shape `%{child_id, title, status, summary, output}` — now delivered **cross-node**; on host loss the `Cluster` synthesizes one with `status: "fail"` (§5.5). |
| `{:cluster_event, {:member_up, node}}` **[NEW]** | `"cluster:members"` | A node joined and answered the join barrier. |
| `{:cluster_event, {:member_down, node}}` **[NEW]** | `"cluster:members"` | `:nodedown`, epmd loss, or `Node.disconnect/1`. |
| `{:host_lost, node, [child_id]}` **[NEW]** | `"deck:events"` / TUI | Advisory for the deck ("host `host-b` unreachable; 2 children lost"). |

The existing `{:agent_event, id, event}` framing, `{:session_started, meta}`, `{:status, _}`,
`{:text_delta, _}`, `{:tool_start|:tool_end, …}`, `{:turn_complete, _}`, `{:error, _}`, `:cancelled`
vocabulary is **unchanged** (design §3 / `docs/architecture.md` §6).

### 4.4 A cross-node wakeup, end to end

```text
node host-a                                │            node host-b
──────────────────────────────────────────────┼──────────────────────────────────────────────
Conductor "conductor-main"                    │
   │ launch_subagent(node: :"athanor@host-b") │
   │ ── :erpc.call(host-b, Orchestrator,      │
   │      :launch_subagent, [ … node: … ]) ───┼──► AgentSupervisor.start_child(worker-…)
   │                                          │        │ init/1: Bus.subscribe("agent:worker-host-b-x:inbox")
   │                                          │        │ (joins :pg group, replicated to host-a)
   │◄── {:ok, "worker-host-b-…", <remote pid>}┼────────┘
   │                                          │        │ … LLM + tools run on host-b …
   │                                          │        │ notify/2 → Bus.publish_event(worker, parent, {:child_done, r})
   │                                          │        │ → :pg.get_members("conductor:conductor-main:children")
   │◄── {:agent_event, "worker-host-b-…",     │        │   → send(host-a_pid, msg)   (cross-node send)
   │       {:child_done, %{…}}} ──────────────┼────────┘
   │ handle_info({:agent_event, _, {:child_done, %{…}}}, %{role: :conductor})  ← UNCHANGED clause
   │ do_enqueue_prompt("[DONE] Sub-agent …")  │
```

No new conductor handler, no new agent code. The whole change is "make the Bus cluster-wide".

## 5. Behavioral Flow

### 5.1 Cluster join / bootstrap

`Athanor.Cluster.start_link/1` runs on every Athanor node:

1. **Identity validation (F8).** Resolve the node name from `Config.node_name/0`
   (`ATHANOR_NODE_NAME`, default `:"athanor@#{hostname}"`) and name type from
   `Config.node_name_type/0` (`:shortnames` default for LAN host names like `host-b`; `:longnames`
   for FQDN/remote). If the node is not already alive, call `Node.start(name, type)` (mirrors
   `Daemon.ensure_distributed_node/1`, but parameterised).
2. **Cookie validation.** `cookie = Config.cluster_cookie/0` (`ATHANOR_CLUSTER_COOKIE` →
   `ATHANOR_COOKIE` → `~/.erlang.cookie`). If `Config.cluster_nodes/0` is non-empty **and** the
   resolved cookie equals the hard-coded default `:athanor_local_secret_cookie`, **refuse to start**
   with a descriptive error (§6.4). Otherwise `Node.set_cookie(cookie)`.
3. **Bootstrap connect.** For each `node in Config.cluster_nodes/0`: `Node.connect(node)`; record a
   `%Member{status: :connecting}` then `:connected`. Nodes that fail are retried on a bounded
   backoff (`Config.cluster_reconnect_ms/0`).
4. **Monitor membership.** `:net_kernel.monitor_nodes(true, node_type: :visible)`; publish
   `{:cluster_event, {:member_up|:member_down, node}}` on `"cluster:members"`.
5. **Join barrier.** After a peer connects, exchange a cheap application-level ping
   (`:erpc.call(node, __MODULE__, :ping, [])`) and wait until the peer is in the `:pg` view
   (`:pg.get_members("cluster:members")` includes it) or a short deadline elapses, so the first
   broadcast is not silently lost (F12/§10 risk 1).
6. Publish `{:cluster_event, {:member_up, node}}` and log via `Logger`.

> **Reconnect policy [OPEN].** v1 is a bounded retry loop inside `Athanor.Cluster`. Whether to also
> scan EPMD / `:net_adm.names` for auto-discovery, or to require an external orchestrator (Tailscale,
> systemd, K8s headless Service), is deferred (§10 OQ3).

### 5.2 Distributed PubSub install

Pure config-gated selection, no runtime flipping:

```elixir
# Athanor.Config
def pubsub_backend do
  case Application.get_env(:athanor, :pubsub_backend, backend_from_env()) do
    :distributed -> Athanor.Bus.Distributed
    _ -> Athanor.Bus.Local

```

`pubsub_backend/0` returns `Athanor.Bus.Distributed` iff `ATHANOR_PUBSUB_BACKEND=distributed` **or**
`cluster_nodes` is non-empty; otherwise `Athanor.Bus.Local` (today's exact behaviour). Because the
bus API is frozen (§4.1), enabling clustering is a configuration change, not a code change at every
call site.

### 5.3 Remote worker placement

`launch_subagent` gains a target host:

- **Tool:** `launch_subagent(title, prompt, wait?, node?)` where `node` is a host label (`"host-b"`)
  or a node name (`"athanor@host-b"`).
- **Orchestrator:** `launch_subagent(parent_id, title, prompt, opts)` accepts `node: node()`
  (default `Node.self()`). If `node == Node.self()` the existing local path runs (F5 unchanged
  otherwise). If not:

```elixir
# Athanor.Orchestrator  [CHANGED / NEW branch]
def launch_subagent(parent_id, title, prompt, opts) do
  target = Keyword.get(opts, :node, Node.self())

  if target == Node.self() do
    do_spawn_local(parent_id, title, prompt, opts)         # existing body
  else
    case Athanor.Cluster.resolve(target) do
      {:ok, peer} ->
        remote_opts = Keyword.drop(opts, [:node])
        :erpc.call(peer, __MODULE__, :launch_subagent, [parent_id, title, prompt, remote_opts],
                   Athanor.Config.cluster_erpc_timeout_ms())

      :error ->
        {:error, {:host_not_found, target}}
    end
  end
end
```

Consequences that must be honoured:
- The child is started **on the peer**, so it is a child of the **peer's** `Athanor.AgentSupervisor`
  and registered in the **peer's** `Athanor.AgentRegistry` (F3/F5). Ownership, crash isolation, and
  `Agent.get_state/1` all stay host-local.
- `Tools.execute/3` inside that worker runs on the peer (F7). `cd` is the peer's filesystem. Tool
  execution and `bash` are therefore correct-by-construction with **no** substitution.
- The parent learns completion through the cluster bus (§4.4). The `wait: true` path works because
  its `"agent:<child_id>:events"` subscription is now cluster-wide.
- The returned `pid` is a **remote pid**; `Orchestrator.lookup/1` (local) will not find it, so the
  tool must surface `node` alongside `child_id` and downstream callers must use
  `Orchestrator.lookup/2`.

> **FS footgun (documented, not solved).** A conductor on `host-a` editing `./src/foo.ex` while
> its remote worker on `host-b` edits `./src/foo.ex` are editing **different files** that happen to
> share a path. Mitigations to call out for operators: pass absolute paths, use §7.1 worktrees per
> host, or confine a task to one host. No path mapping is proposed (§1 non-goals).

### 5.4 Cluster-wide enumeration & control (the single TUI)

- `Athanor.Cluster.Sessions.list/0` fans out:

```elixir
def list do
  [Node.self() | Node.list()]
  |> Task.async_stream(&fetch/1, timeout: Config.cluster_erpc_timeout_ms(), on_timeout: :kill_task)
  |> Enum.flat_map(fn
       {:ok, sessions} -> sessions
       _ -> []
     end)
end

defp fetch(node) do
  case :erpc.call(node, Athanor.Orchestrator, :list_sessions, [],
         Athanor.Config.cluster_erpc_timeout_ms()) do
    sessions when is_list(sessions) -> Enum.map(sessions, &Map.put(&1, :node, node))
    _ -> []
  end
catch
  _, _ -> []
end
```

- **Bounded timeouts matter**: a partitioned peer must never hang the TUI. `:erpc.call/5` with an
  explicit timeout plus `Task.async_stream` `on_timeout: :kill_task` degrades a dead host to "no
  rows" rather than a frozen deck (§10 risk 2).
- **Control** (`send_session`, `cancel_session`, nudges, `Esc`) needs **no** node-aware code: the
  owner `Athanor.Agent` subscribed to `"agent:<id>:inbox"` on its own node, so a `Bus.send_command/2`
  from any node reaches it once `:pg` is the backend (§4.1).
- **Hydration**: `Daemon.fetch_full_sessions/1` is re-pointed at `Athanor.Cluster.Sessions` (per
  session, `:erpc.call(node, Orchestrator, :session_output, [id])`) so an attached TUI hydrates the
  whole cluster (F9). `Athanor.TUI.new/1` + `hydrate_sessions/2` already accept a list of session
  maps; they gain a `:node`/`:host` passthrough.
- **Rendering**: `ordered_tree_entries/1` groups conductors and children by `parent_id` across hosts;
  each row appends `@host` when `host != local`. A disconnected host's rows render with the `✕`
  badge until a re-list confirms removal.

> **[OPEN]** Deck keying. If ids are made cluster-unique (§3.3) the TUI can keep keying `sessions` by
> `id`. If any deployment disables the id change, the TUI must key by `{node, id}`. §10 OQ2.

### 5.5 Failure semantics

- **`:nodedown` (crash, partition, epmd loss).** `Athanor.Cluster` transitions the member to `:down`
  and publishes `{:cluster_event, {:member_down, node}}`. `Athanor.Cluster.Sessions` drops that
  node's rows on the next list. `Athanor.Cluster.Reaper` (below) and the **loss notifier** run.
- **Loss notifier (prevents conductors hanging forever).** For every *remote* child known to live on
  the lost node (`parent_id` present, `node == lost`), the cluster synthesizes and delivers to the
  parent's inbox:

  ```elixir
  report = %{child_id: id, title: title, status: "fail",
             summary: "host #{host} unreachable", output: nil}
  Bus.publish_event(id, parent_id, {:child_done, report})
  ```

  This reuses the **existing** conductor wakeup clause (F6) with `status: "fail"`, so the conductor
  is informed and can re-plan instead of blocking on a `[DONE]` that will never come. Same-host
  children are unaffected (their node is still alive).
- **Orphaned sessions (F11).** Workers are `:temporary` children of their **own** node's supervisor
  and are **not linked** to the (possibly remote) conductor. If the conductor's host dies while the
  worker's host survives a partition, the worker keeps running with no live parent. `Athanor.Cluster.Reaper`
  (phase 5) periodically computes the set of live, reachable conductor ids across the cluster and, for
  any session whose `parent_id` is absent cluster-wide for more than `cluster_reap_after_ms`, either
  (a) cancels it (`Bus.send_command(id, :cancel)` + terminate child) or (b) re-parents it to a local
  fallback conductor. **[OPEN]** §10 OQ4 — default policy (cancel vs. adopt).
- **Reconnect.** On reheal, `:net_kernel` fires `nodeup`; `Athanor.Cluster` re-runs the join barrier
  (§5.1) and re-lists sessions. `:pg` reconciles duplicate memberships. Sessions that died while
  partitioned simply do not reappear (they were `:temporary`); no ghost rows survive a re-list.
- **Local node unaffected.** A peer going down must never take down the local `Athanor.Supervisor`;
  `:erpc` failures are caught and converted to `[]`/`{:error, _}` (§5.4).

## 6. Distribution Strategies Compared

### 6.1 PubSub fan-out (choose the mechanism that makes `broadcast/2` cluster-wide)

| Option | Mechanism | Pros | Cons | Verdict |
|---|---|---|---|---|
| **`:pg` (OTP)** | `:pg.join/2` + `:pg.get_members/1`, cluster-replicated groups | Zero deps; near-identical topic semantics; `send/2` already works remote; idempotent join (fixes duplicate-subscribe hazard); part of OTP kernel | Default scope must be started (F12); membership lags after connect (needs join barrier); `:pg` views diverge on net-split and reconcile on heal; no per-process metadata | **Recommended.** Smallest change that satisfies "standard Erlang message passing, join a cluster". |
| Phoenix.PubSub | `Phoenix.PubSub.PG2` adapter ([`:pg`-based]) with local-dispatch fast path | Battle-tested fan-out, per-node shards, well-understood | New dep; must reimplement `Bus`'s fire-and-forget-return-`:ok` semantics on top; adds config surface for a thin wrapper that is barely 30 LOC today | Fallback if `:pg` proves too coarse. **[OPEN]** |
| `:global` | `:global.register_name/2` + `send` | Built-in; unique names cross-node | Single lock bottleneck (the `:global` server); intended for *named processes*, not high-fan-out topics; poor fit for a `:duplicate`-style multi-subscriber topic | Reject for PubSub. |
| Explicit relays | Each node runs a relay subscribed to local topics, forwards to peer relays over dist (pattern already in `Daemon.start_remote_relay/1`) | Full control; no `:pg`; works with any topology | Most code; must dedupe and handle reconnects by hand; O(nodes) relays; reinvents `:pg` | Reject unless `:pg` is disallowed. |

### 6.2 Registry & supervision across hosts

| Option | What it gives | Pros | Cons | Verdict |
|---|---|---|---|---|
| **Per-node registry + cluster index (proposed)** | Sessions stay owned/registered on their own node; a new `Cluster.Sessions` enumerates over `:erpc` | Ownership = crash isolation = host locality; `lookup/1` stays fast/local; remote pids are still usable (§3.2); no new invariant on ids | Enumeration is O(nodes) RPC per refresh; ids must be made cluster-unique (§3.3) | **Recommended.** |
| `:global` registry | One cluster-wide name per session | Simple `:global.whereis_name/1` | Serialised through the `:global` lock on every register/lookup; needs `read_concurrency` tuning; overkill; `:global` already used for cluster-wide *locks*, not per-session lookups | Reject. |
| `Horde.Registry` + `Horde.DynamicSupervisor` | Distributed unique registry + distributed supervisor with elastic placement | Real cross-node supervision; CRDT merge on partition; placement policy | New dep; changes supervision ownership semantics (a session may be "owned" cluster-wide, not host-local); Horde's `:duplicate` key mode is newer/less common; makes tool/`cd` locality less obvious | Documented alternative; **[OPEN]** for a later "elastic placement" phase. |
| `:pg` only (no registry change) | PubSub works cluster-wide, but `lookup/1` still local | Minimal | Doesn't satisfy "inspect/enumerate remote sessions" (F3/F9) | Insufficient alone. |

**Recommended model:** per-node registries remain authoritative; **PubSub is the routing fabric**;
the **cluster index** is a read-only merged view. Cross-node "supervision" is *orchestration*
(commands + events), not OTP links — a conductor never OTP-supervises a remote worker (F11), which is
precisely why §5.5's loss-notifier and reaper are required.

### 6.3 Worker placement

| Option | How | Pros | Cons | Verdict |
|---|---|---|---|---|
| **Local (today)** | `DynamicSupervisor.start_child` on the caller's node | Simple; fast | Can't target a host | Keep as the default branch (`node == Node.self()`). |
| **Remote via `:erpc` (proposed)** | `:erpc.call(peer, Orchestrator, :launch_subagent, …)` so the **peer** starts the child | Ownership, tools, `cd`, crash isolation all stay host-correct (F5/F7); the bus carries results back | Requires cluster connectivity + id uniqueness; no cross-host filesystem sharing | **Recommended.** |
| Horde.DynamicSupervisor | Supervisor spans nodes; child placed by Horde | Elastic, rebalances on node loss | Changes ownership; node-loss handling now in Horde; tool locality becomes implicit | **[OPEN]** later phase. |

### 6.4 Security posture

Erlang distribution is **extremely** privileged: any node holding the cookie can `send/2`, `:erpc`
arbitrary modules, and effectively run code on connected peers. Athanor adopts a **host-local by
default, trusted-network opt-in** posture:

- **Cookie is the perimeter.** The default `:athanor_local_secret_cookie` (F8) is a *published
  constant in the source tree* and must **never** be used once `cluster_nodes` is non-empty:
  `Athanor.Cluster` refuses to start in that combination (§5.1 step 2). Use `ATHANOR_CLUSTER_COOKIE`
  seeded from a secret manager, or the per-user `~/.erlang.cookie` (`chmod 600`).
- **Prefer a private network.** v1 assumes a trusted LAN/VPN/Tailscale/WireGuard. Do **not** expose
  EPMD (4369) or the distribution port range (`inet_dist_listen_min/max`) to untrusted networks;
  firewall them. Document that `Node.connect/1` = full RPC.
- **Name/type correctness.** Short names (`athanor@host-b`) are LAN-only; use `:longnames` +
  FQDN for anything routed. `Config.node_name_type/0` controls this (F8).
- **Least privilege on the remote side.** Remote spawns flow through the **same**
  `Orchestrator.launch_subagent/4` surface as local ones — no new privileged entry point is added.
  `Athanor.Cluster.Sessions` only calls `list_sessions/0`/`session_output/1` (read-only) on peers.
- **TLS distribution (`-proto_dist inet_tls`) is future work** (§10 risk 5): v1 documents the
  requirement but does not implement it. **[OPEN]** OQ5.
- **TUI attach inherits §7.7's model**: the client is a throwaway node with the same cookie; detach
  kills only the relay (F13).

## 9. Testing Strategy

### 9.1 Unit — `test/athanor/bus_test.exs` **[new]** (`async: false`)
- `Athanor.Bus.Local` behaves **byte-identically** to today: `subscribe/1` + `broadcast/2` delivers

- `publish_event/3` / `send_command/2` produce identical messages regardless of backend (assert on
  the payload, not the transport).

### 9.2 Unit — `test/athanor/cluster_test.exs` **[new]** (`async: false`)

### 9.3 Multi-node integration — `test/athanor/cluster_integration_test.exs` **[new]**
Use real peer VMs (F14). Sketch:

      node: node, id: "w-remote", llm_fn: done_llm())

  assert_receive {:conductor_saw, "[DONE] Sub-agent 'Remote' (w-remote) finished" <> _}, 5_000

Cases to cover:
1. **Remote spawn** returns a remote pid and the worker registers on the **peer's**
   `AgentRegistry` (assert via `:erpc.call(peer, Registry, :count, [Athanor.AgentRegistry])`).
2. **Cross-node `{:child_done}`** wakes a local conductor (§4.4) — the headline behaviour.
3. **Cluster enumeration**: `Athanor.Cluster.Sessions.list/0` includes both the local and the remote
   session, each tagged with `:node`/`:host`.
4. **Remote control**: `Orchestrator.send_session/2` (or `Bus.send_command/2`) from the local node
   drives the remote worker's next turn (assert it transitions `:streaming`).
5. **`nodedown`**: `Node.disconnect(node)` + `on_exit` stop → assert
   `{:cluster_event, {:member_down, node}}` and a synthesized **`status: "fail"`** `{:child_done}` for
   the remote child (§5.5).
6. **Bounded timeout**: with the peer stopped, `Cluster.Sessions.list/0` returns the local rows only
   and does **not** exceed `cluster_erpc_timeout_ms` (assert wall-clock bound).

> `ExUnit.start()`; it may need `ExUnit.configure(exclude: [cluster: true])` if peer tests are slow
> by default. **[OPEN]** OQ7.

## 10. Risks, Edge Cases & Open Questions

### Risks / edge cases
1. **Split-brain / `:pg` divergence.** On a net partition, `:pg` maintains both sides' memberships
   and reconciles on heal; broadcasts do not cross the split. Athanor's PubSub is fire-and-forget, so
   this degrades to "each side keeps working locally", which is acceptable — but a conductor whose
   remote child is on the other side of a split must be told (the §5.5 loss notifier), not left
   waiting. `:pg` reconciliation may briefly produce duplicate deliveries after heal; handlers are
   already idempotent-ish (`{:status, _}` etc.), but the TUI's `streaming_buffer` concatenation could
   duplicate a `{:text_delta}` in that window — flag it.
2. **Blocking on a dead host.** Any synchronous cross-node call (`:erpc.call`, `GenServer.call` on a
   remote pid) can block for the OS-level TCP timeout. **All** new cross-node calls must pass an
   explicit timeout and be wrapped in `Task.async_stream`/`try` so the TUI never freezes (§5.4).
3. **Id collisions (F4).** If the §3.3 id change is skipped, remote and local sessions can share an
   id, corrupting the deck's `sessions` map and losing `session_started` merges. The cluster index
   should **detect and surface** duplicate ids as an error rather than silently overwriting.
4. **Orphan reaper false positives.** `Athanor.Cluster.Reaper` must not cancel a worker whose parent
   is merely *temporarily* unreachable (partition). It must key on cluster-wide conductor presence
   **and** respect a grace period; otherwise a split-brain event could kill durable work. **[OPEN]**
   OQ4 for the default policy.
5. **Security / cookie leakage (F8).** The tree currently ships a constant cookie. Shipping clustering
   without enforcing a strong, non-default cookie would be a remote-code-execution footgun. The
   `validate_identity/0` guard is therefore **mandatory**, not advisory (§6.4). TLS distribution and
   an IP allowlist are future work; v1 relies on a trusted network.
6. **EPMD reachability.** `Node.connect/1` needs EPMD (port 4369) and the dist port reachable in both
   directions, including NAT/firewall. A peer behind NAT will silently never connect. The `/hosts`
   command must show `:connecting → :down` transitions with the last error so this is debuggable.
7. **Filesystem assumptions (F7).** The single most likely user error: assuming a `cd` shared with a
   local conductor also exists on the remote host, or that a remote worker edits the conductor's
   files. There is no sharing; document loudly (§5.3). Interacts with §7.1 (worktrees) — a per-host
   worktree is the principled solution.
8. **Test flakiness.** Multi-node `:peer` tests depend on EPMD, ports, and sufficient startup time;
   they must be tagged, timeout-generous, and must not leave orphan VMs (`on_exit` + `:peer.stop/1`).
   CI without distribution should skip them.
9. **Interaction with §7.2 (Goals).** A `GoalManager` that nudge-delivers over
   `Bus.send_command(worker_id, …)` will "just work" remotely once `Bus` is distributed; but the
   GoalManager subscribing to `"agent:<worker_id>:events"` becomes a **cluster-wide firehose**,
   amplifying the C2 concern from that plan. Note the interaction; don't implement §7.2 here.
10. **Interaction with §7.4 (Store/Resume).** Per-node session metadata (`node`, host) belongs in
    `meta.json`; on resume, a session whose node is no longer reachable must be marked `:lost`, not
    silently re-created locally.
11. **Interaction with §7.7 (Daemon).** The daemon's `attach_subscriber/2` and `fetch_full_sessions/1`
    are the natural integration seam; §7.8 extends rather than replaces them. The daemon node name
    (§7.7 uses `athanor@127.0.0.1`) should be unified with `Config.node_name/0`.
12. **Latency.** A remote worker's `{:text_delta}` stream traverses the network twice (dist + relay).
    Acceptable on a LAN; over WAN the TUI may stutter. Consider coalescing deltas per session in the
    relay if it becomes a problem. **[OPEN]**.

### Open questions (require Conductor/user decision before coding)
- **OQ1 — Backend.** Confirm `:pg` as the distributed PubSub fabric (§6.1), or adopt Phoenix.PubSub
  for a more battle-tested fan-out? Recommend `:pg` for v1.
- **OQ2 — Id scheme.** Adopt the host-scoped id `worker-<host>-<rand>` (§3.3), or carry `node` purely
  as metadata and key the TUI by `{node, id}`? Affects collision handling and the deck key.
- **OQ3 — Discovery.** Explicit `ATHANOR_CLUSTER_NODES` only (v1), or add gossip/EPMD auto-discovery
  later? Recommend explicit-only for v1.
- **OQ4 — Orphan policy.** When a session's parent is unreachable cluster-wide past the grace period,
  **cancel** it or **adopt** it under a local fallback conductor? No default is safe for all tasks.
- **OQ5 — Transport security.** Ship v1 on a trusted network with a strong cookie only, or implement
  `-proto_dist inet_tls` in this phase? Recommend trusted-network v1, TLS as a follow-up.
- **OQ6 — Config home.** Keep everything in `Athanor.Config` module attributes + env vars (matches
  F15), or introduce `config/*.exs`? Recommend the former.
- **OQ7 — Test gating.** Exclude `:cluster` tests from the default `mix test` run (`ExUnit.configure`)
  or run them by default on dev machines? Affects CI time.
- **OQ8 — Cross-node `Agent.get_state/1`.** `Orchestrator.session_output/1` today does
  `Agent.get_state(pid)`; for remote pids this is a blocking cross-node call. Wrap every remote state
  fetch in a bounded `:erpc`/call timeout, or add a dedicated `Cluster.Sessions.output/1` that
  `:erpc`s the whole `session_output/1` (cleaner)? Recommend the latter.
- **OQ9 — Daemon auto-start.** `Daemon.connect_or_start_daemon/1` currently auto-starts a *local*
  daemon (F10). In cluster mode, should an unreachable configured peer trigger a connect-retry loop
  or an error surfaced to the TUI? Recommend retry + `/hosts` error, never an auto-start of a
  different local node.

## 11. Suggested Incremental Milestones (each ends green)

**M1 — Config + identity, no distribution.**
Add the `Athanor.Config` cluster accessors (§8) and `Athanor.Cluster.Member`. Implement
`Athanor.Cluster.host/1`, `resolve/1`, `validate_identity/0` (rejecting the source-default cookie
when `cluster_enabled?()`). Add `test/athanor/cluster_test.exs`. No supervision or `Bus` changes →
existing tests untouched; `pubsub_backend/0` returns `Athanor.Bus.Local` and a regression test pins
that.

**M2 — Bus backend seam.**
Introduce `Athanor.Bus.Backend` + `Athanor.Bus.Local` (a verbatim extraction of today's code) and
route `Bus` through the backend, keeping every public signature and the local default. Add
`Athanor.Bus.Distributed` (`:pg`) and the conditional `:pg` child in `Athanor.Application`.
`test/athanor/bus_test.exs` proves local parity and distributed delivery. Full suite must stay green
byte-for-byte.

**M3 — Cluster membership + distributed bus.**
Implement `Athanor.Cluster` (start/validate/connect/monitor/join-barrier) and wire it into
`Athanor.Application` after the `Registry` children. Publish `"cluster:members"` events. Add a
`:peer`-based test that connects two nodes and asserts a broadcast on one arrives on the other.

**M4 — Cluster-wide sessions + remote placement.**
Add `Athanor.Cluster.Sessions` (bounded `:erpc` fan-out) and `Orchestrator.list_cluster_sessions/0`
+ `lookup/2`; make `launch_subagent` accept `node:` (remote `:erpc` branch); adopt the host-scoped id
scheme; re-point `Daemon.fetch_full_sessions/1` at the cluster enumerator (degenerating to today's
behaviour when `Node.list() == []`). TUI: host badges, `/hosts`, `@host`-qualified `/spawn`. Tests
cover remote spawn, cross-node `{:child_done}`, and cluster enumeration.

**M5 — Failure semantics + reaper.**
Implement `:nodedown` handling, the synthetic `status: "fail"` `{:child_done}` loss notifier, and
`Athanor.Cluster.Reaper` (grace-period orphan GC, policy per OQ4). Tests cover `nodedown`, bounded
timeouts, and orphan detection. TUI shows `:down` hosts distinctly.

**M6 — Security hardening, tooling, docs.**
Add `list_hosts` conductor tool and `mix athanor.cluster --status/--join/--leave`. Enforce
`validate_identity/0` at boot; document the trust model (§6.4) and the filesystem footgun (§5.3) in
`docs/design.md`/`docs/architecture.md` (a short §7.8 subsection marking the phase complete). Final
`mix format && mix compile --warnings-as-errors && mix test` plus `mix test --only cluster`.
