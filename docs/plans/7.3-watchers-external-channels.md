## 0. Hazard review (issues found while grounding the design in the code)

A first sketch of §7.3 ("watchers just send a prompt to a conductor") hides several defects that the
existing code would surface immediately. This table indexes them and fixes them inline below; treat
it as the review pass the §7.2 plan performs over its own draft.

| # | Hazard | Fix |
|---|---|---|
| H1 | A naive watcher calls `Bus.send_command(id, {:prompt, text})`. Over PubSub this is **not** the semantics people expect: `Athanor.Agent.handle_info({:bus_command, {:prompt, _}}, state)` starts a turn when `:idle`/`:error` but the generic busy clause falls through to `do_enqueue_prompt/2` — so behaviour diverges from `Agent.prompt/2` (which returns `{:error, :busy}` synchronously). | Watchers always use `{:enqueue_prompt, text}`, the exact verb `Athanor.Orchestrator.send_session/2` and the §7.2 GoalManager already use. It queues while the conductor is `:streaming`/`:executing_tools` and drains in `drain_prompt_queue/1` — no dropped doorbell, no interruption. |
| H2 | Heartbeat uses a fixed-period `:timer` and "reschedules" by re-arming; under load, missed ticks pile up and the conductor is nudged N times for one elapsed interval. | Monotonic-clock + **reschedule-after-each-tick** loop (identical to §7.2 `GoalManager`'s `:verify_tick`). While a tick's notification is still in flight (`in_flight != nil`) the next tick is **skipped**, not queued. |
| H3 | Dedup maps live in the watcher process; a watcher restart forgets them and re-notifies every event still visible in the source (a GitHub comment, a Telegram update). | Per-watcher dedup keyed on the **provider's** stable id (`comment.id`, `run.id`+`status`, `update_id`, Slack `event_id`), with a TTL. On cold start the watcher starts **from "now"** (skip backlog) unless `replay: true`. Persistence across restarts is §7.4 (**[OPEN]**). |
| H4 | Rate-limiting per watcher is not enough: three watchers pointed at `"conductor-main"` can still flood one inbox. | Two-level budget — per-watcher token bucket **and** a per-target shared limiter (`Athanor.Watcher.Limiter`, one named ETS table keyed by `{target_id}`). Overflow is **coalesced** into one digest nudge, never silently dropped (H12/H13 below). |
| H5 | `Event.raw` (Slack webhook URLs, Telegram URLs containing the bot token, GitHub payloads) is published to `"deck:events"` and rendered/logged. | All events are **sanitized before publish**: `Athanor.Secrets.redact/1` scrubs known token shapes; raw payloads are only attached when `debug?: true` and never at `info` log level. |
| H6 | The watcher `GenServer` performs `Req.get/1` inline → the entire watcher (and every heartbeat it owes the conductor) stalls for the HTTP round-trip. | Follow the **`Athanor.Agent.start_llm_turn/1` / `start_tool_execution/2` pattern**: `spawn_monitor(fn -> send(pid, {:http_result, ref, result}) end)` and handle the reply in `handle_info`. The watcher's mailbox is never blocked. |
| H7 | A chat-channel watcher subscribes to `"agent:<conductor_id>:events"` to mirror replies — which is the **full firehose**, including every `{:text_delta, chunk}`. | Explicit filter (drop `{:text_delta, _}`, `{:status, _}`, tool events), exactly as §7.2's C2/C12 table mandates for the GoalManager. See §4.5. |
| H8 | Chat outbound mirror + chat inbound can echo (a conductor reply that reads like a command is re-ingested). | Inbound and outbound use different provider endpoints (no true loop), but define the mirror set precisely (§5.4): only terminal/escalation events are forwarded by default; `forward_replies: false` is the default (**[OPEN]** OQ5). |
| H9 | Watchers are configured against a conductor id that does not exist or is unstable. `Orchestrator.generate_id/1` appends a random suffix (`"conductor-#{count}-a1b2"`), so a generated id can never be a config target. | Watcher `conductor_id` must be an **explicit, stable** id (`"conductor-main"`, the value `Athanor.Daemon.ensure_main_conductor_and_hydrate/2` already uses; or `"ops"`). `start_watcher/1` validates via `Orchestrator.lookup/1` and parks until it appears (§5.5). |
| H10 | Publishing watcher events as `{:agent_event, watcher_id, {:session_started, _}}` on `"deck:events"` makes `Athanor.TUI.handle_agent_event/3` call `ensure_session/3` and renders a **phantom session** (the same class of bug as §7.2's C13). | Watchers are registered in their **own** `Athanor.WatcherRegistry` (never `Athanor.AgentRegistry`) and published as `{:watcher_event, watcher_id, event}` on `"deck:events"`. `TUI.handle_agent_event/3`'s existing catch-all `_other -> tui` already ignores them; a dedicated rendering clause is optional (§2.4, §7). |
| H11 | Webhook signature checks compare strings with `==` (timing leak) or are skipped "in dev". | Constant-time compare (`:crypto.hash_equals/2`), performed **before** JSON parse; unsigned/invalid payloads are rejected and never ingested. Secrets are optional only for `:heartbeat`. |
| H12 | Overflow of the rate limiter silently discards events → an actionable CI failure never reaches the conductor. | Overflow is coalesced: the first event in a window is sent immediately; subsequent ones accumulate a counter and are flushed as one digest when the window closes (`"...(+3 more)"`). |
| H13 | A watcher with a bad token crashes → supervisor restarts it → it crashes again → infinite crash-loop burning the GitHub rate limit. | `restart: :transient` + internal exponential backoff for **recoverable** errors (5xx, timeout, DNS). After `max_consecutive_errors` the watcher exits `:normal` (so `:transient` does **not** restart it) and publishes `{:watcher_halted, id, reason}`. Fatal errors (401/403, malformed config) halt immediately. |
| H14 | GitHub polling without conditional requests exhausts the 5000 req/hr budget. | Send `If-None-Match` (ETag) / `since` cursors, handle `304`, and back off on `X-RateLimit-Remaining: 0` until `X-RateLimit-Reset`. |
| H15 | Telegram long-poll: advancing `offset` before processing loses updates; advancing late replays them. | Advance `offset = last_seen_update_id + 1` **only after** the batch has been converted to notifications, and persist it in the per-watcher `cursor` (in-memory; §7.4 for durability). |
| H16 | The §7.2 goal escalation path ("escalate to Conductor") and the §7.3 watcher Nudge path both write the conductor inbox; naively they can both fire for one goal. | Watchers **never** inspect goal state; they are a pure sink. §7.2 §10-risk-12 already declares the escalation contract to be `Bus.send_command/2` alone, so a chat watcher mirroring `"conductor:<cid>:children"` receives the escalation with **zero new plumbing** — no double-send, because each watcher is independently rate-limited against the shared per-target limiter (H4). |

## 1. Scope & Non-goals

### In scope
- New `@moduledoc`-documented modules: `Athanor.Watcher` (behaviour + public API),
  `Athanor.Watcher.Spec` (registration/config struct), `Athanor.Watcher.Event` (normalized event),
  `Athanor.Watcher.Server` (the generic `GenServer`), plus three adapter families:
  `Athanor.Watcher.Heartbeat`, `Athanor.Watcher.GitHub`,
  `Athanor.Watcher.Chat.{Telegram,Slack,Discord}`.
- Supporting infrastructure modules: `Athanor.Watcher.Limiter` (shared per-target rate limiting),
  `Athanor.Watcher.HTTP` (injectable HTTP seam), `Athanor.Secrets` (secret resolution + redaction),
  and an optional `Athanor.Watcher.Bootstrapper` (start configured watchers on boot).
- Two new supervision children: `Athanor.WatcherRegistry` (`Registry, :unique`) and
  `Athanor.WatcherSupervisor` (`DynamicSupervisor, :one_for_one`).
- One new `Athanor.Bus` helper `publish_watcher_event/3` (mirrors `publish_event/3`).
- The delivery contract into `"agent:<id>:inbox"` (reusing `Bus.send_command/2` verbatim).
- Config schema for registering watchers + `Athanor.Config` accessors + env-var overrides.
- Dedup, rate-limiting/coalescing, secrets handling, failure/restart semantics.
- Unit + integration tests with an injected HTTP seam and short timers.
- Optional conductor-facing management tools (`start_watcher`, `stop_watcher`, `list_watchers`).

### Non-goals (explicitly excluded)
- **Not** implementing §7.1 worktrees, §7.2 goals, §7.4 persistence, §7.5 memory, §7.6 MCP, or §7.8
  clustering. Watcher cursors/dedup state stay **in memory** (persistence is a §7.4 integration
  point, **[OPEN]** OQ9).
- **Not** adding an inbound HTTP listener by default. The design says GitHub "polls **or** receives
  webhooks"; this plan ships **polling** first and treats webhook reception as an optional,
  dep-gated phase (**[OPEN]** OQ1).
- **Not** adding a WebSocket client dependency. Telegram ships via HTTP long-poll; Slack Socket Mode
  and the Discord gateway are deferred until a websocket dep is accepted (**[OPEN]** OQ8).
- **Not** giving watchers LLM access, conversation state, or the ability to spawn sessions. A
  watcher translates one external trigger into one bounded nudge; nothing more.
- **Not** changing `Athanor.LLM`, the `Athanor.Agent` state machine, or any existing tool contract.
- **Not** multi-node: `Athanor.Bus` is a node-local `Registry` (`docs/architecture.md` §6), so
  watchers must run on the same node as their conductor (**[OPEN]** OQ11).

## 2. Architecture

### 2.1 New modules

| Module | Kind | Responsibility |
|---|---|---|
| `Athanor.Watcher` | behaviour + public API | `@callback` contract, `start_watcher/1`, `stop_watcher/1`, `list_watchers/0`, `ingest/3`, `boot_from_config/0` |

| `Athanor.Watcher.Heartbeat` | behaviour impl | Pure timer; emits a scheduled wakeup `Event` (`handle_tick/1`, no HTTP) |
| `Athanor.Watcher.GitHub` | behaviour impl | Polls the GitHub REST API for PR review comments + failed workflow runs; optional webhook ingest |

| `Athanor.Watcher.Chat.Slack` | behaviour impl | Polls `conversations.history`; outbound `chat.postMessage` (**[OPEN]** Socket Mode) |
| `Athanor.Watcher.Chat.Discord` | behaviour impl | REST poll/outbound; gateway deferred (**[OPEN]** OQ8) |
| `Athanor.Watcher.Limiter` | module + named ETS | Shared per-target token bucket + coalescing counters |
| `Athanor.Watcher.HTTP` | module | Thin `get/2` / `post/2` over `Req` with an injectable `:http_fun` seam (mirrors `:llm_fn`) |
| `Athanor.Secrets` | module | Env → app-config → `~/.athanor/secrets.json` resolution (mirrors `Config.read_opencode_auth_key/1`) + `redact/1` |
| `Athanor.Watcher.Bootstrapper` | `GenServer` (optional) | Starts all watchers declared in `Application.get_env(:athanor, :watchers, [])` on boot |

### 2.2 Changes to existing modules
- `Athanor.Application` — insert `Athanor.WatcherRegistry` (before its supervisor) and
  `Athanor.WatcherSupervisor`, plus an optional `Athanor.Watcher.Bootstrapper` child (see §2.3).
- `Athanor.Bus` — add `publish_watcher_event/3` (§4.2) and extend the `@moduledoc` topic list with
  the watcher topics. **No change** to `send_command/2`, `publish_event/3`, `subscribe/1`.
- `Athanor.Config` — add watcher defaults/accessors (§8), following the existing
  module-attribute + `Application.get_env(:athanor, key, default)` + env-var idiom.
- `Athanor.Agent` — **optional, prompt-only**: extend `@default_conductor_prompt` with one paragraph
  teaching the conductor that `[HEARTBEAT:…]`, `[WATCHER:…]` and `[CHAT:…]` messages are external
  doorbells, not user chat. **No handler changes**: the watcher message arrives at the already-tested
  `handle_info({:bus_command, {:enqueue_prompt, text}}, state)` clause.
- `Athanor.TUI` — **optional**: add one `handle_agent_event/3` clause for
  `{:watcher_event, watcher_id, event}` (append a `{:system, "🔔 …"}` entry). The existing catch-all
  `handle_agent_event(tui, _session_id, _other), do: tui` means the feature is safe without it.
- `Athanor.Tools` — **optional**: add `start_watcher` / `stop_watcher` / `list_watchers` to
  `conductor_schemas/0` + `execute/3` (and the catch-all `when tool_name in [...]` list).
- `Athanor.Daemon` — **optional**: thin `:erpc` wrappers for watcher management so the TUI/remote
  clients can call them (mirrors `Daemon.start_conductor/2`).

### 2.3 Supervision placement (extends design §2 and `docs/architecture.md` §1)

```text
Athanor.Supervisor (:one_for_one)                               # name: Athanor.Supervisor
├── Athanor.AgentRegistry       (Registry, :unique)             # existing: session id -> Agent pid
├── Athanor.PubSub              (Registry, :duplicate)          # existing: topic fan-out (backs Bus)
├── Athanor.AgentSupervisor     (DynamicSupervisor)             # existing: Conductor + Worker GenServers
│      ├── Conductor "conductor-main"  (role: :conductor, parent_id: nil)   # <-- watcher TARGET
│      └── Worker …
├── Athanor.WatcherRegistry     (Registry, :unique)   [NEW]     # watcher_id -> Watcher.Server pid
├── Athanor.WatcherSupervisor   (DynamicSupervisor)   [NEW]     # one Server per watcher
│      ├── Watcher.Server "hb-ops"      (Heartbeat handler)
│      ├── Watcher.Server "gh-ops"      (GitHub handler)
│      └── Watcher.Server "tg-main"     (Telegram handler)
└── Athanor.Watcher.Bootstrapper (GenServer)          [NEW]     # starts config-declared watchers (optional)
```

Ordering rationale (mirrors the existing tree, `docs/architecture.md` §1):
- `Athanor.WatcherRegistry` must start **before** `Athanor.WatcherSupervisor`, whose children register
  into it — exactly as `Athanor.AgentRegistry` precedes `Athanor.AgentSupervisor`.
- `Athanor.AgentSupervisor` is listed **before** the watcher children so that a conductor target
  (`"conductor-main"`) can already be looked up when a watcher boots. Watchers still tolerate a
  missing target at runtime (H9/§5.5).
- Watchers live under a **separate** `DynamicSupervisor`, not `Athanor.AgentSupervisor`, so a
  misbehaving watcher can never consume an agent child slot or trigger `AgentSupervisor` restarts.

Restart policy for `Athanor.Watcher.Server`: **`:transient`** (abnormal crash → restart; clean
`:normal` exit → no restart). Rationale: a watcher that **halts** (bad credentials, exhausted
retries, H13) must stay halted rather than crash-loop; a watcher that **crashes** (a bug) should be
restarted once. This differs deliberately from `Athanor.Agent`'s `:temporary` (workers are one-shot),
and from §7.2's `GoalManager` (`:temporary`, single owner of an in-flight goal).

```elixir
# spec used by Athanor.Watcher.start_watcher/1
spec = %{
  id: {Athanor.Watcher.Server, watcher_id},
  start: {Athanor.Watcher.Server, :start_link, [spec_struct]},
  restart: :transient,
  shutdown: 5_000
}
```

### 2.4 PubSub topics / handlers

| Topic | Publisher | Subscriber | Payload |
|---|---|---|---|
| `"agent:<conductor_id>:inbox"` | `Athanor.Watcher.Server` **(new publisher)** | `Athanor.Agent` (`role: :conductor`, existing handler) | `{:bus_command, {:enqueue_prompt, text}}` — the **only** delivery channel; see §4.4 |
| `"agent:<conductor_id>:events"` | `Athanor.Agent` (existing) | `Athanor.Watcher.Server` **(chat watchers only, new subscriber)** | `{:agent_event, conductor_id, event}` — firehose; filtered per §4.5 |
| `"conductor:<conductor_id>:children"` | child `Athanor.Agent`s (existing) | `Athanor.Watcher.Server` **(chat watchers only, new subscriber)** | `{:agent_event, child_id, {:child_done, report}}` — mirrored to chat, and the §7.2 escalation sink |
| `"deck:events"` | `Athanor.Watcher.Server` **(new publisher)** | `Athanor.TUI`, loggers, telemetry | `{:watcher_event, watcher_id, event}` — **distinct shape** so the TUI never creates a phantom session (H10) |
| `"watcher:<watcher_id>:events"` **[NEW]** | `Athanor.Watcher.Server` | tests, monitors, future dashboards | `{:watcher_event, watcher_id, event}` |
| `"conductor:<conductor_id>:watchers"` **[NEW]** | `Athanor.Watcher.Server` | conductor-adjacent monitors, tests | `{:watcher_event, watcher_id, event}` |

> **Note (H10):** watcher events use `{:watcher_event, id, event}`, **not** `{:agent_event, id, event}`.
> The TUI's session tree is built by `ensure_session/3`, triggered by `{:session_started, meta}`
> `{:agent_event}` messages; using the agent shape would mint a phantom deck row for every watcher.
> The existing `handle_agent_event(tui, _session_id, _other), do: tui` catch-all makes the new shape
> inert until a rendering clause is added.

Key reuse insight: a watcher wakes a conductor through the **identical** path the TUI `/spawn` and
`Orchestrator.send_session/2` already use — `Bus.send_command(conductor_id, {:enqueue_prompt, text})`
→ the conductor's unmodified `handle_info({:bus_command, {:enqueue_prompt, text}}, state)`. No new
conductor handler, no new message grammar for the agent loop.

## 3. Data Structures

### 3.1 `Athanor.Watcher` (behaviour)

```elixir
defmodule Athanor.Watcher do
  @moduledoc """
  Behaviour and public API for external event watchers (design §7.3).

  A watcher is a **doorbell, not a messenger**: a supervised `GenServer`
  (`Athanor.Watcher.Server`) that observes exactly one external source and, on a trigger,
  pushes a single bounded nudge into a Conductor's PubSub inbox
  (`"agent:<conductor_id>:inbox"`). It holds no conversation state, never calls the LLM,
  and never spawns sessions — it rings, and gets out of the way.
  """

  alias Athanor.Watcher.{Event, Spec}

  @type severity :: :info | :warning | :critical

  @doc "Supervisor child spec for the handler (allows per-handler state)."
  @callback child_spec(term()) :: Supervisor.child_spec()

  @doc "Called inside Athanor.Watcher.Server.init/1 with the validated spec."
  @callback init(Spec.t()) :: {:ok, handler_state :: term()} | {:stop, reason :: term()}

  @doc "Poll tick. Return any events the external source has produced since last tick."
  @callback handle_tick(handler_state :: term()) ::
              {:notify, [Event.t()], term()} | {:noreply, term()}

  @doc """
  Inbound push (webhook payload or chat update batch) delivered by `ingest/3`.
  `headers` is a lower-cased map; the handler MUST verify signatures here (H11).
  """
  @callback handle_ingest(payload :: term(), headers :: map(), handler_state :: term()) ::
              {:notify, [Event.t()], term()} | {:noreply, term()} | {:error, term()}

  @optional_callbacks handle_tick: 1, handle_ingest: 3
end
```

### 3.2 `Athanor.Watcher.Spec` (registration / config schema)

```elixir
defmodule Athanor.Watcher.Spec do
  @moduledoc "Validated registration of one watcher (design §7.3; config schema §8)."

  @enforce_keys [:id, :type, :conductor_id]
  defstruct [
    :id,               # stable String.t() — Registry key + config identity
    :type,             # :heartbeat | :github | :chat
    :conductor_id,     # target Conductor id on "agent:<id>:inbox" (MUST be explicit/stable, H9)
    :handler,          # handler module implementing Athanor.Watcher
    :prompt,           # heartbeat: nudge text template (nil => default)
    # scheduling
    every_ms: 60_000,          # tick period (heartbeat + poll watchers)
    tick_timeout_ms: 30_000,   # per-tick HTTP budget
    initial_delay_ms: 0,       # jittered start offset (H14)
    # dedup / rate-limit (shared by all families)
    dedup_ttl_ms: 3_600_000,
    max_per_window: 5,
    window_ms: 60_000,
    min_interval_ms: 15_000,
    coalesce?: true,
    # delivery policy
    mirror?: false,            # chat: mirror conductor terminal events back to the channel
    forward_replies?: false,   # chat: mirror every turn_complete (default OFF, OQ5)
    # failure semantics
    max_consecutive_errors: 5,
    # family-specific options (tokens by ENV NAME only — never a secret value, §7)
    opts: %{}
  ]

  @type t :: %__MODULE__{}

  @doc "Builds and validates a Spec; raises on missing required keys (mirrors Goal.new/1 strictness)."
  @spec new(keyword() | map()) :: t()
  def new(attrs)

  @doc "Parses the `:watchers` application-env list into specs (invalid entries are logged + skipped)."
  @spec from_config([map() | keyword()]) :: [t()]
  def from_config(raw)
end
```

> **Decision (H9):** `conductor_id` is `@enforce_keys`. There is no "default conductor" — silently
> defaulting to `"conductor-main"` would let a typo'd config nudge the wrong orchestrator. The
> `Athanor.Daemon`-managed main conductor id (`"conductor-main"`, see
> `ensure_main_conductor_and_hydrate/2`) is the conventional target.

### 3.3 `Athanor.Watcher.Event` (normalized event)

```elixir
defmodule Athanor.Watcher.Event do
  @moduledoc "A single normalized external trigger, ready to be rendered into an inbox nudge."

  @enforce_keys [:watcher_id, :severity, :title]
  defstruct [
    :watcher_id, :type, :severity, :title, :body, :url,
    :dedup_key,          # provider-stable identity (string), H3
    :origin,             # :poll | :webhook | :chat | :timer
    :sender,             # chat only: "@user" / "slack:U123"
    :occurred_at,        # DateTime.t() | nil
    :target_id,          # conductor id (copied from Spec for the limiter, H4)
    raw: nil             # only populated when the watcher's spec sets debug?: true (H5)
  ]

  @type severity :: :info | :warning | :critical

  @doc """
  Renders the inbox text. The tag prefix is machine-parseable so the conductor (and tests)
  can tell a doorbell from a user message.
  """
  @spec prompt(t()) :: String.t()
end
```

Rendered examples:
```text
[HEARTBEAT:hb-ops] Periodic health check (every 15m). Triage: call list_sessions,
check for stalled or errored workers, run mix test, and reply with a one-line status.
```
```text
[WATCHER:gh-ops:critical] CI failed on PR #412 (acme/widgets) — workflow "test" status=completed conclusion=failure.
https://github.com/acme/widgets/actions/runs/9123
Spawn a fix worker or acknowledge with a short plan.
```
```text
[CHAT:telegram:@martin] The nightly job is stuck again — can you look?
```

### 3.4 `Athanor.Watcher.Server` state

```elixir
defstruct [
  :spec,                # %Athanor.Watcher.Spec{}
  :handler_state,       # handler-owned term
  :timer_ref,           # reference() | nil (Process.send_after)
  :in_flight,           # {pid(), reference()} | nil  (spawn_monitor'd HTTP/tick task, H6)
  :cursor,              # handler-owned poll cursor (ETag, since_id, update_offset), H3/H15
  :dedup,               # %{dedup_key => monotonic_ms} bounded by dedup_ttl_ms
  :consecutive_errors,  # non_neg_integer
  :last_sent_at,        # monotonic ms | nil (min_interval_ms floor)
  :history              # [{monotonic_ms, event}] bounded audit trail (debug)
]
```

> **Deliberate omissions.** No `:messages` (watchers are not agents), no `:subscriber` pid (all output
> is PubSub), no queue of pending notifications (delivery is synchronous `Registry.dispatch` + `send`,
> so there is nothing to await). The limiter state lives **outside** the process in ETS so multiple
> watchers targeting one conductor share one budget (H4).

Non-blocking rule (AGENTS.md: "Never block the TUI process on HTTP requests or tool execution"; same
applies to any supervised process): every network call runs inside `spawn_monitor/1` that `send/2`s
`{:tick_result, ref, result}` / `{:ingest_result, ref, result}` back — the precise pattern in
`Athanor.Agent.start_llm_turn/1` and `start_tool_execution/2`.

## 4. Message & PubSub Protocol

### 4.1 Inbound commands to a `Watcher.Server` (`GenServer.call/cast`, not PubSub)
```elixir
{:get_status}                        # %{id, type, conductor_id, last_event_at, sent_in_window, halted?}
{:force_tick}                        # deterministic tick for tests / manual poke
{:ingest, payload, headers}          # webhook / chat delivery path (delegates to handler)
{:halt, reason}                      # operator kill switch; stops the watcher cleanly
```

### 4.2 `Athanor.Bus` addition
```elixir
@doc """
Publishes a watcher lifecycle/notification event to `"deck:events"`, `"watcher:<id>:events"`
and (when the watcher targets a conductor) `"conductor:<cid>:watchers"`.
Uses the `{:watcher_event, watcher_id, event}` shape so the TUI never mints a phantom session (H10).
"""
@spec publish_watcher_event(String.t(), String.t() | nil, term()) :: :ok
def publish_watcher_event(watcher_id, conductor_id, event) do
  msg = {:watcher_event, watcher_id, event}
  broadcast("deck:events", msg)
  broadcast("watcher:#{watcher_id}:events", msg)
  if is_binary(conductor_id), do: broadcast("conductor:#{conductor_id}:watchers", msg)
  :ok
end
```

Nudges reuse the existing `Athanor.Bus.send_command/2` **verbatim** — no new function — guaranteeing
delivery on `"agent:<id>:inbox"` and reuse of the Agent's existing `{:bus_command, {:enqueue_prompt, text}}`
handler (H1).

### 4.3 Event catalogue

| Event | Channel | Payload |
|---|---|---|
| `{:watcher_started, spec_meta}` | `watcher:<id>:events`, `deck:events`, `conductor:<cid>:watchers` | `%{id, type, conductor_id, every_ms}` (never tokens, H5) |
| `{:watcher_tick, id}` | `watcher:<id>:events` (debug only) | tick audit |
| `{:watcher_notified, event}` | `watcher:<id>:events`, `deck:events`, `conductor:<cid>:watchers` | `%Athanor.Watcher.Event{}` **after** redaction |
| `{:watcher_coalesced, count, digest}` | same as above | rate-limited overflow digest (H12) |
| `{:watcher_error, id, reason}` | `watcher:<id>:events`, `deck:events` | recoverable error, redacted |
| `{:watcher_halted, id, reason}` | `watcher:<id>:events`, `deck:events` | terminal halt (bad auth / retry budget, H13) |
| `{:watcher_delivery_failed, id, reason}` | `watcher:<id>:events`, `deck:events` | target conductor missing (§5.5) |

### 4.4 Delivery contract into `"agent:<conductor_id>:inbox"`

The **entire** write path is:

```elixir
Athanor.Bus.send_command(event.target_id, {:enqueue_prompt, Athanor.Watcher.Event.prompt(event)})
```

Consequences verified against `lib/athanor/agent.ex`:
- Idle/errored conductor → `do_enqueue_prompt/2` → `begin_user_turn/2` → status `:streaming`.
- Busy conductor (`:streaming`/`:executing_tools`) → appended to `prompt_queue` and drained by
  `drain_prompt_queue/1` when the current turn ends. **No doorbell is lost** (H1).
- `Bus.send_command/2` is fire-and-forget `Registry.dispatch/3` + `send/2` (documented in
  `docs/architecture.md` §6): it silently drops if the conductor is not subscribed. The watcher
  therefore checks `Orchestrator.lookup(conductor_id)` **before** sending (§5.5) and counts a send as
  successful only when the lookup succeeds.

### 4.5 Handler-side event filtering (H7)

A chat watcher subscribed to `"agent:<conductor_id>:events"` receives the full firehose. It applies
these rules and ignores everything else (cheap `case`, no allocation on the hot path):

| Incoming event | Action |
|---|---|
| `{:text_delta, _}` | **Drop.** Hottest path in the system; mirroring it would rate-limit the channel to death. |
| `{:status, _}`, `{:tool_start, _}`, `{:tool_end, _}`, `{:user_message, _}` | **Drop** (debug-only history). |
| `{:turn_complete, content}` | Mirror **only if** `spec.forward_replies?` (default false, OQ5). |
| `{:error, reason}` | Mirror as `:critical`. |
| `{:child_done, report}` | Mirror as `:info` (`"[DONE] Sub-agent …"`). |
| `{:session_started, _}` | **Drop.** |
| `:cancelled` | Mirror as `:warning`. |

### 4.6 Reliability rules (H2/H3/H4/H12/H13)

1. **Dedup.** Before delivering, compute `dedup_key`; if present in `state.dedup` (and younger than
   `dedup_ttl_ms`), drop. Evict expired keys on every tick. Keys are provider-stable (H3/H15).
2. **Per-watcher budget.** Token bucket in `state`: `max_per_window` sends per `window_ms`; the first
   is immediate, the rest accumulate.
3. **Per-target budget.** `Athanor.Watcher.Limiter` (named ETS, keyed by `target_id`) enforces a
   ceiling across **all** watchers pointed at one conductor (H4).
4. **Floor.** `min_interval_ms` between any two nudges to the same target, even across watchers.
5. **Coalesce, never drop.** Events blocked by (2)–(4) increment a counter; when the window closes the
   watcher emits one `{:watcher_coalesced, n, digest}` nudge instead of `n` individual ones (H12).
6. **Backoff.** Recoverable errors → exponential backoff (`every_ms`, `2×`, capped at `window_ms×10`),
   `consecutive_errors + 1`; success resets it to 0.
7. **Halt.** `consecutive_errors >= max_consecutive_errors` **or** a fatal error (401/403, malformed
   config) → publish `{:watcher_halted, id, reason}` and `{:stop, :normal, state}` so `:transient`
   does not restart it (H13).

## 5. Behavioral Flow

### 5.1 Start
1. Caller invokes `Athanor.Watcher.start_watcher/1` (from `Athanor.Watcher.Bootstrapper`, a test, a
   conductor tool, or `mix` console).
2. `Spec.new/1` validates required fields and resolves the handler module from `:type`.
3. `DynamicSupervisor.start_child(Athanor.WatcherSupervisor, spec)` with a `:transient` `child_spec`.
4. `Watcher.Server.init/1`:
   - register in `Athanor.WatcherRegistry` under `{:watcher, id}` (**`Registry.register/3`, once** —
     `Bus.subscribe/1` is not idempotent on a `:duplicate` registry, §7.2 C4; the same caution applies
     to the watcher's own subscriptions),
   - `handler.init(spec)`,
   - validate the target: `Orchestrator.lookup(conductor_id)`; if `:error`, park (§5.5) rather than
     crash (H9),
   - subscribe to `"agent:<conductor_id>:events"` and `"conductor:<conductor_id>:children"` **only**
     when `spec.mirror?` (chat watchers),
   - schedule the first tick (`every_ms` + jittered `initial_delay_ms`), publish `{:watcher_started, …}`.

### 5.2 Tick (poll + heartbeat)
1. `handle_info(:tick, state)`:
   - if `in_flight != nil` → skip this tick (H2), reschedule, return;
   - else `spawn_monitor(fn -> send(pid, {:tick_result, ref, dispatch(spec, handler_state)}) end)`
     (H6) and reschedule the next tick.
2. `dispatch/2` calls the handler's `handle_tick/1` (heartbeat emits its `Event`; GitHub performs the
   conditional REST GET; chat long-polls `getUpdates` with a server-side timeout).
3. On `{:tick_result, ref, {:notify, events, hs}}` → update `handler_state`/`cursor` → pipeline each
   event through §4.6 → deliver (§5.4) → clear `in_flight`.
4. On `{:DOWN, ref, :process, _, reason}` before a result → synthesize a recoverable error, apply
   backoff, clear `in_flight` (the watcher is never wedged on a dead task).

### 5.3 Ingest (webhook / chat push)
1. `Watcher.ingest(id, payload, headers)` resolves the pid via `Athanor.WatcherRegistry` and
   `GenServer.call(pid, {:ingest, payload, headers})` (non-blocking on the caller's side is the
   caller's problem; the listener uses a task).
2. `Watcher.Server` delegates to `handler.handle_ingest/3`, which **verifies the signature first**
   (H11) and returns `{:notify, events, hs}` or `{:error, reason}`.
3. Same dedup/rate-limit/deliver pipeline as §5.2.

### 5.4 Deliver
```text
for each Event:
  sanitize (Athanor.Secrets.redact/1)            # H5
  dedup_key seen?            -> drop
  per-window budget spent?   -> accumulate, emit digest on window close   # H12
  per-target budget spent?   -> accumulate, emit digest on window close   # H4
  min_interval_ms floor hit? -> defer to next tick
  Orchestrator.lookup(target) == :error -> park + {:watcher_delivery_failed, _, _}  # H1/H9
  Bus.send_command(target, {:enqueue_prompt, Event.prompt(event)})
  publish_watcher_event(id, target, {:watcher_notified, event})
  mirror to chat provider when spec.mirror? and the event came from the conductor
```

### 5.5 Target conductor absent (H9)
- On start and on every delivery, `Orchestrator.lookup(conductor_id)`:
  - `:error` → do **not** send (fire-and-forget would drop it silently). Buffer at most the last
    `max_per_window` events in `state.history`, publish `{:watcher_delivery_failed, id, :not_found}`,
    and keep ticking (the conductor id is stable, so it usually reappears).
  - Deeper policy (`:park` vs `:stop`, buffer depth) is **[OPEN]** OQ6.

### 5.6 Chat round-trip (1-to-1 pairing, design §7.3)
```text
[Phone] --"look at CI"--> Telegram API --getUpdates--> Watcher.Server "tg-main"
     |                                                      |
     |                             Bus.send_command("conductor-main", {:enqueue_prompt, "[CHAT:telegram:@you] look at CI"})
     |                                                      v
     |                                             Conductor "conductor-main" runs a turn
     |                                                      |
     |                    Watcher.Server subscribed to "agent:conductor-main:events"
     |                                 and "conductor:conductor-main:children"
     |                                                      v
[Phone] <--sendMessage(reply / [DONE] / escalation)-- Telegram API <-- Watcher.Server
```
The pairing is a single `conductor_id` field on the `Spec`, so one conductor can have one chat channel
(or several, each rate-limited against the same target budget).

## 6. The Three Watcher Families

### 6.1 Heartbeat / Cron (`Athanor.Watcher.Heartbeat`)
- **Trigger:** pure timer; `handle_tick/1` always returns exactly one `Event` with
  `dedup_key: "#{watcher_id}:#{bucket}"` where `bucket = div(monotonic_now_ms, every_ms)` — so a
  double-fired or restarted tick within the same bucket cannot double-nudge (H2/H3).
- **Default prompt:** the `[HEARTBEAT:…]` template in §3.3; `spec.prompt` overrides it.
- **Cron expression:** the design says "Heartbeat / Cron". A cron parser is **not** proposed now —
  `every_ms` covers "every 15 minutes" via config arithmetic (`15 * 60_000`) and avoids a new dep.
  Cron syntax is **[OPEN]** (OQ2-adjacent) and can be layered on later by having the handler compute
  the next delay.
- **Tradeoffs:** trivially reliable, no secrets, no rate-limit pressure. Risk: a heartbeat that
  always nudges "check status" trains the conductor to ignore it — mitigated by a *specific* prompt
  template configured per watcher (e.g. "triage the `inbox` label", "diff against yesterday's
  report") rather than a generic ping.

### 6.2 GitHub / CI (`Athanor.Watcher.GitHub`)
- **Mode:** polling the GitHub REST API by default. One conditional request per tick against
  `GET /repos/:owner/:repo/issues/comments?since=<cursor>` and
  `GET /repos/:owner/:repo/actions/runs?status=failure&per_page=…`, using `If-None-Match`/ETag and a
  `since` cursor; a `304` costs no quota (H14). Respond to `X-RateLimit-Remaining: 0` by sleeping to
  `X-RateLimit-Reset`.
- **Auth:** `token_env` (default `"ATHANOR_GITHUB_TOKEN"`) resolved via `Athanor.Secrets` (§7). The
  token is never placed in an `Event` or a log line (H5).
- **Events produced:**
  - PR review comment → `dedup_key: "comment:#{comment.id}"`, `severity: :warning`,
    body = comment body + PR url.
  - CI failure → `dedup_key: "run:#{run.id}:#{run.conclusion}"`, `severity: :critical`,
    body = workflow name + conclusion + url.
- **Webhook mode (optional, [OPEN] OQ1):** a new `Athanor.Watcher.Webhook` listener (a `Plug`/`Bandit`
  endpoint) that calls `Athanor.Watcher.ingest(id, raw_body, headers)`; the handler verifies
  `X-Hub-Signature-256` with `:crypto.hash_equals/2` against the secret from `Secrets` (H11).
- **Alternative considered:** shelling out to the `gh` CLI through the existing
  `Athanor.Tools.run_command/2` (proposed in the §7.2 plan, C9). Rejected as the primary path: it
  couples a background watcher to a `cd` + an installed binary and has no ETag/cursor story. `gh` can
  remain a documented fallback for users who already auth that way.
- **Tradeoffs:** the polling mode has no inbound exposure (good for a laptop/NAT) but is
  latency-bounded by `every_ms` (15–60 s realistic) and consumes quota; webhooks are instant and
  quota-free but require an inbound endpoint + signature secret.

### 6.3 Remote Chat Channels (`Athanor.Watcher.Chat.*`, design §7.3)
- **Pairing:** `spec.conductor_id` is the paired conductor; `spec.mirror?: true` is implied for chat.
- **Telegram** (ships first — pure HTTP, no websocket dep):
  - Inbound: `GET https://api.telegram.org/bot<token>/getUpdates?offset=<cursor>&timeout=<tick_timeout_s>`
    long-poll; advance `offset = max(update_id) + 1` **only after** the batch is converted (H15).
  - Outbound: `POST /bot<token>/sendMessage` with `chat_id` from `spec.opts`.
  - Secrets: `token_env` default `"ATHANOR_TELEGRAM_BOT_TOKEN"`.
- **Slack:** inbound via `conversations.history` polling; outbound `chat.postMessage`. Socket Mode
  (websocket) is deferred (**[OPEN]** OQ8) — it needs a websocket client, which the project has today
  (only `req`/`finch`/`mint`).
- **Discord:** inbound via REST polling of channel messages; outbound `POST /channels/:id/messages`.
  The gateway websocket (and ed25519 interaction verification, which needs `:crypto` ed25519 or a dep)
  is deferred (**[OPEN]** OQ8).
- **What flows back to the phone:** `{:child_done, report}`, `{:error, reason}`, `{:watcher_halted, …}`
  for this conductor, and the §7.2 `{:goal_escalated, …}` (already delivered to
  `"agent:<cid>:inbox"` / `"conductor:<cid>:children"`, so a mirroring watcher sees it with no new
  plumbing — H16). Full assistant replies are opt-in via `forward_replies?` (**[OPEN]** OQ5).
- **Tradeoffs:** instant, mobile, zero-polling-in-a-browser; but adds a durable external dependency, a
  long-lived secret, and provider-specific message length limits (Telegram 4096 chars) that require
  truncation in `Event.prompt/1` rendering.

## 7. Secrets Handling

`Athanor.Secrets` mirrors the established `Athanor.Config.read_opencode_auth_key/1` idiom (env →
app config → on-disk JSON), keeps secrets out of every event/log, and is injectable for tests.

```elixir
defmodule Athanor.Secrets do
  @moduledoc "Secret resolution (env → app config → ~/.athanor/secrets.json) and redaction (design §7.3)."

  @default_path "~/.athanor/secrets.json"

  @doc "Resolves a secret by NAME. Never logs the value."
  @spec get(String.t()) :: {:ok, String.t()} | {:error, :not_found}
  def get(name)   # System.get_env(name) -> Application.get_env(:athanor, :secrets)[name] -> file

  @doc "Reads a JSON secrets file (mode 0600 enforced); mirrors Config.read_opencode_auth_key/1."
  @spec read_file(String.t()) :: {:ok, map()} | {:error, term()}
  def read_file(path \\ @default_path)

  @doc "Replaces known token shapes (bot tokens, bearer headers, webhook URLs) with \"[REDACTED]\"."
  @spec redact(term()) :: term()
  def redact(term)
end
```

Rules:
1. **Config stores env-var *names*, never values.** `Spec.opts` carries `token_env: "ATHANOR_GITHUB_TOKEN"`;
   the value is resolved at `handler.init/1` and held only in the handler's private state.
2. **On-disk file, if used, must be `0600`.** `read_file/1` returns
   `{:error, :insecure_permissions}` otherwise (mirrors the "fail loudly" posture of the §7.2 C3 fix
   for missing verifiers).
3. **Redaction before publish.** `Event.raw` is `nil` unless `debug?: true`; every field that reaches
   `deck:events`, logs, or `inspect/1` passes through `Secrets.redact/1` first (H5). Token-shaped
   substrings (`123456:AA…`, `https://hooks.slack.com/services/…`, `xoxb-…`) are pattern-scrubbed.
4. **Signature verification is mandatory when a signing secret is configured.** A webhook endpoint
   configured without a secret refuses to start (§6.2, H11) rather than silently accepting unsigned
   payloads.
5. **Test seam.** `Athanor.Secrets` resolves through `Application.get_env(:athanor, :secrets, %{})`,
   so tests set secrets with `Application.put_env/3` (the same shape `Config.api_key/0` already honours
   via `Application.get_env(:athanor, :api_key)`), with no network and no real file.

(`:github_api_base_url` with a default of `"https://api.github.com"` so tests can point at a stub).

## 9. Testing Strategy

### 9.1 The HTTP seam (how to stub external HTTP without Plug)
`Req.Test` **cannot** be used today without adding a dependency: its `plug: {Req.Test, name}` path
goes through `Req.Plug`, and `deps/req/lib/req/test.ex` guards every Plug-dependent function behind
`if Code.ensure_loaded?(Plug.Conn)` / `if Code.ensure_loaded?(Plug)`; `plug` is an *optional* dep of
`req` (`deps/req/mix.exs` line 106) and is **not present** in `deps/` or `mix.lock`. Two options:

1. **Injectable `:http_fun` seam (recommended, primary).** `Athanor.Watcher.HTTP.get/2` and `post/2`
   take an `:http_fun` option defaulting to a `Req` call; `Spec.new/1` accepts `http_fun:` and tests
   pass `fn url, opts -> {:ok, %{status: 200, body: canned_json, headers: %{}}} end`. This mirrors how
   `Athanor.Agent.init/1` injects `:llm_fn` and how `test/athanor/agent_test.exs` drives the loop with
   pure functions. It needs **zero** new deps and is fully deterministic.
2. **`{:plug, "~> 1.0", only: :test}` + `Req.Test` (optional).** Then `Req.get(url, plug: {Req.Test, __MODULE__})`
   with `Req.Test.stub/2` gives realistic request/response handling. Adds a test-only dep and forces
   every `Req` call to thread the `:plug` option.

Whichever is chosen, the watcher handlers must receive the seam via the spec, not call `Req` directly.

### 9.2 Unit — `test/athanor/watcher_spec_test.exs` (new, `async: true`)

### 9.3 Unit — `test/athanor/watcher_server_test.exs` (new, `async: false`)
- **Timers faked two ways** (no real 15-minute waits): `every_ms: 20` in the spec, and deterministic
  `GenServer.cast(pid, :force_tick)`; assert inbox delivery by `Bus.subscribe("agent:<target>:inbox")`
  then `assert_receive {:bus_command, {:enqueue_prompt, text}}` — the exact idiom used in
  `test/athanor/agent_test.exs` / `orchestrator_test.exs`.
- **Queued, not dropped, while the conductor is busy** (H1): assert the message lands, then assert a
  second message during a long turn is drained (`Agent` state `messages` grows twice).
- **Dedup** (H3): two events with the same `dedup_key` → exactly one inbox message.
- **Rate-limit + coalesce** (H4/H12): N events in one window → one immediate nudge + one `(+N-1 more)`
  digest, never N nudges.
- **Per-target limiter shared across watchers** (H4): two watchers targeting one conductor; the second
  watcher's excess is coalesced.
- **Tick skip while in flight** (H2): a slow `http_fun` does not queue a second tick.
- **Backoff + halt** (H13): `max_consecutive_errors: 2` with an always-failing `http_fun` → two
  `{:watcher_error, …}` then `{:watcher_halted, …}` and the process exits `:normal`; assert it is
  **not** restarted (monitor stays down).
- **Missing target** (§5.5): no conductor registered → `{:watcher_delivery_failed, _, :not_found}` and
  no crash.

## 10. Risks, Edge Cases & Open Questions

### Risks / edge cases
1. **Fire-and-forget delivery.** `Bus.broadcast/2` is `Registry.dispatch/3` + `send/2`
   (`docs/architecture.md` §6) and silently drops for a dead/absent subscriber. Mitigations: lookup
   before send (H1/§5.5), count delivery only on a successful lookup, cap with the rate limiter, and
   never treat a nudge as acknowledged.
2. **Nudge storms.** Three watchers × a chatty source can flood a conductor. Mitigated by the
   per-target limiter (H4) and coalescing (H12); the hard `max_per_window` cap is the backstop.
3. **Conductor restarts.** If a conductor crashes, its "inbox" topic has no subscriber; the watcher
   parks and buffers a bounded tail (§5.5) rather than spamming into the void.
4. **Secrets in URLs.** Slack incoming-webhook URLs *are* secrets. Redaction must cover URL-embedded
   secrets, not just headers (H5) — covered by a dedicated `redact/1` test.
5. **HTTP flakiness.** Timeouts/`5xx`/DNS → recoverable backoff; `429` → honour `Retry-After`; `401/403`
   → halt (H13). Never crash-loop.
6. **Clock/timezone.** Use `System.monotonic_time(:millisecond)` for intervals, dedup TTL, and buckets;
   use `DateTime.utc_now/0` only for human-facing `occurred_at` fields. Monotonic time is immune to
   NTP/DST jumps (the same rule §7.2 risk 5 adopts).
7. **Webhook replays.** Providers retry deliveries; dedup on the provider event id (H3/H11) makes
   retries idempotent.
8. **Message length.** Telegram caps messages at 4096 chars; `Event.prompt/1` truncates (`body` +
   `url`), and the full payload stays in memory only.
9. **Watcher ↔ §7.2 interaction.** A goal escalation already lands on `"conductor:<cid>:children"`
   and `"agent:<cid>:inbox"`; a chat watcher mirrors it for free, and the shared limiter prevents the
   goal manager and a watcher from double-nudging (H16). Watchers must **not** read goal state.
10. **Watcher ↔ §7.4 interaction.** Cursors/dedup are in-memory; after a VM restart a watcher replays
    from "now" by default (H3). Persisting cursors is a §7.4 integration point (**[OPEN]** OQ9).
11. **Watcher ↔ §7.8 interaction.** `Athanor.Bus` is node-local, so watchers must run on the same node
    as their conductor. Multi-node watchers are out of scope (**[OPEN]** OQ11).
12. **TUI pollution.** Distinct `{:watcher_event, …}` shape prevents phantom sessions (H10); the
    optional rendering clause must be added **before** the `handle_agent_event/3` catch-all.
13. **Credential blast radius.** A chat bot token in `~/.athanor/secrets.json` grants full channel
    control. Document `0600`, prefer env vars for CI, and never echo tokens in `/status` output.
14. **Duplicate watcher ids.** `Athanor.WatcherRegistry` is `:unique`; a second `start_watcher/1` with
    the same id returns `{:error, {:already_registered, pid}}` — surface it clearly rather than
    silently replacing the watcher.

### Open questions (require Conductor/user decision before coding)
- **OQ1 — Webhooks vs polling for GitHub.** Ship polling only, or also add an inbound HTTP listener
  (`Bandit`/`Plug`) for webhooks? Polling needs no new dep; webhooks need one listener dep + a signing
  secret and a reachable endpoint (NAT on a laptop).
- **OQ2 — Config location.** Introduce `config/config.exs` for the watcher list, or keep the
  `Athanor.Config` module-attribute + `ATHANOR_WATCHERS` JSON env idiom? Recommend the latter
  (consistency; the project has no `config/` dir).
- **OQ3 — Secrets storage.** Env vars only, a `~/.athanor/secrets.json` (proposed, mirrors
  `auth.json`), or reuse the existing OpenCode `auth.json` file?
- **OQ4 — Chat inbound shape.** Deliver chat messages as `{:enqueue_prompt, "[CHAT:…] text"}` (the plan)
  or as a distinct event the conductor handles specially? Delivering as a prompt reuses the tested
  path but means the conductor "sees" the phone as a user.
- **OQ5 — What mirrors back to chat.** Only terminal/escalation events (default), or every
  `turn_complete` (`forward_replies?: true`)? Affects noise and token cost on mobile.
- **OQ6 — Missing-conductor policy.** Park (buffer a bounded tail) vs stop vs auto-spawn the conductor
  if absent (a `heartbeat` watcher could bootstrap `conductor-main`). Buffer depth is also unspecified.
- **OQ7 — Limiter budget shape.** `max_per_window` / `window_ms` are invented here; what is the
  desired default budget per conductor (and is a global (all targets) cap wanted too)?
- **OQ8 — Channel coverage / dependency.** Telegram-only first (HTTP long-poll, no new dep), or add a
  websocket client dep for Slack Socket Mode + the Discord gateway? Discord interaction signatures are
  ed25519 — verify feasibility with `:crypto` before committing.
- **OQ9 — Cursor persistence.** Keep cursors/dedup strictly in memory for this phase (plan), or land a
  minimal `~/.athanor/watchers/<id>.json` now (partial §7.4)?
- **OQ10 — Management surface.** Watcher control via conductor tools (`start_watcher`/`list_watchers`),
  TUI slash commands (`/watch …`), `mix` task, or all three?
- **OQ11 — Multi-node.** Watchers are same-node today (`Athanor.Bus` is node-local). Should a watcher
  be allowed to target a conductor on another node via `Athanor.Daemon` in this phase? (Recommend no.)
- **OQ12 — Cardinality.** One `Watcher.Server` per watcher (plan) vs one multiplexing poller per family
  (e.g. a single Telegram long-poll process serving many conductors). The former is simpler and
  isolates failures; the latter saves one long-poll connection per conductor.
- **OQ13 — Heartbeat prompt discipline.** Should the heartbeat template be user-authored per watcher
  (plan) or generated from a list of checks? A vague heartbeat trains the conductor to ignore it.
- **OQ14 — Cron grammar.** Accept real cron expressions for the heartbeat, or keep `every_ms`?
  (Recommend `every_ms` for this phase.)
