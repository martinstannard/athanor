### 0.2 Verified empirically against `git 2.56.0`

These settle design questions that are easy to get wrong from memory.

| Question | Observed result | Consequence |
|---|---|---|
| Does git refuse a worktree **nested inside** the parent working tree? | **No.** `git worktree add ./.athanor/worktrees/w1 -b athanor/w1` succeeded. | Git will *not* protect us from nesting — the decision is ours, and the downsides are ours to manage. |
| Does a nested worktree show up in the parent's `git status`? | Yes: `?? .athanor/` (untracked). | Nesting pollutes every `git status` the agent runs unless the path is gitignored. |
| Is a worktree visible to the *uncommitted* state of its parent? | **No.** Parent had an uncommitted `a.txt` edit; the new worktree's `a.txt` did **not** contain it. | **The decisive constraint** (§2.4): worktrees branch from committed `HEAD` only. |
| Can two worktrees share a branch? | `fatal: a branch named 'athanor/w1' already exists` | Branch names must be unique per worktree. |
| Can a worktree check out a branch already checked out elsewhere? | `fatal: 'main' is already used by worktree at '…'` | Must use `-b <unique>` or `--detach`. |
| Does `git worktree remove` delete uncommitted work? | No — `fatal: … contains modified or untracked files, use --force to delete it` | Safe-by-default deletion falls out of git for free. |
| Does removing a worktree delete its branch? | No — the branch survived (`git branch --list 'athanor/*'` still listed it). | Branch cleanup needs an explicit, separate policy. |
| Is `-d` a safe branch delete? | `git branch -d athanor/w1` succeeded only because it was fully merged. | Use `-d` (never `-D`) so unmerged work is refused. |
| Can the main working tree be removed by mistake? | `fatal: '.' is a main working tree` | The Server must additionally refuse to target the main worktree. |
| Is there machine-readable enumeration for a sweep? | Yes: `git worktree list --porcelain` (path / HEAD / branch-or-detached). | Sweeps parse porcelain, not the pretty format. |
| What is a worktree's `.git`? | A **file**: `gitdir: <main>/.git/worktrees/w6` | Confirms worktrees share the main object DB; they are not clones. |

## 1. Scope & Non-goals

### In scope
- `Athanor.Worktree` (operations), `Athanor.Worktree.Server` (serialised owner + registry),
  `Athanor.Worktree.Registry`.
- Creating, listing and removing worktrees rooted at a **configurable** location.
- A unique-branch policy plus `--detach` for throwaway trees.
- Wiring a worktree's path into a Sub-Agent's `cd`, so `read_file`/`write_file`/`edit_file`/`bash`/
  `glob`/`grep` all operate inside it with no changes to those tools.
- Conductor tool(s) for explicit control, and a `worktree:` option on `launch_subagent` for the
  common "run N tasks in parallel, isolated" case.
- Safe deletion defaults (`git worktree remove`, refusing dirty trees) and a **merged-only**
  branch-delete policy.
- A manual sweep (`mix athanor.worktree` / `list_worktrees`) for leaked trees.

### Non-goals (explicitly excluded)
- **Not** implementing §7.2 Goal verification — but `goal.cd` must be the worktree's path
  (§8.1), and this plan leaves that hook.
- **Not** a general VCS abstraction. One repo root, one `git` binary, porcelain output parsed.
- **Not** cloning. Worktrees share the object DB by design; `deps/` and `_build/` are **not**
  populated (§11 risk 4).
- **Not** automatic deletion on VM restart (§2.5 explains why that is unsafe).
- No remote/`Cluster`-aware worktree placement (§7.8).
- No change to `Athanor.Tools`' file tools, `Athanor.Bus`, or `Athanor.TUI` beyond surfacing
  worktree paths.

## 2. Architecture

### 2.1 New modules

| Module | Kind | Responsibility |
|---|---|---|
| `Athanor.Worktree` | module (pure helpers + thin `git` wrapper) | `add/2`, `remove/2`, `list/1`, `prune/1`, `resolve/2`, `branch_for/1`, `repository?/1`, `clean?/1` |
| `Athanor.Worktree.Server` | `GenServer` | Serialises every mutating git operation; owns the session→worktree map; publishes lifecycle events |
| `Athanor.Worktree.Registry` | `Registry, :unique` | `session_id → worktree path` lookup for other subsystems |
| `Athanor.Tools.Worktree` | module | Tool-argument decoding + result formatting for the three conductor tools |
| `Athanor.Git` | module | The one place that shells out to `git` (`System.cmd("git", args, cd:, stderr_to_stdout: true)` + timeout + structured result) |

`Athanor.Git` is deliberately separate from `Athanor.Tools`: it is infrastructure, not a
model-facing capability, and it gives §7.2's shell verifier a structured command runner to build
on (7.2 **C9** wants exactly this).

### 2.2 Supervision placement (extends `lib/athanor/application.ex`)

```text
Athanor.Supervisor (:one_for_one)
├── Athanor.AgentRegistry       (Registry, :unique)      # existing
├── Athanor.PubSub              (Registry, :duplicate)   # existing
├── Athanor.Worktree.Registry   (Registry, :unique)  [NEW]  # must precede its writer
├── Athanor.Worktree.Server     (GenServer)          [NEW]
└── Athanor.AgentSupervisor     (DynamicSupervisor)      # existing
```

Ordering rationale matches the existing `AgentRegistry` → `AgentSupervisor` pattern: the registry is
started before the process that registers into it. `Worktree.Server` starts **before**
`AgentSupervisor` so a Sub-Agent can resolve its worktree during `init/1`.

Restart policy: `:permanent`. The Server is the only writer of `session_id → path`, so restarting it
must not lose the map — it **rebuilds the map from `git worktree list --porcelain` + the live
`AgentRegistry`** on `init/1` rather than holding it only in memory (§2.5).

### 2.3 Why a single serialising Server (concurrency)

`git worktree add` mutates shared state (`<main>/.git/worktrees/<id>/`, plus `HEAD`/lock files). Two
simultaneous adds can race and fail with a lock error. Since the whole point of this feature is
"A Conductor spawns N workers in parallel", the create path is *exactly* where concurrency is
highest. Therefore **all mutations go through one GenServer**, which is OTP-idiomatic and removes the
class of bug entirely rather than retrying around it.

Reads (`list`, `resolve`, `clean?`) do not need the Server and may run directly.

### 2.4 Where worktrees live — and the clean-tree rule

**Default location: outside the repo**, at
`~/.athanor/worktrees/<repo-slug>-<sha8>/<session_id>`.

Rationale, all from §0.2:
- Git permits nesting, so the "obvious" `./.athanor/worktrees/...` is not blocked and its downsides
  are real: it appears as `?? .athanor/` in every `git status`, and parent-relative `bash`
  recursion (`grep -r`, `find`) walks into it.
- Outside placement keeps the parent working tree pristine. The cost is discoverability, which the
  Registry solves (an agent never needs to guess the path).
- `Config.worktree_root/0` allows opting into `inside` (`<cd>/.athanor/worktrees`) or an absolute
  path. If the resolved root is *inside* the repo, the Server **verifies it is gitignored** and
  refuses otherwise (`git check-ignore -q <path>`), so nesting cannot silently pollute status.

**The clean-tree rule (the most important rule in this plan).** A worktree branches from committed
`HEAD`, so **uncommitted conductor changes are invisible to a worktree-isolated worker** (verified in
§0.2). Silently losing the user's uncommitted work is worse than refusing to start. Therefore
`add/2`:

1. runs `git status --porcelain` in the parent;
2. if non-empty → returns `{:error, {:dirty_worktree_source, <summary>}}` by default;
3. proceeds only with `allow_dirty: true` (tool arg `allow_dirty` / config
   `worktree_allow_dirty/0`), and when it does, **reports the commit it branched from** in the tool
   result so the model knows its view of the repo.

The alternative (auto-stash or auto-commit) is rejected: mutating the user's index behind their back
is not a harness's decision to make. **Decided (OQ-W1):** refuse, with `allow_dirty: true` as the
explicit escape hatch.

### 2.5 Not tracked in memory alone

Because the map must survive a Server restart and a VM restart, the source of truth is **git itself**
(`worktree list --porcelain`) plus a small on-disk sidecar
(`~/.athanor/worktrees/<repo-slug>-<sha8>/sessions.json`) recording `session_id → {path, branch, base_sha, created_at}`.
The sidecar is a cache for attribution ("whose worktree is this?"), not the authority for existence:
git is. `Worktree.Server.init/1` rebuilds by intersecting the three sources (porcelain, sidecar,
live `AgentRegistry`).

### 2.6 Deliberately no automatic GC on startup

A naive "delete worktrees with no live session" sweep would delete **everything** after any VM
restart, because no sessions exist yet. Automatic deletion of a directory that may contain an
agent's uncommitted work is not recoverable. So cleanup is **explicit**: a `remove_worktree` tool
call, or `mix athanor.worktree cleanup`, which lists candidates and requires confirmation/`--force`.
Leaked worktrees are annoying; lost work is not.

## 4. Operation contract

### 4.1 `create`

```text
1. repository?(repo)                       -> else {:error, :not_a_git_repository}
2. clean? repo                             -> else {:error, {:dirty_worktree_source, summary}}
                                              unless allow_dirty
3. resolve path = worktree_root/slug/session_id
4. ensure parent dir exists (File.mkdir_p!)
5. if Config.worktree_inside_repo? -> git check-ignore -q <path>  else {:error, :path_not_ignored}
6. if branch mode:
     git worktree add <path> -b athanor/<session_id> <base>
   else (detached, for throwaway verification):
     git worktree add --detach <path> <base>
7. record base_sha = git rev-parse HEAD (captured in step 2's porcelain pass)
8. register in Worktree.Registry + sidecar; publish {:worktree_created, …}
```

`base` (the ref to branch from): default `"HEAD"`; overridable via the tool arg `base` so a worker
can be pinned to a known-good commit. **Decided (OQ-W2):** the default is `HEAD`, not the repo's
default branch.

### 4.2 `remove`

```text
1. refuse if path == repo (main working tree)            # git also refuses; belt and braces
2. git worktree remove [--force] <path>
     - without --force, git refuses a dirty tree (verified) -> {:error, {:dirty_worktree, files}}
3. branch policy (default :keep):
     :delete -> git branch -d <branch>   # safe delete; refuses unmerged work
     :keep   -> leave the branch
4. unregister; publish {:worktree_removed, …}
```

`--force` is **never** implied. It requires the explicit tool arg `force: true`.

### 4.3 `list`

`git worktree list --porcelain`, parsed into `[%{path, head, branch | :detached, main?: bool}]`,
annotated with the owning `session_id` from the Registry/sidecar when known.

### 4.4 `prune`

`git worktree prune` — removes *metadata* for worktrees whose directory has already been deleted out
from under git. Never deletes a directory. This is the safe "tidy up" and is what the startup path is
allowed to do automatically.

## 6. Tools

Three conductor-only tools (matching §7.6's "one tool per verb" convention and keeping each schema
unambiguous). Adding them to `workspace_schemas/0`'s `:conductor` branch only:

| Tool | Args | Returns |
|---|---|---|
| `create_worktree` | `branch?` (default true), `base?`, `allow_dirty?` | the path + branch + `base_sha`, or an error explaining a dirty tree |
| `list_worktrees` | `—` | one line per worktree: path, branch/`detached`, owning session id |
| `remove_worktree` | `path` or `session_id`, `force?`, `branch?: :keep \| :delete` | confirmation, or the dirty-file list that blocked it |

Plus an option on the existing orchestration tool:

```elixir
launch_subagent(title, prompt, worktree: true | "branch-name" | false, base?: …)
```

`worktree: true` → create a worktree, set the child's `cd` to it, and return both ids. This is the
ergonomic path for "audit these three modules in parallel"; `create_worktree` remains for explicit
control. Mirrors 7.2's C10 decision to offer a combined and an explicit form.

Schemas otherwise follow `Athanor.Tools.workspace_schemas/0` verbatim. The `execute/3` catch-all's
`when tool_name in [...]` list must be extended (it currently lists 10 names).

**Conductors only** — a worker has no business creating more worktrees. Enforced by schema gating
(the model is never told the tool exists) *and* by the dispatch clause returning
`{:error, "Unknown tool: …"}` for a worker role if it is ever called anyway. **Decided (OQ-W3):**
`remove_worktree` stays **conductor-only** — a worker does not get self-cleanup.

## 8. Interactions with the rest of §7

### 8.1 §7.2 Goal verification (the reason 7.1 goes first)
7.2's risk #11 states verification must run in the worker's worktree, not the main checkout —
otherwise `mix test` passes against unrelated code and closes a goal that was never achieved.
7.2's plan already carries `Goal.cd`; this plan supplies the value via
`Worktree.Server.path_for(session_id)` at `set_goal` time. **Without 7.1, 7.2's `:shell` verifier is
unsound for any goal whose acceptance criterion is "the tests pass".**

### 8.2 §7.6 Search tools
`Config.search_ignores/0` already denies `.athanor`, so a *nested* worktree root is excluded from
`glob`/`grep` results. Note the cost nuance: `Glob` enumerates with `Path.wildcard/2` and filters
afterwards, so a nested root is *filtered* but still *traversed*; an outside root avoids that
traversal entirely — another point for the default.

### 8.3 §7.4 Store / resume
The sidecar is a first cousin of §7.4's persisted session state. When 7.4 lands, `sessions.json`
should migrate into the session directory rather than remaining a separate file. Flagged, not
implemented here.

### 8.4 §7.8 Cluster
Worktree paths are node-local; a remote session's path means nothing on another host. Any
cluster-aware worktree resolution is explicitly out of scope until 7.8.

## 9. Safety & security

1. **Never destroy uncommitted work implicitly.** `remove` without `force` relies on git's own
   dirty-tree refusal (verified); `force` is a separate, explicit argument.
2. **Never delete an unmerged branch.** `git branch -d` (never `-D`).
3. **Never target the main working tree.** Rejected by path equality *and* by git itself.
4. **Never nest without gitignoring.** `git check-ignore -q` gates inside-repo placement.
5. **No shell interpolation.** Arguments go to `System.cmd("git", args)`, never through `bash -c`
   (contrast with the existing `bash` tool). A branch name containing `; rm -rf /` is an argument,
   not a command.
6. **Bound the blast radius of every git call** with `cd:` and a timeout (`Worktree.git_timeout_ms`).
7. **Validate the session id** used in a path/branch (it becomes a filesystem path component): allow
   `[a-z0-9._-]` only, reject `..` and `/`. Session ids are generated today, but `launch_subagent`
   accepts a caller-supplied `:id`.
8. **Base-sha disclosure.** `create` reports the commit it branched from, so a model working in a
   worktree cannot silently believe it sees the conductor's uncommitted work.

## 10. Testing strategy

### 10.1 Fixture: a throwaway git repo (`async: true`, `@moduletag :tmp_dir`)
A helper builds a real repo per test (`git init`, `user.email`, `user.name`, one commit) — the
feature is *defined* by git's behaviour, so faking git would test nothing. Helper lives in
`test/support/git_repo.ex` (**new** — this is the first test support module; `test_helper.exs` stays
a bare `ExUnit.start()`).

Guard: `@tag :git` plus a `git --version` check in the helper so the suite degrades to "skipped"
rather than "failed" where git is unavailable.

### 10.2 Unit — `test/athanor/git_test.exs` (`async: true`)
`run/2` exit 0 / non-zero / timeout / missing binary; output capture; `cd` honoured.

### 10.3 Unit — `test/athanor/worktree_test.exs` (`async: true`)
- `add/2` creates a directory that is a real worktree (`File.exists?(path/.git)` is a *file*).
- **`add/2` refuses a dirty source repo** and the error names the offending paths (the §2.4 rule —
  the single most important assertion in this plan).
- `allow_dirty: true` succeeds and reports a `base_sha` that predates the uncommitted edit.
- unique branch per session; a second worktree for the same session reuses it rather than failing.
- detached mode leaves `branch: nil` and `git worktree list` reports `detached`.
- `remove/2` refuses a dirty worktree without `force`; succeeds with it.
- `remove/2` leaves the branch by default; `branch: :delete` deletes only a merged branch.
- `list/1` parses porcelain, marking the main worktree.
- `repository?/1` is false in a non-repo temp dir.
- **inside-repo placement is refused when the path is not gitignored**, and accepted once
  `.gitignore` contains it.

### 10.4 Unit — `test/athanor/worktree_server_test.exs` (`async: false`)
- Concurrent `create` calls for N sessions all succeed (this is the case a naive implementation
  fails with a git lock error).
- `init/1` rebuilds `sessions` from porcelain + sidecar after a restart.
- `path_for/1` is `:error` for an unknown session.
- Events are published on `deck:events` (subscribe and assert `{:agent_event, id, {:worktree_created, _}}`).

### 10.5 Integration — `test/athanor/worktree_agent_test.exs` (`async: false`)
- `Orchestrator.launch_subagent(…, worktree: true)` places the child inside the worktree: a fake
  `llm_fn` calls `write_file` and the file lands **in the worktree, not the parent** — the end-to-end
  isolation proof.
- The parent repo's `git status` is unchanged after the worker writes (no pollution).
- A conductor's `create_worktree` / `list_worktrees` / `remove_worktree` round-trip via
  `Tools.execute/3`.
- `Tools.schemas(role: :worker)` does **not** advertise the new tools.

### 10.6 Gates (`AGENTS.md`)
Every milestone leaves `mix format --check-formatted`, `mix compile --warnings-as-errors` and
`mix test` green. New public functions get `@doc` + `@spec`; new modules get a `@moduledoc`
covering their §7.1 role.

## 11. Risks, edge cases & open questions

### Risks
1. **Invisible uncommitted work (highest severity).** Verified: a worktree never sees the parent's
   uncommitted edits. Mitigated by the clean-tree rule, `allow_dirty` disclosure, and a dedicated
   test. This is the failure mode that would most damage trust in the harness.
2. **Dirty-repo false positive.** `git status --porcelain` includes untracked files, so a repo with
   a scratch note is "dirty". `allow_dirty` is the escape hatch; **Decided (OQ-W4):** any porcelain
   output counts as dirty — untracked-only is *not* special-cased.
3. **`deps/` and `_build/` are absent in a fresh worktree.** A worker that runs `mix test`
   immediately pays a full `deps.get` + compile (slow, and needs network). Mitigations, in order of
   preference: (a) document it and let the worker run `mix deps.get`; (b) `MIX_BUILD_PATH` pointing
   at a shared build; (c) a `deps` symlink. **Decided (OQ-W5): option (a)** — document that a fresh
   worktree starts without `deps`/`_build` and the worker runs `mix deps.get`; a shared build path
   or symlink is rejected because shared artifacts leak state between workers and undermine the
   isolation the worktree exists to provide. *(Documentation not yet written.)*
4. **Leaked worktrees.** A crashed agent or a killed VM leaves a directory and a branch. Cleanup is
   manual by design (§2.6); `list_worktrees` + `mix athanor.worktree cleanup` are the remedy.
5. **Lock contention.** `git worktree add` can fail with an index/pack lock if another git process
   holds it. The Server serialises *our* calls, but an agent running `bash git worktree add` is
   outside that. Treat lock errors as retryable (bounded retry with backoff) and surface them.
6. **Branch sprawl.** Unique branches per session means one branch per worktree; `:keep` on delete
   accumulates them. Documented; `branch: :delete` is available.
7. **Submodules.** A repo with submodules does not initialise them in a worktree. Out of scope;
   document.
8. **`.gitignore` for the inside-repo path** must exist *before* creation, so the check precedes
   `add`. A user who gitignores it afterwards has already polluted at least one status.
9. **Windows paths.** Out of scope (Balgownie is Linux), but `slug`/path handling should not assume
   `/` beyond `Path.*` helpers.
10. **`spawn_session/1`'s `Keyword.put(:register, true)`.** If the worktree plumbing ever needs
    unregistered sessions (7.2's peer verifier does), this must become `put_new` — 7.2 C15.

### Decisions (all settled 2026-10-17; W1–W4, W6, W7 match what shipped)

- **OQ-W1 — Dirty source repo:** **refuse.** `add/2` returns `{:error, {:dirty_worktree_source,
  summary}}` unless `allow_dirty: true` (tool arg `allow_dirty` / `Config.worktree_allow_dirty?/0`),
  in which case it reports the `base_sha` it branched from. Auto-stash/auto-commit is rejected:
  mutating the user's index is not the harness's decision. *Implemented.*
- **OQ-W2 — `base` default:** **`HEAD`** — a worktree branches from committed `HEAD`.
  *Implemented.*
- **OQ-W3 — Worker self-cleanup:** **no.** `create_worktree` / `list_worktrees` /
  `remove_worktree` are **conductor-only**; a worker is neither told they exist nor allowed to call
  them. *Implemented.*
- **OQ-W4 — Untracked-only dirtiness:** **treat any porcelain output as dirty** — untracked files
  are not special-cased. *Implemented (documented in `Athanor.Worktree`).*
- **OQ-W5 — Dependency population:** **document-only (option a).** A fresh worktree starts without
  `deps`/`_build`; the worker runs `mix deps.get`. Shared `MIX_BUILD_PATH` / `deps` symlink
  rejected as leaky. ***Documentation not yet written — outstanding work.***
- **OQ-W6 — Tool shape:** **three explicit tools** (`create_worktree` / `list_worktrees` /
  `remove_worktree`) rather than one `worktree(action: …)`. *Implemented.*
- **OQ-W7 — Location default:** **outside the repo** (`~/.athanor/worktrees/…`);
  `ATHANOR_WORKTREE_INSIDE=1` / `Config.worktree_inside_repo?/0` opts into `<repo>/.athanor/
  worktrees`, gated on `git check-ignore`. *Implemented.*
- **OQ-W8 — Task-level parallelism limit:** **yes, cap it.** `Athanor.Worktree.Server` should hold a
  configurable `max_worktrees` (default **8**, env-overridable) and refuse the next create with a
  clear error rather than letting a conductor exhaust inodes/disk. ***Not yet built — outstanding
  work.***

## 12. Suggested Incremental Milestones (each ends green)

**M1 — `Athanor.Git` + `Athanor.Worktree` (read-side), no processes.**
`run/2`, `repository?/1`, `clean?/1`, `list/1`, `branch_for/1`, `root_for/2`, plus the git-repo test
helper. No supervision change → zero risk to the existing 94 tests.

**M2 — `add/2` + `remove/2` with the safety rules.**
Clean-tree rule, unique/`--detach` branch modes, dirty-remove refusal, merged-only branch delete,
inside-repo gitignore gate. This is where the §0.2 behaviours get pinned by tests.

**M3 — Supervision + `Worktree.Server` (serialised mutations + registry + sidecar).**
Add `Worktree.Registry` + `Worktree.Server` + `Athanor.Git` to `Athanor.Application` in the §2.2
order; `create_for_session/2`; `init/1` rebuild; `deck:events` publishing; concurrency test.

> **As built (M3):** no separate `Athanor.Worktree.Registry` was added. The Server is already the
> single writer of `session_id → worktree` and answers `path_for/1` from its own map, so a Registry
> would be a second source of truth to keep reconciled for a lookup that happens once per spawn. It
> earns its place only if a lookup ever needs to bypass the Server. One further refinement: "live"
> in the rebuild means git-registered **and** its directory still exists — `git worktree list`
> keeps reporting a worktree whose directory a user deleted until its metadata is pruned, and
> nothing can be spawned into that path.

**M4 — Agent wiring.**
`cd` from the worktree at spawn; `launch_subagent(…, worktree: …)`; the integration test proving a
worker writes inside the worktree and the parent stays clean.

**M5 — Conductor tools + `mix athanor.worktree` + docs.**
Three tools + schema gating + `execute/3` clauses; `mix athanor.worktree` (`list` / `cleanup`);
mark §7.1 implemented in `docs/design.md`; README paragraph. Final
`mix format && mix compile --warnings-as-errors && mix test`.

## 14. Definition of done

1. A conductor can spawn N sub-agents in parallel, each writing in its own worktree, with the parent
   repo's `git status` unchanged — demonstrated by an integration test.
2. A dirty source repo is refused with an actionable message; `allow_dirty` reports the base sha.
3. `remove_worktree` cannot silently destroy uncommitted work or delete an unmerged branch.
4. All git access goes through `Athanor.Git` (no `bash -c`, no interpolation, timeouts everywhere).
5. `mix format --check-formatted`, `mix compile --warnings-as-errors`, `mix test` all green,
   including on a machine with no `git` on `PATH` (tests skip, not fail).
6. §7.2's `Goal.cd` can be resolved from a session id via `Worktree.Server.path_for/1`.
