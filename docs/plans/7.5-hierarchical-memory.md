# Implementation Plan — §7.5 Hierarchical Memory System (`Athanor.Memory`)

> **Status: IMPLEMENTED** — milestones M1–M5 are on branch `feat/memory` (see `git log`), and
> `docs/design.md` §7.5 carries the as-built behaviour. This document remains the reasoning behind
> it. The OQ1…OQ11 decisions recorded below are those taken when implementing; `[OPEN]` markers are
> historical. Deviation from the plan as written: **session scope is not persisted** (the schema
> offers `project`/`global`; OQ11's in-memory-only recommendation deferred), and the retrieval
> weight test prose in §11.4 was inconsistent with the §7.1 formula — §7.1's scoring shipped.

## 0. Review pass (decisions & corrections already applied)

A critical read of the first draft — grounded against the real source — surfaced flaws that would
have shipped. They are fixed inline below; this table indexes them.

| # | Defect | Fix |
|---|---|---|
| D1 | Draft said memory is "refreshed every turn". The system prompt is assembled **exactly once**, in `Athanor.Agent.init/1` (`lib/athanor/agent.ex:153-203`); `state.messages` is an append-only list whose head is the system message. | Injection is a **single, session-start** operation (§2.4, §5). Mid-session refresh is explicitly a non-goal; the `recall` tool is the only in-flight escape hatch (§5.3). |
| D2 | Draft added a `worker_schemas()` group but left `schemas/1`'s fallback as `_ -> workspace_schemas()` (`lib/athanor/tools.ex:29`). | Workers would silently **not** receive `remember`/`recall`. The fallback branch must become `_ -> workspace_schemas() ++ worker_schemas()` (§6.4). |
| D3 | Draft injected **all** of `learnings.jsonl` into every prompt. That is the exact "pollute every prompt" failure the design warns against, and it blows any token budget. | Only curated `MEMORY.md` is auto-injected; the append-only `learnings.jsonl` is retrieved **on demand** via `recall` (§4, §7). This is the core anti-pollution mechanism. |
| D4 | Draft resolved paths from `File.cwd!()`. `Tools.execute/3` is called with `cd: cd, session_id: session_id` (`lib/athanor/tools.ex:413`), and a worker's `cd` may be a git worktree (`§7.1`). | Scope resolution uses the **tool opts** (`cd`, `session_id`) and ascends to a workspace root, never `File.cwd!()` (§5.2). |
| D5 | Draft proposed a `config/config.exs`. No `config/` directory exists in the tree. | Defaults follow the existing `Athanor.Config` idiom: module attribute + `Application.get_env(:athanor, key, default)` + optional env var (§10). |
| D6 | Draft redacted secrets only on **write**. A `MEMORY.md` that a human wrote (or an older version) can already contain a token, and it would be injected verbatim. | Redaction runs on **write *and* on injection** (`Memory.Injector`) (§9). |
| D7 | Draft deduped by raw string equality in the `.jsonl`. Case/whitespace variants would produce duplicate bullets. | Dedup keys on a **normalized-fact hash** `(scope, category, hash)` (§8). |
| D8 | Draft injected global memory into every repo unconditionally — a cross-project leak (a `~/…/logseq` path or a machine-specific workflow would appear in an unrelated repo's prompt). | Global memory is **scope-gated**: injected only as a short pointer header, with full content opt-in via `Config`/`recall` (§4, §5.4). |
| D9 | Draft treated distillation as an unattended background job that edited `MEMORY.md`. | Distillation is **conductor-driven** and writes through the same dedup/redact pipeline as `remember`; an optional `Distiller` process may *propose*, never silently commit (§9.1). |

## 1. Scope & Non-goals

### In scope
- New `@moduledoc`-documented modules under `Athanor.Memory`:
  `Athanor.Memory` (facade), `Athanor.Memory.Entry` (struct), `Athanor.Memory.Store`
  (on-disk read/write for `MEMORY.md` + `learnings.jsonl`), `Athanor.Memory.Retrieval`
  (keyword scoring / `recall`), `Athanor.Memory.Injector` (prompt-section builder + budget),
  and optionally `Athanor.Memory.Distiller` (post-session, conductor-driven).
- Three memory tiers with explicit precedence and merge rules (§4).
- Two on-disk stores per tier: a **curated** `MEMORY.md` (human + conductor editable) and an
  **append-only** `learnings.jsonl` (machine-written, retrieved on demand).
- One injection hook: a memory section appended to the system prompt in
  `Athanor.Agent.init/1` (`lib/athanor/agent.ex`), computed once at session start.
- Three first-class tools — `remember(category, fact)`, `recall(query)`, `forget(id)` — wired
  through `Athanor.Tools.schemas/1` + `Athanor.Tools.execute/3`.
- A pragmatic keyword/BM25-lite retrieval first cut (§7), with an embeddings escape hatch
  flagged as a later phase.
- New `Athanor.Config` accessors + env vars (§10), a testing strategy (§11), risks/open
  questions (§12), a phased rollout (§13), and a file-by-file change list (§14).

### Non-goals (explicitly excluded)
- **Not** implementing §7.4 session transcripts / `Athanor.Store`. `recall` searches
  `learnings.jsonl` + `MEMORY.md` only in phase 1; **session-transcript search is a §7.4
  integration point** and is flagged **[OPEN]** (§7.3 / §12 OQ3).
- **Not** implementing a vector database, `sqlite`/FTS5 (`exqlite`), or an embeddings provider.
  Embeddings are a phase-2 option behind the same `Athanor.Memory.Retrieval` facade (§7.2).
- **Not** implementing §7.3 Watchers or the external Logseq knowledge-graph **index**. Phase 1
  stores a *link* to the graph (`~/Documents/logseq`) and, at most, reads a user-pinned file
  path; it does not crawl the graph (§5.4, §12 OQ4).
- **Not** building an autonomous "memory agent" that rewrites prompts unattended. Distillation
  is conductor-driven and reviewable (§9.1).
- **Not** changing `Athanor.LLM`, the TUI input loop, or the Daemon RPC surface.
- **Not** a distributed/remote memory service — single node, local files (§7.7 clustering is out
  of scope).

## 2. Architecture

### 2.1 New modules

All names below are **[PROPOSED]** unless noted; none exist in the tree today.

| Module | Kind | Responsibility |
|---|---|---|
| `Athanor.Memory` | facade (pure) | Public entry points: `system_prompt_section/1`, `remember/3`, `recall/2`, `forget/2`, `distill/2`; resolves tiers & delegates |
| `Athanor.Memory.Entry` | struct + pure funcs | One memory record; `new/1`, `normalize/1`, `hash/1`, `to_json/1`, `from_json/1` |
| `Athanor.Memory.Store` | module (filesystem) | Read/append `learnings.jsonl`; read/upsert `MEMORY.md`; atomic append; workspace-root discovery |
| `Athanor.Memory.Retrieval` | module (pure) | Tokenize + score + rank a query over an in-memory list of `Entry`s; `search/3` |
| `Athanor.Memory.Injector` | module (pure) | Build the truncated, redacted, budgeted prompt section for a (workspace, role) pair |
| `Athanor.Memory.Distiller` **(optional, phase 3)** | pure + optional GenServer | Turn `[DONE]` outcomes into candidate entries for conductor review |

> **Design note (mirrors §7.2's "non-blocking" rule):** in phase 1 memory is **pure functions +
> local file IO** — no new supervised process. Reading a few-hundred-line `.jsonl` and scoring in
> memory is trivially cheap; adding a `GenServer`/ETS index before it is needed violates AGENTS.md's
> "keep it lightweight" guidance. A `Athanor.Memory.Index` ETS owner is deferred to phase 2 (§13).

### 2.2 Changes to existing modules

- `Athanor.Agent` — **the single injection point.** In `init/1`, after `system_prompt` and `cd`
  are resolved (`lib/athanor/agent.ex:159-161`), compute the memory section and join it into the
  system message (`lib/athanor/agent.ex:203`). See §2.4 for the exact diff shape. No other Agent
  change is required in phase 1 (the tools arrive via `Tools.schemas/1`).
- `Athanor.Tools` — add `worker_schemas()` (`remember`, `recall`, `forget`) and extend the
  `:conductor` branch; fix the worker fallback (§6.4); add `execute/3` clauses for the three
  tools; extend the "known tool" catch-all `when tool_name in [...]` list
  (`lib/athanor/tools.ex:385-398`).
- `Athanor.Config` — add memory accessors (§10), following the existing
  module-attribute + `Application.get_env/3` + env-var shape (`lib/athanor/config.ex`).
- `Athanor.Application` — **no change in phase 1.** (Optional phase-2 `Athanor.Memory.Index`
  child; see §13.)
- `Athanor.Bus` / `Athanor.Orchestrator` — **no change.** Distillation reuses the existing
  `conductor:<id>:children` wakeup (`lib/athanor/agent.ex`) and the existing orchestration tools.

### 2.3 Where state lives (no supervision tree required)

Because phase-1 memory is file-backed, there is no new process to place in the tree. For
reference, the tree after **phase 2** (optional index) would extend `lib/athanor/application.ex`
as:

```text
Athanor.Supervisor (:one_for_one)                     # name: Athanor.Supervisor
├── Athanor.AgentRegistry   (Registry, :unique)        # existing
├── Athanor.PubSub          (Registry, :duplicate)     # existing
├── Athanor.AgentSupervisor (DynamicSupervisor)        # existing
└── Athanor.Memory.Index    (GenServer + ETS)  [NEW, PHASE 2, OPTIONAL]
       └── lazily builds a token → entry_id inverted index from learnings.jsonl
```

Ordering rationale: the index must start **after** nothing in particular (it reads files, not
registries), but it must precede any consumer that reads through it. Keep it last so a broken
index cannot delay the agent tree. Restart policy `:permanent` (it owns an ETS table named
`Athanor.Memory.Index`); on crash it is rebuilt lazily from disk, so no durability is lost.

### 2.4 The injection hook (verified location)

There is exactly **one** place where the system prompt is built today — `Athanor.Agent.init/1`
(`lib/athanor/agent.ex`). Verbatim:

```elixir
# lib/athanor/agent.ex:153-161
default_prompt =
  case role do
    :conductor -> @default_conductor_prompt
    :worker -> @default_worker_prompt
  end

system_prompt = Keyword.get(opts, :system_prompt, default_prompt)
model = Keyword.get(opts, :model, Config.model())
cd = Keyword.get(opts, :cd, File.cwd!())
```

```elixir
# lib/athanor/agent.ex:203
messages: [%{role: "system", content: String.trim(system_prompt)}]
```

**Proposed change** — one added function call plus a join (function shape **[PROPOSED]**):

```elixir
# lib/athanor/agent.ex (init/1), after cd is resolved
memory_section =
  Athanor.Memory.system_prompt_section(cd: cd, role: role, session_id: id)

system_content =
  [String.trim(system_prompt), memory_section]
  |> Enum.reject(&(&1 in [nil, ""]))
  |> Enum.join("\n\n")

# ...
messages: [%{role: "system", content: system_content}]
```

Rationale for putting the hook **here**, not in `Athanor.LLM.stream/4`: `Athanor.LLM` is a
stateless transport that receives the already-assembled `messages` list
(`lib/athanor/agent.ex:388`, `lib/athanor/llm.ex:stream/4`). Injecting at the transport would
re-inject on every turn (D1) and cannot know the session's `role`/`cd` cheaply. Injecting at
`init/1` guarantees the section is present exactly once, ahead of the first user turn, and is
captured by the deterministic `llm_fn` seam tests already use.

## 3. Data Structures

### 3.1 `Athanor.Memory.Entry` **[PROPOSED]**

```elixir
defmodule Athanor.Memory.Entry do
  @moduledoc """
  One durable memory record (design §7.5). Entries live in an append-only
  `learnings.jsonl`; the curated `MEMORY.md` is a separate, human-readable projection.
  """

  @type scope :: :global | :project | :session
  @type category :: :fact | :gotcha | :convention | :preference | :architecture | :tooling | :link

  @enforce_keys [:id, :scope, :category, :text]
  defstruct [
    :id,                    # "mem_" <> 12 hex chars
    :scope,                 # :global | :project | :session
    :category,              # see @type category
    :text,                  # the fact, one or two sentences
    :tags,                  # [String.t()], default []
    :source,                # %{session_id: String.t(), kind: :tool | :distill | :manual}
    :hash,                  # normalized-text hash for dedup (D7)
    :supersedes,            # id() | nil  — the entry this one replaces, if any
    :deprecated,            # boolean, default false
    :hits,                  # integer, default 0 (recall counter)
    :created_at,            # ISO-8601 string (UTC)
    :updated_at             # ISO-8601 string (UTC)
  ]

  @type t :: %__MODULE__{}
end
```

Helpers (**[PROPOSED]**): `new/1` (fills `id`, `created_at`/`updated_at`, `hash`, `source`),
`normalize/1` (downcase, collapse whitespace, strip terminal punctuation),
`hash/1` (`:crypto.hash(:sha256, normalize(text)) |> Base.encode16(case: :lower) |> binary_part(0, 16)`),
`to_json/1` / `from_json/1` (round-trip via the built-in `JSON` module — AGENTS.md forbids an
extra JSON dep).

### 3.2 On-disk format — project tier (`.athanor/`)

`.athanor/MEMORY.md` — the **curated, human-editable** projection. Structure:

```markdown
# Project Memory — <repo name>

<!-- Curated. Safe to edit by hand. Injected into every session in this repo. -->
<!-- Managed sections below are upserted by `remember`/distill; do not reorder headings. -->

## Architecture
- Auth is handled by `Athanor.Auth`; tokens are validated in `Plug` middleware.

## Conventions
- New tools need `@doc` + `@spec` + a row in the `schemas/1` group (see AGENTS.md gates).

## Gotchas
- `mix test` requires `ATHANOR_*` env; without it `Config.api_key/0` returns `{:error, _}`.
- Worktree tests must run from the worktree `cd`, not the main checkout (§7.1).

## Preferences
- Prefer `git rebase` over merge commits in this repo.
```

`.athanor/learnings.jsonl` — **append-only**; one JSON object per line, newest appended last:

```json
{"id":"mem_9f2c1a0b3d4e","scope":"project","category":"gotcha","text":"mix test requires ATHANOR_* env vars or Config.api_key/0 errors","tags":["test","config"],"source":{"session_id":"worker-1","kind":"tool"},"hash":"7b1e...","supersedes":null,"deprecated":false,"hits":0,"created_at":"2026-02-11T09:12:03Z","updated_at":"2026-02-11T09:12:03Z"}
```

- **Why two files.** `MEMORY.md` is small, curated, and *auto-injected*; `learnings.jsonl` is
  unbounded, machine-written, and *retrieved only via `recall`* (D3). This separation is what lets
  Conductors/Sub-Agents "accumulate durable knowledge … without polluting every prompt" (design §7.5).
- **Append atomicity.** Writes use `File.write!(path, line <> "\n", [:append])`. On POSIX a single
  small `O_APPEND` write is atomic, so concurrent writers from several agents cannot interleave a
  line (see §12 risk 6 for the caveat and mitigation).

### 3.3 On-disk format — global tier (`~/.athanor/memory/`)

```text
~/.athanor/memory/
├── MEMORY.md        # curated cross-project facts, workflows, machine setup (auto-injected, gated)
├── learnings.jsonl  # append-only global learnings (recall-only)
└── links.md         # external knowledge graphs & pointers, e.g. "logseq: ~/Documents/logseq"
```

`~/.athanor/memory/` is created with mode `0700`; both files `0600` (§9). The path is overridable
via `ATHANOR_HOME` for tests and for §7.7 daemon deployments (§10).

### 3.4 Internal resolution result (**[PROPOSED]**)

`Athanor.Memory.resolve/2` (pure, used by every public function) returns a map, never a struct
that leaks the filesystem:

```elixir
%{
  workspace_root: String.t() | nil,   # nearest ancestor containing `.athanor/` or `.git/`
  project_dir:    String.t() | nil,   # <workspace_root>/.athanor  (nil if none found)
  global_dir:     String.t()          # Config.memory_global_dir/0
}
```

## 4. Memory Tiers, Precedence & Merge Rules

### 4.1 Tiers

| Tier | Location | Scope | Written by | Auto-injected? |
|---|---|---|---|---|
| **Session** (ephemeral) | in-memory list on the session | one session | `remember(scope: :session)` | yes (into that session only) |
| **Project / Workspace** | `.athanor/MEMORY.md`, `.athanor/learnings.jsonl` | the repo rooted at `workspace_root` | any session working in that repo; distillation | `MEMORY.md` **yes**; `learnings.jsonl` only via `recall` |
| **Global / User** | `~/.athanor/memory/` | the machine/user | any session; user edits | `MEMORY.md` **gated** (see §5.4) |

### 4.2 Precedence (conflict resolution)

More-specific wins; the rank of a tier deters the "which fact is true?" ambiguity:

```text
rank(:session) = 3   >   rank(:project) = 2   >   rank(:global) = 1
```

Merge algorithm (**[PROPOSED]** `Athanor.Memory.Merge`, or a private func in `Athanor.Memory`):

1. Collect all candidate `Entry`s from the in-scope tiers.
2. Collapse entries with the same `hash` (D7) into one, keeping the **highest-rank** `scope`;
   tie-break by most recent `updated_at`.
3. Apply `supersedes`: if entry *A* supersedes *B*, keep *A* and mark *B* `deprecated: true`
   (never physically delete in phase 1 — append-only; see §8.3).
4. Order the surviving entries by `{rank desc, updated_at desc}`.
5. Drop any entry whose `deprecated == true` or that fails the injector's redaction/allow-list.

### 4.3 What is *not* merged
`learnings.jsonl` is **never** merged into the injected section (D3). It is a retrieval corpus
only. `MEMORY.md` is the only auto-injected artefact; the two files must therefore be kept
**consistent but not identical** — distillation may promote a `learnings.jsonl` entry into a
`MEMORY.md` bullet, and `forget` must update both (§8.3).

## 5. Behavioral Flow

### 5.1 Session start — injection

```
Athanor.Agent.init/1
  └─ cd = opts[:cd]                      # worker may be in a worktree (§7.1)
  └─ Athanor.Memory.system_prompt_section(cd: cd, role: role, session_id: id)
        ├─ resolve/2: ascend from cd to workspace_root (.athanor/ or .git/)
        ├─ Store.read_memory_md(project_dir)  (if present)
        ├─ Store.read_memory_md(global_dir)   (if present & enabled)
        ├─ Injector.build/2:      merge → redact → order → truncate to budget
        └─ returns a String.t() | nil  ("## Memory …")
  └─ system content = [default_prompt, memory_section] |> join("\n\n")
```

The injected block is deterministic for a given `(cd, role)` pair, which makes it testable via the
`llm_fn` seam (§11.2).

### 5.2 `remember(category, fact)`

1. Model calls `remember(category: "gotcha", fact: "…")`.
2. `Tools.execute("remember", args, opts)` — `opts` carries `cd` and `session_id`
   (`lib/athanor/tools.ex:413`), giving scope + provenance **without** `File.cwd!()` (D4).
3. `Athanor.Memory.remember/3`:
   a. `scope = args["scope"] || :project`; resolve target dir.
   b. Redact secrets (**write-time**, D6) — reject or scrub on match.
   c. `Entry.new/1` → compute `hash`.
   d. **Dedup:** if a live entry with the same `(scope, category, hash)` exists, bump its
      `updated_at`/`hits` and change nothing else; else `Store.append_learning/2`.
   e. Optionally **project into `MEMORY.md`** when `category` is curated (see §9.1) via
      `Store.upsert_memory_bullet/3`.
   f. Return `{:ok, "Remembered (<id>) in <scope> scope."}`.
4. If this happened at session start, the current prompt is **unchanged** (D1); the entry is
   visible to *future* sessions and immediately to `recall` in this one.

### 5.3 `recall(query)`

1. `Athanor.Memory.recall/2` resolves tiers, loads `learnings.jsonl` (project + global) and the
   `MEMORY.md` bullets as `Entry`-like records.
2. `Athanor.Memory.Retrieval.search(entries, query, limit)` scores and ranks (§7.1).
3. Returns a JSON string of the top-`limit` results with `id`, `scope`, `category`, `text`,
   `updated_at`, `source` — so the model can cite provenance and call `forget(id)` if wrong.
4. Optionally increments `hits` (best-effort, non-blocking; skipped if the file is locked).

### 5.4 Global tier gating (D8)

By default the global `MEMORY.md` is injected as a **short header plus a pointer**, not its full
body:

```
### Global memory (user: ~/.athanor/memory/MEMORY.md)
Cross-project preferences exist. Consult them with `recall(query, scope: "global")` when relevant.
```

Full injection is opt-in via `Config.memory_global_inject?/0` (default `false`), so a machine-wide
fact never silently contaminates an unrelated repo's prompt. `learnings.jsonl` never auto-injects.

### 5.5 Session end — nothing to do

Phase 1 writes memory **during** the session (via `remember`) or **after** `[DONE]` via
distillation (§9). There is no implicit flush on terminate; a crash simply loses un-`remember`ed
in-context knowledge, which is acceptable for phase 1 and flagged in §12.

## 7. Retrieval Strategy (keyword/FTS first vs. embeddings)

### 7.1 Recommended first cut — BM25-lite over `learnings.jsonl` (D3)

Rationale: the corpus is **small** (a repo's `learnings.jsonl` realistically holds hundreds to a
few thousand lines; `MEMORY.md` tens of bullets). Reading it and scoring in memory is well under a
millisecond at that scale, needs **no new dependency** (AGENTS.md: "prefer lightweight, pure-Elixir"),
and is fully deterministic/testable.

`Athanor.Memory.Retrieval.search/3` (**[PROPOSED]**):

1. **Tokenize** the query and each entry: downcase, `String.split(~r/[^a-z0-9_]+/)`, drop
   stop-words, stem nothing in phase 1 (keep it dumb and predictable).
2. **Score** each entry:
   ```
   score = 2.0 * (query tokens in entry.text)
         + 1.0 * (query tokens in entry.tags)
         + 0.5 * (query tokens in entry.category)
         + recency_boost(updated_at)      # e.g. +0.3 if < 30 days, else 0
         + scope_boost(entry.scope)       # project > global
   ```
   (A true BM25 IDF term is a phase-2 refinement; a plain weighted overlap is enough to be useful
   and trivial to unit-test.)
3. **Filter** `deprecated == true`; **dedup** by `hash`; **rank**; take `limit`.
4. Return provenance (`id`, `scope`, `category`, `updated_at`).

### 7.2 Embeddings (phase 2, optional, behind the same facade)

- Add `Athanor.Memory.Retrieval.search/4` with `mode: :embedding`; `Athanor.Embed` (**[PROPOSED]**)
  wraps an embedding endpoint (§7.6 MCP / a `Config.embedding_model/0`).
- Store vectors alongside entries (`"embedding": [float]` in the jsonl line, or a sidecar
  `learnings.vec.jsonl`).
- Cosine similarity over the candidate set. Only worthwhile once recall quality is demonstrably
  weak on keyword search, or once the corpus is large — **do not build it first.**
- **[OPEN] (OQ1)** — whether the embedding provider is the same OpenCode Go endpoint (a different
  model), a local model, or an MCP server. The design (§7.6) is undecided.

### 7.3 Session-transcript search (depends on §7.4)

Design §7.5 #3 says `recall` searches "past session transcripts and learnings". Transcripts live
at `~/.athanor/sessions/<id>/transcript.jsonl` (§7.4) and **do not exist yet**. Phase 1 `recall`
searches learnings + `MEMORY.md` only. When §7.4 lands, add a `:transcripts` corpus behind a
feature flag. **[OPEN] (OQ3).**

## 8. Dedup, Conflict Handling & Deletion

### 8.1 Dedup (write path)

- Compute `hash = Entry.hash(text)` over `normalize(text)` (D7).
- On `remember`, scan the target `learnings.jsonl` for a live entry with the same
  `(scope, category, hash)`:
  - **found** → no new line; bump `updated_at`/`hits` (rewrite that line in place is avoided;
    instead append a `{"id":…,"op":"touch"}` marker — see §8.3) and report "already known".
  - **absent** → append a new entry.
- `MEMORY.md` bullet upsert is idempotent on the bullet's first 80 normalized chars.

### 8.2 Conflict handling

- **Same `hash`, different tiers** → highest tier wins (§4.2).
- **Semantic contradiction** (same subject, opposite claim) — phase 1 is *heuristic*, not
  semantic: `remember` requires the caller to pass `supersedes: "<old_id>"` when it knows it is
  correcting a prior entry. The new entry records `supersedes`; the old one is marked
  `deprecated` and dropped from injection + recall. **[OPEN] (OQ6)** — whether an LLM-driven
  contradiction detector is wanted; recommendation: no, in phase 1 (keeps memory deterministic
  and cheap).
- **`MEMORY.md` vs `learnings.jsonl` divergence** — `MEMORY.md` is authoritative for injection;
  a divergence is resolved by distillation (§9.1) or `forget` (§8.3).

### 8.3 Deletion with an append-only log

Because `learnings.jsonl` is append-only, `forget(id)` cannot physically remove a line without a
rewrite. Two options:

1. **Tombstone (recommended):** append `{"id": "<id>", "op": "forget", "at": "…"}`; readers apply
   tombstones when loading (drop forgotten/deprecated ids). `MEMORY.md` is edited directly
   (it is a normal file).
2. **Compact:** rewrite the jsonl excluding forgotten ids. Required eventually to bound file
   growth; run opportunistically (e.g., when the file exceeds N KB and the process holds no
   readers) — **[OPEN] (OQ7)** on the trigger.

Phase 1: tombstones + manual compaction command/`mix` task later.

## 9. Privacy, Secrets & Post-Session Distillation

### 9.1 Privacy & secret handling

- **Redaction runs on write *and* on injection** (D6): `Athanor.Memory.Redact` (**[PROPOSED]**)
  scrubs, at minimum:
  - `sk-[A-Za-z0-9]{16,}` and generic `(?i)(api[_-]?key|token|secret|password)\s*[:=]\s*\S+`,
  - `Authorization: Bearer \S+`,
  - `-----BEGIN [A-Z ]*PRIVATE KEY-----` blocks,
  - `AKIA[0-9A-Z]{16}` (AWS), and long base64/hex blobs (> 40 chars) adjacent to key words.
- Injection-time redaction defends against a **hand-edited `MEMORY.md`** that already contains a
  secret, and against an entry written before redaction existed.
- Filesystem permissions: `~/.athanor/memory/` = `0700`, files `0600` (`File.chmod/2`).
- `forget(id)` is the escape hatch when a secret slips through; log the `reason` in an audit line.
- **[OPEN] (OQ8)** — should `.athanor/learnings.jsonl` be `.gitignore`d while `.athanor/MEMORY.md`
  is committed (shared team knowledge)? The `.gitignore` in-tree currently ignores only build
  artefacts. Recommendation: **commit `MEMORY.md`** (curated, redacted, team-valuable) and
  **gitignore `learnings.jsonl`** (unbounded, may capture incidental detail).

### 9.2 Post-Session Distillation (§7.5 #4)

Trigger: the Conductor receives the existing `[DONE] Sub-agent '<title>' (<id>) finished: …`
message via its `conductor:<id>:children` handler (`lib/athanor/agent.ex`). The design intent is
that the Conductor — which has the synthesis view — decides what is policy, not what is noise.

Phase 1 (conductor-driven, **[PROPOSED]**):

1. The Conductor's system prompt instructs it, on `[DONE]`, to:
   *"If the sub-agent discovered a non-obvious root cause or a codebase convention, call
   `remember(category, fact)` for each durable learning. Do not record transient task details."*
2. `Athanor.Memory.distill(conductor_id, entries)` (**[PROPOSED]**) upserts a batch through the
   same dedup + redact pipeline, and—for `:convention`/`:architecture`/`:gotcha` categories—writes
   a bullet into `.athanor/MEMORY.md` under the matching section.
3. Distillation is **reviewable**: `MEMORY.md` is a normal file a human can edit or revert.

Phase 3 (optional): `Athanor.Memory.Distiller` GenServer subscribes to `deck:events` for
`{:child_done, …}` events and **proposes** candidate entries into a `pending` queue surfaced in
the TUI for one-click accept — it must **never** write `MEMORY.md` unattended (D9). **[OPEN] (OQ9).**

## 11. Testing Strategy

### 11.1 Unit — `test/athanor/memory_test.exs` (new, `async: true`)

- `Entry.new/1` fills `id`/`created_at`/`hash`; `normalize/1` collapses case/whitespace (D7).
- `Store.append_learning/2` then `Store.read_learnings/1` round-trips through the built-in `JSON`.
- **Redaction (D6):** `Redact.scrub/1` strips `sk-…`, `Bearer …`, and a PEM block; and
  `Injector` re-scrubs a `MEMORY.md` that contains a raw key.
- **Dedup (§8.1):** two `remember` calls with case/whitespace variants produce **one** live entry.
- **Precedence (§4.2):** a project entry and a global entry with the same `hash` collapse to the
  project scope.
- **Budget (§7 / §10):** an oversized `MEMORY.md` is truncated to `memory_project_budget` and the
  section ends with a `… (N more; use recall)` marker; the *last* entry is dropped, not the first.
- **Global gating (D8):** by default the global section is a header/pointer, not the body.

### 11.2 Injection integration — extend `test/athanor/agent_test.exs`

The `llm_fn` seam already lets a test capture the exact messages list. Add a test that writes
`tmp_dir/.athanor/MEMORY.md`, starts an `Athanor.Agent` with `cd: tmp_dir` and a capturing
`llm_fn`, and asserts the **first** message's content contains a known bullet:

```elixir
llm_fn = fn messages, _tools, agent_pid ->
  send(self(), {:system_prompt, hd(messages).content})
  {:ok, %{role: "assistant", content: "ok", tool_calls: []}}
end
Athanor.Agent.start_link(id: "mem-a", role: :worker, cd: tmp_dir, llm_fn: llm_fn)
assert_receive {:system_prompt, sys}
assert sys =~ "Auth is handled by"
```

Also assert **idempotence/order**: the memory block appears **after** the default worker prompt
and exactly once (D1), and that with `ATHANOR_MEMORY=0` no memory block is present.

### 11.3 Tools — extend `test/athanor/tools_test.exs`

- `Tools.schemas(role: :worker)` includes `remember`/`recall`/`forget`; `role: :conductor`
  includes them too (**D2 regression**: the worker fallback must not omit them).
- `Tools.execute("remember", %{"category"=>"fact","fact"=>"…"}, cd: tmp_dir, session_id: "s1")`
  writes a line to `tmp_dir/.athanor/learnings.jsonl` with `source.session_id == "s1"`.
- `Tools.execute("recall", %{"query"=>"…"}, cd: tmp_dir)` returns the just-written fact.
- `Tools.execute("forget", %{"id"=>id}, cd: tmp_dir)` makes a subsequent `recall` miss it.
- The existing catch-all still returns "Missing or invalid required arguments" for `remember`
  with no `fact` (guard against the `when tool_name in [...]` extension).

### 11.4 Retrieval — `test/athanor/memory_retrieval_test.exs` (new, `async: true`)

- Ranking: a query matching `tags` beats a query matching only body text at equal frequency.
- `limit` is respected; `deprecated`/tombstoned ids are excluded.
- Empty query returns `[]`, never crashes.

### 11.5 Workspace-root discovery — `test/athanor/memory_store_test.exs` (new)

- `resolve/2` from `tmp_dir/sub/dir` with a `tmp_dir/.athanor/` finds `tmp_dir` as root.
- A **worktree-shaped** layout (`tmp_dir/.athanor/worktrees/w1/`) resolves to `tmp_dir`
  (the repo root), not to the worktree — proving §7.1 compatibility (D4).
- No `.athanor/` and no `.git/` ⇒ `workspace_root: nil` and injection is a no-op.

### 11.6 Gates (AGENTS.md)

Every milestone must leave `mix format --check-formatted`,
`mix compile --warnings-as-errors`, and `mix test` green. All new public functions get
`@doc` + `@spec`; new modules get `@moduledoc` naming their design-§7.5 role.
`test/test_helper.exs` is a bare `ExUnit.start()` — **no changes needed**; reuse `@moduletag
:tmp_dir` and the `llm_fn` injection seam.

## 12. Risks, Edge Cases & Open Questions

### Risks / edge cases
1. **Prompt pollution / token blow-up (the central risk).** Mitigated by injecting only curated
   `MEMORY.md` (never `learnings.jsonl`), a hard char budget, and truncation with a `recall`
   pointer. A regression here defeats the entire feature (D3).
2. **Stale or wrong memory.** An agent acting on a superseded fact is worse than no memory.
   Mitigations: `updated_at`, `supersedes`/`deprecated`, `recall` returning provenance, and
   `MEMORY.md` being human-reviewable/revertible. `MEMORY.md` is committed to git (§9.1 OQ8) so
   bad bullets are diffable.
3. **Cross-project leakage.** A global fact leaking into every repo prompt (D8). Mitigated by
   header-only global injection by default and scope-aware `recall`.
4. **Secret leakage.** Mitigated by redact-on-write **and** redact-on-injection (D6) plus `0700`
   permissions. Add a test that a raw `sk-…` never reaches `MEMORY.md`, `learnings.jsonl`, or the
   injected system prompt.
5. **Prompt-injection via memory content.** A `MEMORY.md` bullet could contain instruction-like
   text ("ignore previous instructions…"). Mitigations: delimit the block with explicit `## Memory`
   markers, keep it *data* (no imperative framing), and (design choice) never auto-commit
   unattended writes (D9). Document that memory is untrusted input.
6. **Concurrent writers.** Several agents may append to the same `learnings.jsonl`. `O_APPEND`
   single small writes are atomic on POSIX; larger entries could theoretically interleave.
   Mitigation: keep lines < PIPE_BUF (4096 bytes) and truncate `fact` to a max length; a
   phase-2 `Athanor.Memory.Index`/writer GenServer can serialize if needed.
7. **File growth.** `learnings.jsonl` only grows (tombsones, no deletes). Mitigation: opportunistic
   compaction (§8.3 OQ7) and a bounded `fact` length.
8. **`recall` cost/latency.** Loading + scoring on every call is fine for a few thousand lines;
   set a `limit` and a corpus size guard. Deferred ETS index (§2.3) is the scaling path.
9. **`cd` that is not a git repo.** `resolve/2` must degrade gracefully (`workspace_root: nil`,
   no injection) rather than writing a stray `.athanor/` in, say, `/tmp`. Never create `.athanor/`
   implicitly on the **injection** path (read-only); only `remember` creates it.
10. **Interaction with §7.1 (Worktrees).** A worker's `cd` is a worktree; memory must resolve to
    the **shared** repo `.athanor/`, not the worktree, or every worktree would fork its own memory
    (test in §11.5).
11. **Interaction with §7.4 (Store/Resume).** `HANDOFF.md` and `transcript.jsonl` are future
    corpora for `recall`; today `recall` must not claim to search them (§7.3).
12. **Interaction with §7.2 (Goal).** A goal-attached worker that calls `remember` is orthogonal
    to verification; no coupling. Do **not** gate `remember` on goal status — a lesson learned
    during a failed goal is still worth recording.
13. **Daemon (§7.7).** With a long-lived daemon, `ATHANOR_HOME` must be process-wide and stable so
    all sessions share one global tier; document it.

### Open questions (require Conductor/user decision before coding)
- **OQ1 — Retrieval engine.** Keyword/BM25-lite (recommended) vs SQLite FTS5 (`exqlite`) vs
  embeddings. Recommendation: keyword first; revisit only if recall quality is poor (§7).
- **OQ2 — Injection budget units.** Chars (recommended, dependency-free) vs tokens. Confirm the
  ceiling (§10).
- **OQ3 — Transcript corpus.** When does `recall` start searching §7.4 `transcript.jsonl`? (§7.3)
- **OQ4 — External knowledge graph.** Link-only (recommended) vs reading a user-pinned file vs
  indexing the whole `~/Documents/logseq` graph (§5.4 / §1 non-goals).
- **OQ5 — `forget` permissions.** Any session may forget project entries; global deletion
  user-only? (§6.3)
- **OQ6 — Contradiction detection.** Heuristic `supersedes` (recommended) vs an LLM judge (§8.2).
- **OQ7 — Compaction trigger.** Size threshold vs manual `mix` task (§8.3).
- **OQ8 — Version control.** Commit `.athanor/MEMORY.md` and gitignore `.athanor/learnings.jsonl`?
  (§9.1)
- **OQ9 — Distiller.** Conductor-driven via `remember` (recommended, phase 1) vs an unattended
  `Athanor.Memory.Distiller` process (phase 3, proposal-only) (§9.2).
- **OQ10 — Role scope.** Should workers get `remember`/`recall`, or only conductors? Design says
  "an agent" and D2 argues both; confirm workers are not meant to be read-only (§6.4).
- **OQ11 — `session` scope persistence.** Is `scope: "session"` ever worth persisting, or should it
  stay in-memory only (recommended)? (§4.1)
