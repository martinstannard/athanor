## 1. Scope & Non-goals

### In scope
- New `@moduledoc`-documented modules: `Athanor.Goal` (data + helpers), `Athanor.Verifier`
  (with `Athanor.Verifier.Result`), `Athanor.GoalManager` (one GenServer per goal).
- Three-entity separation: **Worker** = existing `Athanor.Agent` (`role: :worker`) with a new
  `goal_id` binding; **Verifier** = new module + test-only injectable; **Goal Manager** =
  new GenServer.
- Progress receipts written by the worker, observed by the GoalManager (never closing the goal
  itself).
- Timer-driven verify loop, stall detection, PubSub nudges to `"agent:<id>:inbox"`, escalation to
  the Conductor after `max_nudges`.
- Two verifier modes: deterministic shell command and independent peer `Athanor.Agent` session
  (`parent_id: nil`).
- New conductor-facing tools (`set_goal`, `verify_goal`, `goal_status`, `list_goals`) and a
  worker-facing `report_progress` tool.
- New config keys, new supervision children (`Athanor.GoalRegistry`, `Athanor.GoalSupervisor`),
  new PubSub topics.
- Unit + integration tests, faking both LLM (`llm_fn`) and verifier (`verifier_fn`) and using
  short timers.

### Non-goals (explicitly excluded)
- **Not** implementing §7.1 worktrees — but `Athanor.Goal` carries a `cd` so the verifier runs in
  the correct directory (see §2.2 / §10).
- **Not** implementing §7.3 Watchers — but escalation is routed through the same
  `Bus.send_command/2` inbox mechanism a Watcher would use.
- **Not** implementing §7.4 persistence/resume — receipts and goal state stay in memory;
  persistence is flagged as an integration point (**[OPEN]**, §10).
- No changes to the LLM transport (`Athanor.LLM`), TUI input loop, or Daemon RPC surface beyond
  optional thin wrappers.
- No distributed/remote goal manager (single-node only).

## 2. Architecture

### 2.1 New modules

| Module | Kind | Responsibility |
|---|---|---|
| `Athanor.Goal` | struct + pure funcs | Goal definition, status enum, receipt construction, `terminal?/1` guard |
| `Athanor.Goal.Receipt` | struct + pure funcs | Progress receipt (worker → GoalManager) |
| `Athanor.Verifier` | module (pure + a spawn helper) | Runs deterministic checks in `:shell` or `:peer` mode, returns `Athanor.Verifier.Result` |
| `Athanor.Verifier.Result` | struct | Verdict + evidence + timing |
| `Athanor.GoalManager` | `GenServer` | Owns one goal's lifecycle: timer, verifier invocation, nudges, escalation, closure |

### 2.2 Changes to existing modules
- `Athanor.Agent` — add `:goal_id` to its struct/opts; inject the goal objective **and the
  `report_progress` instruction** into the worker system prompt; **suppress**
  `maybe_publish_child_done/2` when `goal_id != nil`, replacing it with a `{:goal_candidate_done, report}`
  event **only when the turn's content carries a parsed `===ATHANOR_DONE===` sentinel** (a plain
  sentinel-less turn must stay silent — see C1/§5.2); parse an optional
  `===ATHANOR_PROGRESS=== summary=<line>` sentinel alongside the existing `parse_done_sentinel/1`
  (see §4.4, **[OPEN]**). If `goal_id != nil` but **no GoalManager is registered** for that goal
  (e.g. the `:temporary` manager crashed), the Agent must **fall back** to the normal
  `{:child_done, report}` path so the conductor still wakes (C8).
- `Athanor.Orchestrator` — reuse `lookup/1`, `list_sessions/0`, `session_output/1`,
  `send_session/2`; add a `goal_worker_id/0`-style id helper only if needed for peer verifiers.
- `Athanor.Tools` — add schemas + `execute/3` clauses for `set_goal`, `verify_goal`,
  `goal_status`, `list_goals`, `report_progress`; extend the "known tool" catch-all clause.
- `Athanor.Bus` — add a goal topic family via one new function `publish_goal_event/3` (see §4.2)
  and reuse `send_command/2` for nudges/escalations.
- `Athanor.Application` — insert two children (see §2.3).
- `Athanor.Config` — add goal config accessors (§8).

### 2.3 Supervision placement (extends design §2)

```text
Athanor.Supervisor (:one_for_one)                              # name: Athanor.Supervisor
├── Athanor.AgentRegistry      (Registry, :unique)             # existing: id -> Agent pid
├── Athanor.PubSub             (Registry, :duplicate)          # existing: topic fan-out
├── Athanor.GoalRegistry       (Registry, :unique)   [NEW]     # {:goal, goal_id} & {:worker, worker_id} -> GoalManager pid
├── Athanor.AgentSupervisor    (DynamicSupervisor)             # existing: Conductor + Worker GenServers
│      ├── Conductor "ops"          (role: :conductor, parent_id: nil)
│      │     ├── Worker "worker-1"  (role: :worker, parent_id: "ops", goal_id: "goal-1")
│      │     └── Worker "worker-2"  (role: :worker, parent_id: "ops")
│      └── Peer Verifier "verifier-…" (role: :worker, parent_id: nil)   # spawned on demand by GoalManager/:peer mode
└── Athanor.GoalSupervisor     (DynamicSupervisor)   [NEW]     # one GoalManager per goal
       ├── GoalManager "goal-1"  (:temporary, registered in GoalRegistry)
       └── GoalManager "goal-2"
```

Ordering rationale: both `Registry` children must start **before** the `DynamicSupervisor` that
registers into them (the existing tree already follows this pattern for `AgentRegistry` ←
`AgentSupervisor`). `GoalRegistry` therefore precedes `GoalSupervisor`.

Restart policy for `GoalManager`: `:temporary` (same as `Athanor.Orchestrator.spawn_session/1`
uses for `Athanor.Agent`: `restart: :temporary`). Rationale: an auto-restarting goal manager could
re-nudge a dead worker in a loop; a lost goal is escalated, not silently restarted. **[OPEN]** —
whether goal state should survive crashes ties to §7.4.

> **Correction (C8):** `:temporary` means a manager crash silently drops the goal *and* — with the
> naive suppression in §2.2 — swallows the worker's completion notification. Two mitigations are
> therefore **mandatory**, not optional: (a) the Agent falls back to `{:child_done}` when no
> manager is registered for its `goal_id`; (b) `GoalManager.terminate/2` publishes a
> `{:goal_failed, reason}` event so a lost goal is at least visible rather than invisible.

> **Correction (C5):** `GoalRegistry` keys `{:goal, goal_id}` **and** `{:worker, worker_id}` must be
> released (`Registry.unregister/2`) on **every** terminal transition (`:closed`, `:escalated`,
> `:failed`, `:cancelled`) and in `terminate/2`, otherwise a second goal on the same worker cannot
> register `{:worker, worker_id}` and `for_worker/1` keeps resolving to a dead manager.

### 2.4 PubSub topics / handlers

| Topic | Publisher | Subscriber | Payload |
|---|---|---|---|
| `"agent:<worker_id>:events"` | `Athanor.Agent` (existing) | `Athanor.GoalManager` **(new subscriber)** | `{:agent_event, worker_id, event}` — receipts, `:turn_complete`, `{:status, _}`, `{:goal_candidate_done, _}` |
| `"agent:<worker_id>:inbox"` | `Athanor.GoalManager` **(new publisher)** | `Athanor.Agent` (existing) | `{:bus_command, {:enqueue_prompt, nudge_text}}` |
| `"agent:<conductor_id>:inbox"` | `Athanor.GoalManager` **(new publisher)** | `Athanor.Agent` (`role: :conductor`) | `{:bus_command, {:enqueue_prompt, escalation_text}}` |
| `"conductor:<conductor_id>:children"` | `Athanor.GoalManager` (via `Bus.publish_event(worker_id, conductor_id, {:child_done, report})`) | Conductor (existing handler) | `{:agent_event, worker_id, {:child_done, report}}` — the **only** path that wakes a conductor when a goal is attached |
| `"conductor:<conductor_id>:goals"` **[NEW]** | `Athanor.GoalManager` (via `Bus.publish_goal_event/3`) | Conductor watchers, tests | `{:goal_event, goal_id, event}` — goal lifecycle mirror (C11); see §4.2 |
| `"deck:events"` | Every `Athanor.Agent` + `Athanor.GoalManager` | `Athanor.TUI`, loggers | `{:agent_event, id, event}` (existing shape) |
| `"goal:<goal_id>:events"` **[NEW]** | `Athanor.GoalManager` | GoalManager watchers, tests | `{:goal_event, goal_id, event}` |

> **Correction (C2/C12):** the GoalManager's subscription to `"agent:<worker_id>:events"` is a
> **firehose** — it also carries every `{:text_delta, chunk}`, and (because
> `Bus.publish_event/3` broadcasts there too) the manager's *own* `{:child_done, report}` echo. Both
> must be explicitly discarded; see the new §4.6.

Key reuse insight: the Conductor's wakeup handler is
`handle_info({:agent_event, _child_id, {:child_done, %{...}}}, %{role: :conductor} = state)` in
`lib/athanor/agent.ex`. By having the **GoalManager** emit `{:child_done, report}` through the
existing `Bus.publish_event(worker_id, parent_id, ...)`, goal closure wakes the conductor via the
*identical, already-tested* code path — no new conductor handler is required.

## 3. Data Structures

### 3.1 `Athanor.Goal`

```elixir
defmodule Athanor.Goal do
  @moduledoc """
  Goal definition for Goal-Driven Autonomy (design §7.2).
  A Goal binds a worker session to a Verifier strategy; only `Athanor.GoalManager`
  may transition the goal to `:closed`, and only after `Athanor.Verifier` succeeds.
  """

  @type verifier_spec ::
          {:shell, String.t()}
          | {:peer, String.t()}
          | [{:shell, String.t()} | {:peer, String.t()}]   # AND-list, all must pass

  @type status :: :pending | :active | :verifying | :closed | :escalated | :failed | :cancelled

  @enforce_keys [:id, :objective, :worker_id, :verifier]
  defstruct [
    :id,
    :title,
    :objective,
    :worker_id,
    :parent_id,          # conductor id (nil for a root/self goal)
    :cd,                 # working dir for shell verification (worktree-aware, §7.1)
    :model,              # model hint used by :peer mode
    verifier: nil,       # MUST be supplied (C3); {:shell, cmd} | {:peer, q} | AND-list
    status: :pending,
    max_nudges: 3,
    stall_after_ms: 60_000,
    verify_interval_ms: 30_000,
    nudge_count: 0,
    verify_attempts: 0,
    receipts: [],        # [Athanor.Goal.Receipt.t()], newest last
    created_at: nil,
    last_progress_at: nil,   # monotonic ms
    closed_at: nil,
    close_evidence: nil
  ]

  @type t :: %__MODULE__{}
end
```

Helpers: `new/1` (builds struct, defaults from `Athanor.Config`), `terminal?/1`
(status in `[:closed, :escalated, :failed, :cancelled]`), `with_receipt/2`.

> **Correction (C3):** there is **no** default verifier. `new/1` raises when `:verifier` is absent
> or `nil`. A silent `{:shell, "mix test"}` default is dangerous: run in the wrong `cd` it passes
> against unrelated code and closes a goal that was never achieved (see §10 risk 11). The only
> permitted fallback is the explicit, opt-in `Athanor.Config.goal_verify_command/0`, and even that
> returns `nil` by default → a goal with no verifier is a usage error, not a passing goal.

### 3.2 Progress receipt

```elixir
defmodule Athanor.Goal.Receipt do
  @moduledoc "A worker-authored, append-only progress receipt (design §7.2 #1)."
  @enforce_keys [:goal_id, :worker_id, :summary]
  defstruct [:goal_id, :worker_id, :summary, :step, :evidence,
             seq: 0, status: :progress, at: nil, source: :tool]

  @type t :: %__MODULE__{}
end
```

`source: :tool | :sentinel` distinguishes the `report_progress` tool call from a parsed
`===ATHANOR_PROGRESS===` sentinel (see §4.4).

### 3.3 Verifier result

```elixir
defmodule Athanor.Verifier.Result do
  @moduledoc "Structured ground-truth outcome returned by Athanor.Verifier."
  @type verdict :: :verified | :contradicted | :inconclusive
  @type mode :: :shell | :peer

  @enforce_keys [:mode, :verdict]
  defstruct [:mode, :verdict, :evidence, :command, :peer_id,
             duration_ms: 0, checked_at: nil]

  @type t :: %__MODULE__{}
end
```

- `:verified` — command exited `0` / peer emitted `===ATHANOR_DONE=== status=ok`.
- `:contradicted` — command exited non-zero / peer emitted `status=fail`.
- `:inconclusive` — timeout, tool error, missing peer, or unparsable peer output (treated as
  *not verified*; never closes a goal).

### 3.4 `Athanor.GoalManager` state

```elixir
defstruct [
  :goal,                 # %Athanor.Goal{}
  :worker_pid,           # pid() | nil
  :timer_ref,            # reference() | nil (Process.send_after)
  :verifier_task,        # {pid(), reference()} | nil  (spawn_monitor)
  :last_verify_at,       # monotonic ms | nil
  :last_verifier_result, # %Athanor.Verifier.Result{} | nil
  :verifier_fn,          # (Goal.t(), keyword() -> {:ok, Result.t()} | {:error, term()})
  :history               # [{monotonic_ms, event}] bounded audit trail
]
```

> **Correction (C2/C12/C4):** the draft carried a `:subscriber` field with no inbound command to
> set it — removed. All GoalManager output goes through PubSub. The manager subscribes **exactly
> once** to `"agent:<worker_id>:events"` in `init/1`: `Bus.subscribe/1` is not idempotent on a
> `:duplicate` registry, and re-registering the same process+key adds extra entries so a single
> broadcast is delivered N times (verified: three `Registry.register/3` calls → three entries).

Non-blocking rule (AGENTS.md + design §1): the verifier runs inside a `spawn_monitor`'d process
that `send/2`s `{:verifier_result, ref, result}` back to the GoalManager — exactly the
`Athanor.Agent.start_llm_turn/1` / `start_tool_execution/2` pattern. The GoalManager's `receive`
loop is never blocked on shell or HTTP.

### 4.2 `Athanor.Bus` additions
```elixir
@doc "Publishes a goal lifecycle event to deck:events and goal:<goal_id>:events."
@spec publish_goal_event(String.t(), String.t() | nil, term()) :: :ok
def publish_goal_event(goal_id, parent_id, event) do
  msg = {:goal_event, goal_id, event}
  broadcast("deck:events", msg)
  broadcast("goal:#{goal_id}:events", msg)
  if is_binary(parent_id), do: broadcast("conductor:#{parent_id}:goals", msg)
  :ok
end
```
Nudges and escalations reuse the existing `Athanor.Bus.send_command/2` verbatim (no new
function), guaranteeing delivery to `"agent:<id>:inbox"` and reuse of the Agent's existing
`{:bus_command, {:enqueue_prompt, text}}` handler.

> **[OPEN]** `publish_goal_event/3` deliberately mirrors `publish_event/3`'s
> `{:agent_event, id, event}` shape as `{:goal_event, goal_id, event}`. Alternative: reuse
> `publish_event/3` with `goal_id` as the "agent id" so the TUI renders goals for free — rejected
> here because the TUI's `ensure_session/3` would treat a goal as a session. Decision needed from
> the Conductor.

### 4.4 Sentinel / receipt encoding
- **Closure** uses the *existing* `===ATHANOR_DONE=== status=ok|fail summary=<line>` sentinel and
  `Athanor.Agent.parse_done_sentinel/1` — no new grammar. A worker's sentinel becomes a **claim**
  (`:goal_candidate_done`), never a closure.
- **Progress** adds one optional sentinel `===ATHANOR_PROGRESS=== summary=<one line>` parsed by a
  new `Athanor.Agent.parse_progress_sentinel/1` (mirroring `parse_done_sentinel/1`'s regex shape)
  so receipts work even if the model omits the `report_progress` tool call. **[OPEN]** — this
  grammar is not in design.md; confirm before implementing.

### 4.5 Nudge / escalation text (concrete)
```
[GOAL NUDGE 1/3] Goal goal-1 ('Ship auth fix') has not reported progress for 62s.
Objective: <objective>
Last receipt: <summary or "none">. Take the next bounded step and call report_progress.
You cannot close this goal — the Verifier must confirm it.
```
```
[GOAL ESCALATED] Goal goal-1 ('Ship auth fix') exceeded max_nudges (3) without verification.
Verifier: shell `mix test` → contradicted. Evidence: <first 400 chars>.
Nudges sent: 3. Last worker status: idle. Requires Conductor/user intervention.
```

### 4.6 Event filtering rules (C2/C12/C4)

The GoalManager's single subscription to `"agent:<worker_id>:events"` receives the whole worker
firehose. It must apply these rules and **ignore everything else** (cheap `case` clauses, no
allocation on the hot path):

| Incoming event | Action |
|---|---|
| `{:text_delta, _}` | **Drop.** High-frequency; the hottest path in the system. |
| `{:status, :streaming \| :executing_tools}` | Record `worker_status` only (no publish). |
| `{:status, :idle \| :error}` | Record `worker_status`; a transition from busy → `:idle`/`:error` is a stall-clock candidate (§5.4). |
| `{:user_message, _}`, `{:tool_start, _}`, `{:tool_end, _}` | **Drop** (or append to `:history` behind a debug flag). |
| `{:turn_complete, content}` with a done sentinel | Treat as `{:goal_candidate_done}` → verify now (§5.2). |
| `{:turn_complete, _}` without a sentinel | Refresh `last_progress_at` only. |
| `{:goal_candidate_done, report}` | Trigger `:force_tick` verification. |
| `{:child_done, _}` | **Drop.** This is the manager's *own* closure echo (C12); acting on it would re-enter the close path. |
| `{:goal_failed, _}` | **Drop.** Another manager's terminal event. |
| `{:DOWN, …}` | Only handle when the ref matches `:verifier_task`. |

> Rationale: without the `{:text_delta}` drop, a single streaming worker would enqueue thousands of
> no-op messages into the manager mailbox per turn. Without the `{:child_done}` drop, closure via
> `Bus.publish_event/3` loops back into the manager that emitted it.

## 5. Behavioral Flow

### 5.1 Goal start
1. Conductor calls tool `set_goal(worker_id, objective, verify, cd?)`.
2. `Athanor.Tools.execute("set_goal", args, opts)` → `Athanor.GoalManager.start_goal(goal, opts)`.
3. `start_goal/2` builds `%Athanor.Goal{}`, `DynamicSupervisor.start_child(Athanor.GoalSupervisor, spec)`
   (spec `%{id: {GoalManager, goal_id}, start: {GoalManager, :start_link, [goal, opts]}, restart: :temporary}`).
4. `GoalManager.init/1` registers in `Athanor.GoalRegistry` under both `{:goal, goal_id}` and
   `{:worker, worker_id}`, subscribes to `"agent:<worker_id>:events"`, sets
   `last_progress_at = monotonic_now`, schedules `Process.send_after(self(), :verify_tick, verify_interval_ms)`.
5. Publishes `{:goal_started, goal}` and (optionally) nudges the worker once to begin.

> **Correction (C10) — ordering.** `set_goal(worker_id, …)` requires the worker to **already exist**
> (the manager validates via `Orchestrator.lookup(worker_id)`, and §5.4 needs a live inbox to nudge).
> A conductor that sets a goal before launching the worker gets `{:error, :worker_not_found}`.
> To remove that footgun, `set_goal` should also accept the combined form
> `set_goal(objective, verify, title?, cd?)` which **launches the worker and the goal atomically**
> (`Orchestrator.launch_subagent/4` → `GoalManager.start_goal/2`) and returns `{worker_id, goal_id}`.
> Both forms are needed: the combined one for the common case, the explicit one for retargeting an
> existing worker. If the worker is launched successfully but `start_goal/2` fails, the tool must
> terminate the just-spawned worker rather than leave an unmanaged orphan.

### 5.2 Worker step
1. Worker (existing `Athanor.Agent`) runs its normal turn loop; `start_llm_turn/1` /
   `start_tool_execution/2` unchanged.
2. Worker tool call `report_progress(summary, step?, evidence?)` → `Athanor.Tools.execute/3` →
   `GoalManager.report_progress(worker_id, receipt)` (resolved via `GoalRegistry`).
3. GoalManager appends the receipt, resets `last_progress_at`, increments `seq`, publishes
   `{:goal_receipt, receipt}`. It does **not** verify on every receipt (avoids `mix test` spam) —
   receipts only reset the stall clock.
4. On a worker `:turn_complete` **whose content parses via `Agent.parse_done_sentinel/1`**,
   `Athanor.Agent` emits `{:goal_candidate_done, report}` **instead of** `{:child_done, …}`; the
   GoalManager treats this as "verify now" (`:force_tick` semantics) but still cannot close on the
   claim alone. A sentinel-less turn emits nothing (C1) — otherwise every conversational turn would
   trigger a verification. If the worker's `goal_id` has **no registered manager**, emit the ordinary
   `{:child_done, report}` instead so the conductor still wakes (C8).

### 5.3 Periodic verify tick
1. `handle_info(:verify_tick, state)`:
   - if `state.verifier_task != nil` → skip this tick (no overlap), reschedule.
   - else spawn the verifier via `state.verifier_fn.(goal, cd: goal.cd, model: goal.model)` inside
     `spawn_monitor`, store `{pid, ref}`, reschedule next tick.
2. On `{:verifier_result, ref, {:ok, %Result{}}}`:
   - `:verified` → **close** (§5.6).
   - `:contradicted` → record; if the worker already claimed done **or** the stall clock expired →
     nudge/escalate (§5.4–5.5).
   - `:inconclusive` → record; treat like `:contradicted` for stall purposes but never close.
3. On `{:DOWN, ref, :process, pid, _}` before a result → synthesize `:inconclusive` (verifier crash)
   and continue.

### 5.4 Stall detection → nudge
```
stalled? =
  goal.status in [:active, :verifying] and
  (monotonic_now - last_progress_at) >= goal.stall_after_ms and
  worker_status in [nil, :idle, :error]
```

> **Correction (C6):** the draft dereferenced `verifier_result.verdict` unguarded. On the first tick
> `last_verifier_result` is `nil`, so `nil.verdict` raises and kills the manager (which, being
> `:temporary`, then loses the goal — C8). Always nil-guard before reading a verdict.

> **Correction (#48):** the `or last_verifier_result.verdict == :contradicted` disjunct was a bug,
> not a feature. It let a *failing* verifier bypass the worker-liveness guard, and for a
> `mix check`-shaped end-state verifier that is the *expected* state from t=0 until the last commit —
> so an actively `:streaming` worker was nudged on every tick and escalated in ~90s. A verdict is
> information about the work, never evidence that the worker is idle. `nudge_count` is also reset by
> demonstrated progress (a `report_progress` receipt, or a completed turn that carried no completion
> sentinel), so the budget counts *consecutive* unproductive ticks rather than lifetime nudges.
- `worker_status` is read through `Athanor.Orchestrator.session_output(worker_id)` (returns
  `%{status: …}`) without blocking: it is a `GenServer.call` into the Agent's own loop, which is
  already async w.r.t. the TUI.
- If stalled and `nudge_count < max_nudges`:
  `Bus.send_command(worker_id, {:goal_nudge, nudge_text})`, `nudge_count + 1`, publish
  `{:goal_nudged, …}`.

> **Correction (#49):** the nudge must **not** go through `{:enqueue_prompt, _}`. That lands in the
> worker's conversational `prompt_queue`, which for a goal-attached session drains only at a *task*
> boundary (`mid_turn_injection?/1` is false whenever `goal_id` is set, #44) — i.e. never while the
> worker is stalled mid-task, which is the only time a nudge is sent. `{:goal_nudge, _}` is consumed
> by `Athanor.Agent` at the next tool-round boundary (or immediately when nothing is in flight), so
> the reminder arrives while the work is still running, and no *user* objective can be injected into
> a goal worker mid-flight (#44's invariant, which is why draining the conversational queue instead
> was rejected). Delivery is reported separately from sending: the agent publishes
> `{:nudge_delivered, _}`, which is what `escalation_text/5` quotes alongside `nudge_count`.
- If the worker's inbox is unreachable (`Orchestrator.lookup(worker_id) == :error`) → escalate
  immediately (nudging a dead process is pointless).

### 5.5 `max_nudges` exceeded → escalate
- When `nudge_count >= max_nudges` and still unverified:
  `Bus.send_command(parent_id, {:enqueue_prompt, escalation_text})` (hits the Conductor's existing
  `{:bus_command, {:enqueue_prompt, text}}` path and its `prompt_queue`), publish
  `{:goal_escalated, …}`, set `status: :escalated`, cancel the verify timer (or back off to a slow
  heartbeat).
- If `parent_id == nil` (root goal) → publish to `deck:events` only and log via `Logger`.

### 5.6 Successful verify → goal closed (and **who** may close)
- **Only `Athanor.GoalManager` closes a goal, and only on a `:verified` verdict *and* the worker's
  own `===ATHANOR_DONE===` claim.** The Worker never closes; the Verifier proposes; the GoalManager
  decides.
- Closure sequence: `status: :closed`, `closed_at`, `close_evidence = result.evidence`, cancel
  timer, **release both `GoalRegistry` keys** (C5), then
  `Bus.publish_event(worker_id, parent_id, {:child_done, report})` with
  `report = %{child_id: worker_id, title:, status: "ok", summary: goal.objective, output: result.evidence}`
  → the Conductor receives `[DONE] Sub-agent '<title>' (<id>) finished: status=ok summary=…`
  through its existing handler.
- Optionally enqueue a terminal system message to the worker
  (`{:enqueue_prompt, "[GOAL CLOSED] Verified by <mode>: <evidence>. Stop and summarise."}`) or
  `Bus.send_command(worker_id, :cancel)`. **[OPEN]** — decide whether closure stops the worker.

> **Correction (C7):** the draft's public `close/2` contradicted "only the GoalManager closes a
> goal". `close/2` is **internal** (`defp`) and reachable only from the verify-result handler, which
> is the sole code path holding a `:verified` result.

> **Correction (#50):** the verdict alone is **not** sufficient. C1 says "a claim is not a verdict";
> this is its mirror — a verdict does not substitute for a claim. A benchmark verifier is polled from
> t=0 and answers "is the tree green *right now*?", so it passes against partial work; closing on it
> alone killed goals mid-implementation and then swallowed the worker's real completion (see
> `Athanor.Agent.maybe_publish_child_done/2`, which must still surface a completion whose goal has
> already resolved). `:verified` with no claim is a distinct state: the result is recorded and the
> manager waits, and it deliberately does **not** enter the stall path — a passing verifier is
> positive evidence, and nudging on it would nag a worker into "finishing" finished work. `verify_now/1` (manual re-verification) is the
> only goal-closing entry point exposed to callers, and it still routes through the Verifier.

> **Correction (C5):** `terminate/2` must also release the keys and publish `{:goal_failed, reason}`
> so a crashed manager neither leaks registry entries nor disappears silently.

## 6. The Two Verifier Modes

```elixir
@spec Athanor.Verifier.verify(Athanor.Goal.t(), keyword()) ::
        {:ok, Athanor.Verifier.Result.t()} | {:error, term()}
```

### 6.1 `:shell` — deterministic ground truth
- Delegates to a **new structured runner** `Athanor.Tools.run_command(command, cd:, timeout:)`
  returning `{:ok, %{output: String.t(), exit_code: integer()}} | {:timeout, output} | {:error, term()}`,
  and refactors the existing `Tools.execute("bash", …)` clause to be a thin adapter over it (its
  public `{:ok, String.t()} | {:error, String.t()}` contract and the two error strings are
  **unchanged** for the Agent-facing tool).
- Mapping:
  `{:ok, %{exit_code: 0}}` → `%Result{mode: :shell, verdict: :verified, command: cmd, evidence: output}`;
  `{:ok, %{exit_code: n}}` → `:contradicted` (exit ≠ 0);
  `{:timeout, _}` → `:inconclusive`;
  `{:error, _}` → `:inconclusive`.
- **Correction (C9):** the draft proposed sniffing the overloaded `bash` error string
  (`"Command timed out after …"` vs `"Command exited with status …"`) to separate `:contradicted`
  from `:inconclusive`. String-sniffing a user-facing message is brittle (any wording change
  silently flips a *failure* into a *no-op retry* loop). The structured runner makes the
  distinction a type-level guarantee and resolves OQ9 in the **safe** direction: a genuine non-zero
  exit can never be mistaken for a timeout.
- Examples: `mix test`, `mix compile --warnings-as-errors`, `gh pr view <n> --json state`,
  `git diff --quiet`.
- **Tradeoffs:** fast, cheap, reproducible, ideal for CI-shaped goals; cannot judge subjective goals
  ("was the README good?"); susceptible to environment flakiness (network, `epmd`, test temp dirs).

### 6.2 `:peer` — independent agent from scratch
- Spawns a **fresh** `Athanor.Agent` with `parent_id: nil` (eligible for
  `Athanor.Orchestrator.spawn_session/1` with `role: :worker`), a distinct `session_id`, and a
  *verifier* system prompt that receives only the goal objective + the verifier instruction (never
  the worker's `messages` — that is the "no shared blind spots" guarantee).
- Pattern (mirrors `Athanor.Tools.await_subagent/2`):
  1. `Bus.subscribe("agent:<peer_id>:events")`
  2. `Orchestrator.spawn_session(id: peer_id, role: :worker, parent_id: nil, register: false, cd: goal.cd, llm_fn: …)`
  3. `Bus.send_command(peer_id, {:prompt, verify_prompt})`
  4. `receive {:agent_event, ^peer_id, {:turn_complete, output}}` with `peer_timeout_ms`
  5. Parse via `Athanor.Agent.parse_done_sentinel(output)` → `ok` ⇒ `:verified`, `fail` ⇒
     `:contradicted`, none/timeout ⇒ `:inconclusive`
  6. Tear down with `Orchestrator.cancel_session(peer_id)` (and optionally
     `DynamicSupervisor.terminate_child/2`).
- **Correction (C13/C15):** spawn the peer **unregistered**. ⚠️ This requires a one-line change to
  `Orchestrator.spawn_session/1` first: it currently does `Keyword.put(:register, true)`, which
  **unconditionally overwrites** a caller-supplied `register: false` (verified at
  `lib/athanor/orchestrator.ex:67`). Change it to `Keyword.put_new(:register, true)` so tests and
  callers can opt out, then pass `register: false` for peers.
  Rationale: registered peers surface in `Orchestrator.list_sessions/0` and as phantom rows in the
  TUI deck, and collide in `AgentRegistry` if a peer id is ever reused. If unregistered spawning
  proves insufficient (e.g. `session_output/1` needs the lookup), the fallback is to register with a
  marker in the registry metadata and filter `role: :verifier` out of `list_sessions/0`.
- **Tradeoffs:** handles fuzzy/subjective goals and can actually *reason* about ground truth; but is
  expensive, slower, non-deterministic, and can share blind spots if it uses the same model/prompt —
  mitigated by a dedicated verifier prompt and (optionally) a stronger/different `model`.

### 6.3 Mode selection
- Chosen **per goal** at `set_goal` time: `verify: "mix test"` (string ⇒ shell),
  `verify: {:peer, "Re-derive that the auth bug is fixed"}`, or
  `verify: [{:shell, "mix test"}, {:peer, "…"}]` (AND — all must pass).
- Fallback: `Athanor.Config.goal_verify_command/0` if `set_goal` omits `verify`.
- `verifier_spec` list semantics: **evaluated in order with short-circuit** — as soon as one element
  returns `:contradicted`, stop and return `:contradicted` (do **not** run the remaining, possibly
  expensive `:peer` checks); all `:verified` ⇒ `:verified`; otherwise `:inconclusive`. Order the
  spec cheapest-first (shell before peer).
- **Correction (C14):** the draft's "any `:contradicted` ⇒ `:contradicted`" reads as evaluate-all,
  which would burn a full peer-verifier session (tokens + latency) on a goal the shell check had
  already refuted. Short-circuiting also makes `:contradicted` dominate a later `:inconclusive`.
- **Correction (C3):** "fallback: `Config.goal_verify_command/0` if `set_goal` omits `verify`" is
  only valid when that config value is non-`nil` (its default is `nil`). Otherwise the goal build
  raises — there is no silent `mix test` default.

## 10. Risks, Edge Cases & Open Questions

### Risks / edge cases
1. **Nudge dropped (fire-and-forget PubSub).** `Bus.broadcast/2` does `Registry.dispatch` + `send`;
   it is fire-and-forget and will silently drop if the worker is not subscribed or is dead.
   Mitigations: (a) increment `nudge_count` *before* sending; (b) `Orchestrator.lookup(worker_id)`
   check — dead worker ⇒ skip nudging, escalate immediately; (c) require a receipt or tick change to
   consider a nudge "effective"; (d) after `max_nudges` regardless of effect, escalate.
2. **Worker already busy.** `Bus.send_command(worker_id, {:enqueue_prompt, …})` maps to
   `Athanor.Agent.handle_info({:bus_command, {:enqueue_prompt, text}}, state)` → `do_enqueue_prompt/2`,
   which queues into `prompt_queue` while `:streaming | :executing_tools` and drains in
   `drain_prompt_queue/1`. Safe, **but** the queue is unbounded — hence the hard `max_nudges` cap.
   If the worker is `:error`, the nudge starts a fresh turn (`do_enqueue_prompt/2` clause for `[:idle, :error]`).
   Since #44 the general queue *also* drains one prompt mid-round (`drain_one_queued_prompt/1`), but a
   goal-attached worker — precisely the session this section is about — is exempt, so a nudge still
   waits for the task boundary and cannot rewrite the worker's target under a running verification.
3. **Verifier flakes.** Shell timeouts → `:inconclusive` (never closes); retry up to `max_nudges`
   ticks with backoff, then escalate rather than loop forever. Peer verifier unparsable output →
   `:inconclusive`.
4. **Verifier crash.** `spawn_monitor` + `{:DOWN, …}` → synthesize `:inconclusive`, clear
   `verifier_task`, continue; never leave the GoalManager wedged on a dead verifier.
5. **Timer / clock drift.** Use `System.monotonic_time(:millisecond)` for intervals and stall math
   (never `DateTime`); monotonic time is immune to NTP/DST jumps and to VM suspend gaps (which merely
   delay, never reorder, `Process.send_after`). `Process.send_after/3` fires late-but-once. Reschedule
   after each tick rather than using a fixed-period timer to avoid pile-up.
6. **Overlapping verification / double close.** Guard on `verifier_task != nil`; make `close/2`
   idempotent and only honour it when `last_verifier_result.verdict == :verified`.
7. **False closure regression.** Highest-severity risk: a goal-attached worker emitting
   `===ATHANOR_DONE===` must **not** wake the conductor. The suppression branch in
   `maybe_publish_child_done/2` is the critical invariant and needs a dedicated regression test.
8. **Conductor gone.** `Orchestrator.lookup(parent_id) == :error` ⇒ log + `publish_goal_event` only;
   don't crash the GoalManager.
9. **GoalManager crash (C8).** `:temporary` ⇒ no auto-restart; in-memory receipts are lost. **Not
   merely "acceptable"**: with naive `child_done` suppression it also swallows the worker's
   completion. Mitigations are now mandatory: Agent-side `{:child_done}` fallback when no manager is
   registered for the `goal_id`, plus `terminate/2` publishing `{:goal_failed, reason}`. Persistence
   is §7.4.
10. **`Tools.execute("bash", …)` overloaded error contract.** Timeout and non-zero exit both arrive
    as `{:error, String.t()}`; distinguishing `:contradicted` from `:inconclusive` needs either
    message sniffing (brittle) or a new structured helper. Flagged.
11. **Interaction with §7.1 (Worktrees).** Verification must run in the worker's isolated worktree
    (`goal.cd`), not the main checkout — otherwise `mix test` passes against unrelated code. Planning
    hook only; no worktree logic here.
12. **Interaction with §7.3 (Watchers).** A heartbeat/GitHub watcher is the natural *third* escalation
    sink ("doorbells, not messengers"). The escalation path is deliberately just `Bus.send_command/2`,
    so a Watcher can subscribe to `"goal:<gid>:events"` or receive the conductor inbox message with
    zero new plumbing.
13. **Interaction with §7.4 (Store/Resume).** `receipts`, `goal.status`, and `close_evidence` are
    exactly the state that should land in `transcript.jsonl` / `HANDOFF.md`; on resume, a `:verifying`
    goal must be re-created (or marked `:failed`) rather than silently trusted.
14. **Peer-verifier independence.** Same model + same prompt ⇒ same blind spots. Mitigation: dedicated
    verifier system prompt + `goal.peer_model` override; must be documented as a heuristic, not a
    guarantee.

### Open questions (require Conductor/user decision before coding)
- **OQ1 — Receipt mechanism.** `report_progress` tool, `===ATHANOR_PROGRESS===` sentinel, or both?
  design.md says "writes progress receipts" without a grammar.
- **OQ2 — GoalManager cardinality.** One GenServer per goal (proposed) vs. one global manager
  supervising many goals. The doc says "`Athanor.GoalManager` GenServer" (singular) — possibly a
  single instance per worker, or a single registry-style manager.
- **OQ3 — Does closure stop the worker?** After verification, cancel the worker, or leave it alive
  for follow-ups?
- **OQ4 — Goal event shape.** `{:goal_event, goal_id, event}` on new topics vs. reusing
  `Bus.publish_event/3` with `goal_id` as the agent id so the TUI renders goals for free.
- **OQ5 — Who may call `set_goal`?** Conductors only, TUI, or also a worker self-assigning a goal?
- **OQ6 — `publish_goal_event/3` parent topic name** (`"conductor:<id>:goals"`) is invented here; is it
  wanted, or should escalations/verifications go only through `"conductor:<id>:children"`?
- **OQ7 — Persistence.** Should receipts/goal state survive VM restart now (partial §7.4) or be
  strictly in-memory for this phase?
- **OQ8 — Config location.** Introduce `config/config.exs`, or continue the `Athanor.Config`
  module-attribute + env-var idiom?
- **OQ9 — Structured bash result. _Resolved (C9):_** yes — add `Athanor.Tools.run_command/2` returning
  `{:ok, %{output, exit_code}} | {:timeout, output} | {:error, reason}` and re-implement the existing
  `"bash"` tool as an adapter over it. The Agent-facing `{:ok, String.t()} | {:error, String.t()}`
  contract and both error strings stay byte-identical, so no existing test or prompt changes.
- **OQ10 — `set_goal` shape.** Combined `set_goal(objective, verify, title?)` (spawns worker + goal)
  vs. explicit `set_goal(worker_id, objective, verify)` (retargets existing). Recommendation: ship
  **both** (C10); the combined form is the common case and removes the "worker must pre-exist"
  footgun.

## 11. Suggested Incremental Milestones (each ends green)

**M1 — Data + Verifier, no processes.**
Add `Athanor.Goal`, `Athanor.Goal.Receipt`, `Athanor.Verifier`, `Athanor.Verifier.Result`, and
`Athanor.Tools.run_command/2` (refactoring the existing `"bash"` clause onto it, **C9**) + shell-mode
tests. No supervision-tree changes → zero risk to existing tests, and the legacy `bash` tests must
stay green byte-for-byte.

**M2 — Supervision + GoalManager skeleton.**
Add `Athanor.GoalRegistry` + `Athanor.GoalSupervisor` to `Athanor.Application`; add
`Athanor.Bus.publish_goal_event/3`; implement `GoalManager.start_goal/1,2`, `init/1` (register both
keys, subscribe **once**, **C4**), the `:verify_tick` reschedule loop with the **nil-guarded** stall
check (**C6**), the **firehose filter** (**C2/C12**), `status/1`, `cancel/1`, `list_goals/0`,
`for_worker/1` — with a no-op verifier `verifier_fn`. Include key release on terminal transitions and

**M3 — Wire the Verifier + closure path.**

`Bus.publish_event(worker_id, parent_id, …)`. Add `verify_now/1` and the **internal** `close/2`

**M4 — Worker integration + trust-but-verify invariant.**
Add `:goal_id` to `Athanor.Agent`; suppress `maybe_publish_child_done/2` for goal-attached workers and

`{:child_done}` **fallback** when no manager is registered (**C8**); add the `report_progress`
worker-only tool + optional `===ATHANOR_PROGRESS===` parser; add the regression test proving a
worker's `===ATHANOR_DONE===` does **not** wake the conductor, plus the sentinel-less-turn and
no-manager-fallback tests. This is the correctness heart of §7.2.

**M5 — Stall detection, nudges, escalation.**
