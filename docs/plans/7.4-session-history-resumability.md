# Implementation Plan — §7.4 Session History, Resumability & Context Compaction (`Athanor.Store`)

**Status: proposed — not yet implemented.**

> Planning artefact only. All module/function names below were verified against the current tree
> (`lib/athanor/{agent,orchestrator,tools,bus,application,config,llm,tui,daemon}.ex`,
> `lib/mix/tasks/athanor{,.daemon}.ex`, `test/athanor/*`). Anything not derivable from the code is
> marked **[OPEN]**. Every name prefixed `Athanor.Store.*` is **proposed** and does not exist today.

## 0. Review pass (corrections already applied)

A critical read of the first draft surfaced defects that would have shipped data loss or corrupt
history. They are fixed inline below; this table indexes them.

| # | Defect | Fix |
|---|---|---|
| C1 | Reconstructing `transcript.jsonl` from the existing `"deck:events"` firehose is **lossy**: `{:tool_start, name, raw_args}` carries the tool *name and args* but **never the `tool_call.id`**, and intermediate assistant messages (the ones carrying `tool_calls`) are **never emitted at all** — only the terminal no-tool-call turn emits `{:turn_complete, _}` (`lib/athanor/agent.ex`). So the persisted history could not be replayed into a valid OpenAI message array. | The `Athanor.Agent` publishes the **exact message maps** it appends (§4.2, §5.1), not a reconstructed approximation. |
| C2 | Naïvely persisting every `"deck:events"` event would log one line **per `{:text_delta, chunk}` token** (thousands per turn) — file explosion, and redundant with the final assembled message. | `{:text_delta, _}` is **never** persisted; the assistant message is recorded **once**, at append time (§4.4, §5.1). |
| C3 | `Athanor.Agent.init/1` unconditionally sets `messages: [%{role: "system", …}]`. A resumed session would therefore come up with an **empty** history — the entire point of §7.4. | Add a `:messages` opt to `init/1` that **pre-seeds** the working set; the system message is **re-derived** (never persisted — see C13). |
| C4 | `Agent.get_state/1` and `snapshot_meta/1` **omit `:session_id`** (the OpenCode Go `x-opencode-session` id). The design requires it in `meta.json`, but no runtime surface exposes it, so it cannot be persisted from the live process. | Expose `session_id` in both `get_state/1` and `snapshot_meta/1` (§2.2, M1). |
| C5 | Naïve compaction cutting "the oldest N messages" can split an `assistant` message carrying `tool_calls` from its paired `role: "tool"` result messages → the next LLM call 400s ("tool_call_id has no matching tool_call"). | Compaction cuts **only at `user` message boundaries** (§5.4), so tool-call/result pairs are never separated. |
| C6 | Writing `meta.json` with `File.write/2` is not atomic; a crash mid-write leaves unparseable JSON and the whole session unloadable. | `meta.json`/`HANDOFF.md` are written **tmp + `datasync` + atomic `File.rename/2`** (§5.2). |
| C7 | A crash mid-`IO.write` leaves a **truncated trailing JSONL line**. Treating that as corruption would drop an otherwise-good transcript. | The reader treats a malformed **final, newline-less** line as a tolerated `{:truncated, _}` and parses every complete line before it (§5.2). |
| C8 | Resuming children before their parents means a resumed child's `notify_parent_on_done` / conductor inbox targets an **unstarted** pid, and `list_sessions/0` ordering drifts. | Rehydration is **topologically ordered, parents strictly before children** (§5.3). |
| C9 | `Orchestrator.spawn_session/1` does `Keyword.put(:register, true)` (verified `lib/athanor/orchestrator.ex:67`), so a resume that needs an unregistered session (peer verifiers, §7.2) cannot opt out — the same defect §7.2 logged as C15. | Change to `Keyword.put_new/3` before resume re-creates unregistered sessions (§7.1 M3). |
| C10 | `~/.athanor` has **no single-writer lock**. Two daemons (§7.7) or a daemon + a foreground VM writing the same session dirs corrupt each other. | Document single-owner assumption + optional `flock`; flagged risk + **[OPEN]** (§10). |
| C11 | Compaction needs a token count, but the LLM client **discards provider `usage`** (the SSE parser only accumulates `delta` content/tool-calls — `lib/athanor/llm.ex`). | Ship a heuristic estimator first; capturing `usage` is an **[OPEN]** (§5.5). |
| C12 | A session persisted with `last_status: "streaming"` cannot resume its in-flight LLM stream / tool task (`current_task` is not persisted). | Resume **neutralises** status to `:idle` with `current_task: nil`, and records a `resume` marker (§5.3). |
| C13 | Persisting the `system` message AND re-deriving it on resume produces **two** system messages (or a stale prompt if the default prompt changed). | The `system` message is **excluded** from `transcript.jsonl`; it is always regenerated from role/opts (§3.1, §3.2). |

## 1. Scope & Non-goals

### In scope
- New `@moduledoc`-documented modules: `Athanor.Store` (facade + versioning), `Athanor.Store.Session`
  (meta struct/schema), `Athanor.Store.Transcript` (append-only JSONL), `Athanor.Store.Handoff`
  (rolling `HANDOFF.md`), `Athanor.Store.Compactor` (compaction policy + algorithm),
  `Athanor.Store.Tokens` (token accounting), `Athanor.Store.Recorder` (the PubSub→disk writer
  GenServer).
- Append-only per-session directories under `~/.athanor/sessions/<id>/` holding `meta.json`,
  `transcript.jsonl`, and `HANDOFF.md`.
- A **write path**: `Athanor.Agent` publishes exact message maps; `Athanor.Store.Recorder` persists
  them (fsync + atomic metadata).
- **Seamless resume**: `mix athanor --resume` / `/resume <id>` → `Athanor.Orchestrator` rehydrates
  the Conductor + child sub-agent tree (parents before children) and the TUI viewport, restoring
  each `Athanor.Agent`'s `messages` working set.
- **Context compaction**: when a Conductor nears its token budget, older transcript turns are folded
  into `HANDOFF.md` and the in-memory working set is shrunk while recent turns stay intact.
- On-disk **versioning/migration**, crash-safety, a testing strategy (temp dirs + simulated
  crashes), a phased rollout, and a file-by-file change list.

### Non-goals (explicitly excluded)
- **Not** implementing §7.5 Memory (`remember`/`recall`, `.athanor/MEMORY.md`, global memory). Store
  persists *transcripts*; Memory curates *durable facts*. `HANDOFF.md` is deliberately session-local
  and is a candidate input to Memory later, not part of it.
- **Not** implementing §7.7 attach/detach or the daemon lifecycle; Store only adds a resume entry
  point the daemon *calls*. Multi-client mirroring stays out of scope.
- **Not** implementing §7.2 Goal state persistence directly — but the goal lifecycle events on
  `"deck:events"` are recorded as `kind: "event"` records so a future `GoalManager` can rehydrate
  (§10 risk 13).
- **Not** encrypting or redacting transcript contents in v1. Tool outputs may contain secrets; the
  file inherits normal `~` permissions (§10 risk 5).
- **Not** a database. No indexes beyond a directory scan (an optional root `index.json` is flagged
  **[OPEN]**). No cross-node replication (§7.8) — single-owner assumption (§10 risk 1).
- No distributed/remote Store; no remote `:erpc` surface beyond the thin wrappers in §6.3.

## 2. Architecture

### 2.1 New modules

| Module | Kind | Responsibility |
|---|---|---|
| `Athanor.Store` | facade (pure + config) | Root path resolution, session-dir layout, `load/1`, `list/1`, `delete/1`, version check/migration dispatch |
| `Athanor.Store.Session` | struct + pure funcs | `meta.json` schema ↔ `%Session{}`; `new/1`, `to_map/1`, `from_map/1` |
| `Athanor.Store.Transcript` | IO module | Append/read JSONL records; truncation-tolerant reader; record encoding |
| `Athanor.Store.Handoff` | pure | Render/parse the rolling `HANDOFF.md` from session state + records |
| `Athanor.Store.Compactor` | pure | Decide what to keep/drop, build the summary, emit a new `messages` list (C5) |
| `Athanor.Store.Tokens` | pure | Heuristic token estimation for a message list (C11) |
| `Athanor.Store.Recorder` | `GenServer` (`:permanent`) | Subscribes to `"deck:events"`, owns per-session append handles, writes transcripts + atomically updates meta/HANDOFF |

### 2.2 Changes to existing modules
- `Athanor.Agent` —
  - Accept `:messages` (pre-seed) and `:resume` opts in `init/1`; when `:messages` is supplied, use
    it instead of the default `[system]` list (C3), always prepending the freshly derived system
    message.
  - Refactor the three append sites (`begin_user_turn/2`, `{:llm_result, {:ok, msg}}`,
    `{:tools_result, msgs}`) through a single private `record_messages/2` helper that appends **and**
    publishes `{:message, msg}` (C1) — one choke point, no missed sites.
  - Expose `session_id` (and `turn_count`) in `get_state/1` and `snapshot_meta/1` (C4).
  - Optional self-compaction trigger after `{:turn_complete, _}` (§5.4), publishing a
    `{:compaction, summary}` event.
- `Athanor.Orchestrator` — add `resume_session/1,2`, `resume_all/1` (§5.3); change
  `Keyword.put(:register, true)` → `Keyword.put_new/3` (C9). Reuse `spawn_session/1`,
  `lookup/1`, `list_sessions/0`, `session_output/1` unchanged for the restore itself.
- `Athanor.Bus` — add `publish_message/3` (broadcasts `{:message, id, msg}`) and
  `publish_transcript_event/3` (or fold both into `publish_event/3` with new event shapes). See §4.2.
- `Athanor.Application` — insert one child `{Athanor.Store.Recorder, []}` (see §2.3).
- `Athanor.Config` — add Store accessors (§8).
- `Athanor.TUI` — add a `/resume <id>` slash command (`handle_key/2` clause + `loop/2` branch) and
  reuse the **existing** `TUI.hydrate_sessions/2` + `Daemon.messages_to_tui_entries/1` for viewport
  restore (no new rendering code).
- `Athanor.Daemon` — add `resume_session/2`, `resume_all/2` `:erpc` wrappers and route
  `ensure_main_conductor_and_hydrate/2` through resume when requested.
- `Mix.Tasks.Athanor` — parse `--resume` / `--session <id>` and pass through to the TUI/daemon
  (§3.4, M4).

### 2.3 Supervision placement (extends design §2)

```text
Athanor.Supervisor (:one_for_one)                              # name: Athanor.Supervisor
├── Athanor.AgentRegistry      (Registry, :unique)             # existing
├── Athanor.PubSub             (Registry, :duplicate)          # existing
├── Athanor.AgentSupervisor    (DynamicSupervisor)             # existing: Conductor + Worker GenServers
├── Athanor.Store.Recorder     (GenServer, :permanent) [NEW]   # single writer; subscribes "deck:events"
└── … (any future watcher/goal children from §7.2/§7.3)        # unrelated to Store

# Resumed sessions are ordinary Athanor.Agent children under Athanor.AgentSupervisor,
# re-created by Athanor.Orchestrator.resume_* (no new supervisor):
Athanor.AgentSupervisor
├── Conductor "ops"        (role: :conductor, parent_id: nil,  messages: <rehydrated>)
│     ├── Worker "worker-1" (role: :worker, parent_id: "ops",  messages: <rehydrated>)
│     └── Worker "worker-2" (role: :worker, parent_id: "ops",  messages: <rehydrated>)
```

Ordering rationale: `Recorder` needs `Athanor.PubSub` up to subscribe, and needs nothing else; place
it **last** so every other subsystem can publish before it is listening (the singleton is tolerant of
a Session whose `meta.json` does not yet exist — it creates it lazily on first record). Its restart
policy is `:permanent` (unlike `Athanor.Agent`'s `:temporary`): a crashed Recorder **must** come back
or persistence silently stops; on restart it re-subscribes and lazily re-opens per-session handles.

> **Correction (C10 / single-writer):** `Recorder` is a **singleton per node**. It is the only
> process that writes `~/.athanor/sessions/**`. This is what makes append ordering trivially safe
> (one writer per file) and is why we do **not** have each `Athanor.Agent` write its own file.

### 2.4 PubSub topics / handlers

| Topic | Publisher | Subscriber | Payload |
|---|---|---|---|
| `"deck:events"` | Every `Athanor.Agent` (existing) | `Athanor.TUI`, loggers, **`Athanor.Store.Recorder` (new)** | `{:agent_event, id, event}` (existing shape) |
| `"deck:events"` | Every `Athanor.Agent` | `Athanor.Store.Recorder` | `{:message, id, msg}` **[NEW]** — the exact message map appended to `state.messages` (C1) |
| `"agent:<id>:events"` | Every `Athanor.Agent` (existing) | Blocking waiters, targeted watchers | `{:agent_event, id, event}` (unchanged) |
| `"conductor:<id>:children"` | Child `Athanor.Agent`s (existing) | Parent Conductor | `{:agent_event, child_id, {:child_done, report}}` (unchanged) |

Rationale for reusing `"deck:events"`: `Athanor.Bus.subscribe/1` registers on a `:duplicate` Registry
keyed by an **exact** topic string — there is **no wildcard subscription** (`Registry` topics are not
glob patterns). A per-session `"session:<id>:transcript"` topic would therefore force the Recorder to
subscribe/unsubscribe on every `{:session_started, _}` / death, which is more moving parts for no
gain. The Recorder instead subscribes **exactly once** to `"deck:events"` and filters (§4.4). The TUI
already ignores unknown events (`handle_agent_event/3` ends in `_other -> tui`), so `{:message, _}`
is inert for it.

> **Correction (C-dup):** per the §7.2 finding (C4), `Bus.subscribe/1` is **not idempotent** on a
> `:duplicate` registry — subscribing the same process+key twice yields duplicate entries and every
> broadcast is delivered twice (⇒ every record written twice). `Recorder.init/1` must subscribe
> **exactly once**.

## 3. Data Structures & On-disk Schemas

### 3.1 The in-memory history we must persist (ground truth)

This is the exact shape the plan must round-trip. It lives today **only** in the GenServer state
field `:messages` of `%Athanor.Agent{}` (`lib/athanor/agent.ex`), as a plain, append-only list
(`state.messages ++ [msg]`). It is read out via `Agent.get_state/1` (returns the `messages` key) and
`Orchestrator.session_output/1`; the daemon forwards it in `Daemon.fetch_full_sessions/1`, and the
TUI rebuilds its viewport from it with `Daemon.messages_to_tui_entries/1`.

| Message | Map shape (verified in `agent.ex` + `llm.ex`) | Persisted? |
|---|---|---|
| system | `%{role: "system", content: String.trim(system_prompt)}` | **No** — re-derived on resume (C13) |
| user | `%{role: "user", content: text}` | Yes |
| assistant | `%{role: "assistant", content: content, tool_calls: [%{id: id, type: "function", function: %{name: name, arguments: json_string}}]}` — `tool_calls` is always present, possibly `[]` | Yes |
| tool | `%{role: "tool", tool_call_id: id, content: output}` | Yes |

Notes that constrain the design:
- Assistant messages are produced by `Athanor.LLM.finalize_message/1`; `arguments` is a **JSON string**,
  not a map. Round-trip must preserve it as a string (do not decode/re-encode, or whitespace/key order
  can change and break nothing functionally but is noisy in diffs).
- Terminal assistant turns also emit `{:turn_complete, content}` where `content` equals the assistant
  message's `content`. We persist **either** the message **or** the event, never both (C13 dedupe).
- `turn_count` and `current_task` are **not** persisted; `turn_count` restarts at 0 on resume.

### 3.2 `Athanor.Store.Session`

```elixir
defmodule Athanor.Store.Session do
  @moduledoc "meta.json schema for a persisted Athanor session (design §7.4)."
  @enforce_keys [:id, :role]
  defstruct [
    :id,                 # Athanor session id (also the directory name)
    :title,
    :role,               # :conductor | :worker
    :parent_id,          # conductor id, or nil
    :model,
    :cd,
    :opencode_session_id,# OpenCode Go "x-opencode-session" (Agent.session_id)
    :created_at,         # DateTime (ISO8601 string on disk)
    :updated_at,
    :last_status,        # :idle | :streaming | :executing_tools | :error
    :turn_count,
    :child_ids,          # [String.t()] convenience index
    :compaction,         # %{count: n, last_at: DateTime.t(), transcript_bytes: n}
    version: 1
  ]
  @type t :: %__MODULE__{}
end
```

`new/1` derives defaults from `Athanor.Config`; `to_map/1`/`from_map/1` mirror
`Athanor.Agent.snapshot_meta/1`'s field names where they overlap so the `{:session_started, meta}`
event can be persisted with no translation layer.

### 3.3 On-disk layout

```text
~/.athanor/                                   # root: ~/.athanor, override ATHANOR_HOME
├── sessions/
│   ├── conductor-main/
│   │   ├── meta.json          # atomic-write (tmp + datasync + rename); versioned
│   │   ├── transcript.jsonl   # append-only JSON Lines, one record per line
│   │   └── HANDOFF.md         # rolling structured summary (atomic-write)
│   └── worker-1/
│       ├── meta.json
│       ├── transcript.jsonl
│       └── HANDOFF.md
└── sessions/index.json        # OPTIONAL root index (id → parent_id, role, updated_at) [OPEN]
```

- `File.mkdir_p` the session dir before its first write; write `meta.json` **before** the first
  transcript record so a directory is never "transcript without metadata".
- Directory name = **Athanor** session id (`state.id`). The OpenCode Go id is a **field** inside
  `meta.json` (design §7.4 calls that field `session_id`; see naming **[OPEN]** §8 note).

**`transcript.jsonl` record envelope** (one JSON object per line):

```json
{"v":1,"seq":7,"ts":"2026-01-01T12:00:03.123Z","session_id":"worker-1","kind":"assistant","payload":{"role":"assistant","content":"","tool_calls":[{"id":"call_1","type":"function","function":{"name":"read_file","arguments":"{\"path\":\"mix.exs\"}"}}]}}
```

| Field | Meaning |
|---|---|
| `v` | record schema version (C-version, §3.5) |
| `seq` | per-session monotonic integer assigned by the Recorder on arrival |
| `ts` | `DateTime.utc_now()` ISO8601 (human-readable; **not** used for maths) |
| `session_id` | Athanor session id (redundant with the dir, but makes a record self-describing if files are concatenated) |
| `kind` | `"user" \| "assistant" \| "tool" \| "status" \| "event" \| "compaction" \| "resume" \| "checkpoint"` |
| `payload` | for `user/assistant/tool`: the **exact message map** (C1); for `status`: `%{"status": "…"}`; for `event`: `%{"event": "…", "data": …}` |

`kind` covers the design's four mandated record types: `user` = user prompt, `assistant` = assistant
response **and** tool call (the `tool_calls` array), `tool` = tool output. `status`/`event`/`resume`/
`compaction` are audit records (§4.3).

**`meta.json`**:

```json
{
  "version": 1,
  "id": "worker-1",
  "title": "Audit Worker",
  "role": "worker",
  "parent_id": "conductor-main",
  "model": "deepseek-v4.1-flash",
  "cd": "/home/me/project",
  "session_id": "ses_athanor_ab12cd34ef56",
  "created_at": "2026-01-01T12:00:00.000Z",
  "updated_at": "2026-01-01T12:05:00.000Z",
  "last_status": "idle",
  "turn_count": 3,
  "child_ids": ["worker-2"],
  "compaction": {"count": 1, "last_at": "2026-01-01T12:04:50.000Z", "transcript_bytes": 48211}
}
```

### 3.4 `HANDOFF.md` schema (rolling structured summary)

Rendered by `Athanor.Store.Handoff.render/2`, parsed back by `Handoff.parse/1` into a map, and
injected into the LLM as a single summary message by the Compactor (§5.4).

```markdown
# Handoff — Audit Worker (worker-1)
<!-- athanor-handoff v1 -->
- role: worker
- parent_id: conductor-main
- model: deepseek-v4.1-flash
- cd: /home/me/project
- opencode_session: ses_athanor_ab12cd34ef56
- updated_at: 2026-01-01T12:04:50.000Z

## Goal
Audit all files under lib/ and report the Elixir version.

## Completed steps
- [x] read_file("mix.exs") → elixir ~> 1.19
- [x] bash("mix test") → 42 tests, 0 failures

## Open blockers
- none

## Active sub-agents
| id | title | status | last summary |
|---|---|---|---|
| worker-2 | Docs audit | idle | README checked |

## Files touched
- mix.exs (read)

## Compaction log
- 2026-01-01T12:04:50.000Z: compacted 18 messages → kept 6 (summary sha256=9f2c…)
```

The `<!-- athanor-handoff v1 -->` sentinel gives `parse/1` a version anchor (same policy as §3.5).
`Handoff.to_summary_text/1` flattens the structured sections into a compact prose blob for LLM
injection (the LLM gets text, not a Markdown table).

### 3.5 Versioning

- Two independent version numbers: `meta.json#"version"`, and `transcript.jsonl` record `"v"`; plus
  the `HANDOFF.md` HTML-comment sentinel. Today all are `1`.
- `Athanor.Store.check_version/1` and a `Athanor.Store.Schema.migrate/1` dispatch table
  (`@migrations %{1 => &migrate_1_to_2/1}`) own upgrades.
- **Reader policy**: parse records with `v <= current`; **skip** records with unknown **fields**;
  on `v > current` (§3.5 forward-compat) or a malformed `meta.json`, return
  `{:error, {:unsupported_version, n}}` / `{:error, :corrupt}` and **skip that session** rather than
  crashing the resume sweep (§5.3, §9.4).

## 4. Message & PubSub Protocol

### 4.1 What gets persisted, and on which event

| Source event (`"deck:events"`) | Record written | Notes |
|---|---|---|
| `{:session_started, meta}` | create dir + `meta.json` (no transcript record) | meta from `snapshot_meta/1` (+`session_id`, C4) |
| `{:message, %{role: "user"} = m}` | `kind: "user"` | published from `begin_user_turn/2` |
| `{:message, %{role: "assistant"} = m}` | `kind: "assistant"` | includes `tool_calls` (C1) |
| `{:message, %{role: "tool"} = m}` | `kind: "tool"` | includes `tool_call_id` (C1) |
| `{:status, status}` | update `meta.json#last_status` (+ `kind: "status"` audit) | debounced atomic write |
| `{:error, reason}` / `:cancelled` | `kind: "event"` | audit + `last_status: "error"` |
| `{:child_done, report}` | `kind: "event"` | also feeds `HANDOFF.md` "Active sub-agents" |
| `{:compaction, summary}` | `kind: "compaction"` | §5.4 |
| `{:turn_complete, _}` | **nothing** | redundant with the assistant message (C13) |
| `{:text_delta, _}`, `{:tool_start, _}`, `{:tool_end, _}`, `{:user_message, _}` | **nothing** | derivable / high-frequency (C2) |

> **Correction (C1/C13):** the `{:message, msg}` event is the load-bearing new event. Without it the
> transcript cannot be replayed into a valid LLM message array (missing `tool_call.id` on
> intermediate assistant turns) and `{:turn_complete, content}` would double-count the final assistant
> text. `{:tool_start}`/`{:tool_end}` remain TUI-only activity events.

### 4.2 `Athanor.Bus` additions

```elixir
@doc """
Publishes an exact appended message map to `"deck:events"` as `{:message, agent_id, msg}`.
Used by `Athanor.Store.Recorder` to persist the true conversation history (design §7.4, C1).
"""
@spec publish_message(String.t(), String.t() | nil, map()) :: :ok
def publish_message(agent_id, parent_id, msg) when is_binary(agent_id) do
  broadcast("deck:events", {:message, agent_id, msg})
  _ = parent_id   # kept for signature symmetry with publish_event/3; not routed to children
  :ok
end
```

`publish_message/3` mirrors `publish_event/3`'s shape exactly (same `{:…, id, payload}` tuple, same
single broadcast), so it needs no new topic and no new subscription. `status`/`event` records reuse
the **existing** `publish_event/3` (they are already on the wire as `{:agent_event, id, {:status, _}}`
etc.). The `{:compaction, _}` and `{:resume, _}` events likewise ride the existing `publish_event/3`.

### 4.3 Event catalogue (persisted subset)

| Event | Channel | Record / effect |
|---|---|---|
| `{:session_started, meta}` | `deck:events` (existing) | create session dir + `meta.json` |
| `{:message, msg}` **[NEW]** | `deck:events` | `user`/`assistant`/`tool` record (C1) |
| `{:status, s}` | `deck:events` (existing) | `meta.json#last_status` update (debounced) |
| `{:error, reason}` | `deck:events` (existing) | `kind: "event"` + `last_status: "error"` |
| `:cancelled` | `deck:events` (existing) | `kind: "event"` |
| `{:child_done, report}` | `deck:events` (existing) | `kind: "event"` + HANDOFF sub-agent row |
| `{:compaction, %{summary, kept, dropped}}` **[NEW]** | `deck:events` | `kind: "compaction"` + `HANDOFF.md` rewrite |
| `{:resume, %{from: version}}` **[NEW]** | `deck:events` | `kind: "resume"` marker (C12) |

### 4.4 Recorder filtering rules

The Recorder receives the whole `"deck:events"` firehose. It must filter with cheap `case` clauses and
**ignore everything else**:

| Incoming | Action |
|---|---|
| `{:message, id, %{role: "system"}}` | **Drop** (system never persisted, C13) |
| `{:message, id, %{role: r}}` where `r in ["user","assistant","tool"]` | append record |
| `{:text_delta, _}`, `{:tool_start, _}`, `{:tool_end, _}`, `{:user_message, _}`, `{:turn_complete, _}` | **Drop** (C2/C13) |
| `{:session_started, meta}` | ensure dir + meta (idempotent) |
| `{:status, _}`, `{:error, _}`, `:cancelled`, `{:child_done, _}`, `{:compaction, _}`, `{:resume, _}` | audit/meta (see §4.1) |
| `_other` | **Drop** |

> Rationale: without the `{:text_delta}` drop the Recorder would take one message per streamed token;
> without the `{:system}` drop every resume would nest two system prompts.

## 5. Behavioral Flow

### 5.1 The write path

1. `Athanor.Agent` mutates `state.messages` **only** through `record_messages/2` (proposed refactor),
   which appends and calls `Bus.publish_message(state.id, state.parent_id, msg)`.
2. `Athanor.Store.Recorder.handle_info({:message, id, msg}, state)` →
   `Transcript.append(session_dir, record)` where `record = %{v: 1, seq: next_seq, ts: now, session_id: id, kind: kind_of(msg), payload: msg}`.
3. Append is a single `:file.write/2` of `JSON.encode!(record) <> "\n"` to the session's open append
   handle, followed by `:file.datasync/1` (per-record) or deferred to a batch flush (§5.2).
4. Meta updates (`last_status`, `turn_count`, `compaction`) are folded into a debounced atomic write
   (e.g. at most once per 500 ms per session, plus on `terminate/2`) so hot status churn does not
   rewrite `meta.json` thousands of times.
5. All writes happen in the **Recorder** process; the `Athanor.Agent` never touches disk and never
   blocks on I/O (AGENTS.md "never block the TUI/agent on HTTP or tool execution").

> **Ordering guarantee:** a single agent publishes to a single Recorder pid, and BEAM guarantees
> message order per sender→receiver pair, so a session's records are appended in conversation order
> even though many agents publish concurrently. `seq` is assigned by the Recorder (single writer), so
> it is monotonic per session.

### 5.2 fsync, atomicity & crash safety

- **JSONL append.** Open with the raw API `:file.open(path, [:append, :raw, :binary])`; write one
  complete line per record; `:file.datasync(fd)` (data-only sync, cheaper than `:file.sync/1`). A
  crash between the `write` and the `datasync` may lose the final record but never corrupts earlier
  ones (append only extends the file). Verified: `:file.datasync/1` and `:file.sync/1` both return
  `:ok` on an `[:append, :raw, :binary]` handle.
- **Truncation tolerance (C7).** After a crash mid-write the file may end in a partial line with no
  trailing `"\n"`. `Transcript.read/1` reads the whole file, splits on `"\n"`, drops the trailing
  empty element when the file ends in a newline, and if the last element is non-empty (a partial
  line) it **drops it** and returns `{:truncated, byte_size}` in the result metadata. Any *interior*
  malformed line is a genuine `{:error, :corrupt}`, but the reader still returns the good prefix.
- **`meta.json` / `HANDOFF.md` atomic replace (C6).** Write `<name>.tmp` in the **same directory**,
  `:file.datasync(fd)`, close, then `File.rename/2` onto the target (atomic on POSIX same-filesystem;
  verified rename replaces contents). Never `File.write/2` in place.
- **Ordering of durability.** The transcript is the **source of truth**; `meta.json` is a convenience
  cache. On resume, if `meta.json#last_status` looks stale, it is reconciled from the transcript tail
  (§5.3 step 4). So a lost/torn `meta.json` degrades gracefully.
- **Recorder crash.** `:permanent` restart re-subscribes and re-opens handles lazily. A record lost
  during the restart window is recoverable because `Athanor.Agent` still holds the full `messages` in
  memory; a `Store.reconcile/1` sweep (M6) can append any missing tail by diffing `Agent.get_state`
  against the last transcript record.

### 5.3 Resume / rehydration algorithm & ordering

`Athanor.Orchestrator.resume_all(opts)` (and `resume_session(id, opts)`):

1. **Discover.** `Store.list(root)` globs `~/.athanor/sessions/*/meta.json`; parse each with
   `Session.from_map/1`; skip (and log) malformed/unsupported ones (§3.5).
2. **Order (C8).**
   a. **Conductors first** (`role: :conductor`) sorted by `created_at` ascending.
   b. Then **workers/depth-first by `parent_id` chain**, ensuring a session is emitted only after its
      `parent_id` — a topological sort keyed on `parent_id`. Concretely: group by `parent_id`, then
      emit recursively from each root conductor. Ties within a parent broken by `created_at`.
3. **Rehydrate messages.** For each session: `Transcript.read/1` → keep `user`/`assistant`/`tool`
   records in `seq` order → `messages = records |> Enum.map(& &1.payload)`. If a `compaction` marker
   exists, prefix the compacted-summary message from `HANDOFF.md` (§5.4) so the working set matches
   the last compaction. (`system` is regenerated by `init/1`, C13.)
4. **Neutralise in-flight state (C12).** Force `status: :idle`, `current_task: nil`; emit a
   `{:resume, %{from: version}}` marker record. A `last_status: "streaming"` session is annotated in
   `HANDOFF.md` ("interrupted mid-turn at <ts>") so the model knows a turn did not finish.
5. **Spawn in order.** For each session call
   `Orchestrator.spawn_session(id: id, title: title, role: role, parent_id: parent_id, model: model,
   cd: cd, session_id: opencode_session_id, messages: messages, register: true)` — parents before
   children, so when a child comes up its parent is already live and registered (its
   `notify_parent_on_done` conductor inbox and `Orchestrator.lookup(parent_id)` both resolve).
6. **No initial prompt.** Resume never re-sends the last user prompt (that would re-run work). The
   session simply becomes `:idle` with the restored history; a human (or the TUI) nudges it next.
7. **TUI viewport.** `TUI.run/1` already builds its view from `Daemon.ensure_main_conductor_and_hydrate`
   → `fetch_full_sessions/1` → `messages_to_tui_entries/1` → `TUI.hydrate_sessions/2`. Resume reuses
   this **unchanged**; the restored `messages` are the same data the live path renders.

> **Correction (C8):** ordering is not cosmetic. `Orchestrator.spawn_session/1` registers into
> `Athanor.AgentRegistry`; a child spawned before its conductor still *stores* the conductor id and
> will pub/sub correctly (topics are string-keyed), but `list_sessions/0` ordering,
> `Agent.get_state`-based parent lookups, and any `notify_queue`-style logic assume the parent exists.
> Parents-before-children removes the entire class of "woke a parent that isn't there yet" races.

### 5.4 Compaction trigger + algorithm

**Where it runs.** The `Athanor.Agent` owns `state.messages`, so it drives compaction; the Recorder
persists the outcome. After each `{:turn_complete, _}` (and, if desired, after each `{:tools_result, _}`)
the Agent evaluates a trigger; if tripped it calls the **pure** `Athanor.Store.Compactor.compact/2`,
replaces `state.messages`, and publishes `{:compaction, %{summary: …, kept: n, dropped: m}}`.

**Trigger.**
```
estimate = Athanor.Store.Tokens.estimate_messages(state.messages)
trigger? = estimate + reserve_tokens >= round(context_limit_tokens * compaction_threshold)
```
with defaults `compaction_threshold: 0.8`, `context_limit_tokens: 128_000`, `reserve_tokens ~ 8_000`
(headroom for the next response + tool schemas). Hysteresis: do not compact again until the estimate
drops below `0.5 * context_limit` (prevents thrash on every turn near the boundary). **[OPEN]** exact
numbers are guesses pending a real model context limit.

**Algorithm (C5).**
```
compact(messages, opts) :: {new_messages, summary}
1. system  = hd(messages)                      # %{role: "system"} — always kept verbatim
2. rest    = tl(messages)
3. keep_budget = round(context_limit_tokens * compaction_keep_fraction)   # default 0.4
4. Walk `rest` from newest → oldest, accumulating Tokens.estimate/1,
   stopping when adding the next message would exceed keep_budget.
5. Snap the cut point to the nearest `user` boundary at or before the stop index,
   so the kept suffix starts with a `user` message and no assistant(tool_calls)/tool
   pair is split (C5). If no user boundary fits, keep the whole thing (no-op).
6. prefix = rest[0 .. cut-1]; recent = rest[cut .. -1]
7. summary_msg = summary_message(prefix, session_meta)
8. new_messages = [system, summary_msg] ++ recent
```

- **Summary generation.** v1 is **deterministic** (no extra LLM call): `Handoff.render/2` folds all
  `user`/`assistant`/`tool` records in `prefix` into the structured sections of `HANDOFF.md`
  (goal = first user prompt / latest assistant plan; completed steps = tool calls with `{:ok, _}`;
  blockers = tool calls with `{:error, _}` + `{:error, _}` events; files touched = `read_file`/
  `write_file`/`edit_file` args). `Handoff.to_summary_text/1` flattens it into `summary_msg`
  (`%{role: "assistant", content: "[CONTEXT COMPACTED] …"}`). A `summarizer_fn` seam
  (`(prefix, meta) -> {:ok, text} | {:error, term}`) allows tests to inject a fake and a future
  version to call the LLM.
- **Persistence of the compaction.** The Recorder, on `{:compaction, _}`, (a) appends a
  `kind: "compaction"` record (so the transcript has an explicit compaction marker), (b) atomically
  rewrites `HANDOFF.md`, and (c) bumps `meta.json#compaction{count,last_at,transcript_bytes}`.
  The **transcript is never truncated** — only `HANDOFF.md` and the in-memory working set shrink
  (design §7.4: "compacts older `transcript.jsonl` turns into `HANDOFF.md`").

> **Correction (C5):** the "keep the last N messages" rule is unsafe in an OpenAI-shaped history.
> An `assistant` message with `tool_calls: [...]` must be immediately followed by one `role: "tool"`
> message per `tool_call.id`. Cutting between them produces a history the next request rejects. The
> `user`-boundary snap makes the invariant structural.

### 5.5 Token accounting (C11)

```elixir
defmodule Athanor.Store.Tokens do
  @moduledoc "Heuristic token estimates for compaction thresholds (design §7.4)."
  @chars_per_token 4

  @spec estimate(String.t()) :: non_neg_integer()
  def estimate(text) when is_binary(text), do: max(1, div(byte_size(text), @chars_per_token))

  @spec estimate_messages([map()]) :: non_neg_integer()
  def estimate_messages(messages) do
    Enum.reduce(messages, 0, fn m, acc -> acc + message_cost(m) end)
  end

  # ~4 tokens of framing per message + content + tool_call name/arguments JSON.
  defp message_cost(%{role: "tool"} = m), do: 4 + estimate(m[:content] || "")
  defp message_cost(%{tool_calls: tcs} = m) when is_list(tcs) and tcs != [] do
    4 + estimate(m[:content] || "") +
      Enum.reduce(tcs, 0, fn tc, a -> a + estimate(tc.function.name) + estimate(tc.function.arguments) end)
  end
  defp message_cost(m), do: 4 + estimate(m[:content] || "")
end
```

`byte_size/4` is a well-known rough proxy for English+code; it is **deliberately conservative-low**
so the trigger fires a little early rather than blowing the real context window.
**[OPEN] — provider usage:** `Athanor.LLM`'s SSE parser (`consume_sse_chunk/3` / `finalize_message/1`)
currently accumulates only `delta` content and tool-call fragments and **discards any `usage` object**
in the final chunk. The accurate fix is to capture `usage.prompt_tokens` from the terminal SSE frame
and store it on the assistant message (e.g. `:usage`), then use the last known `prompt_tokens` as the
authoritative estimate. Flagged because it touches the LLM transport (otherwise out of scope) and the
exact OpenCode Go usage payload shape is unverified from the code.

## 6. Interaction with Existing Subsystems

### 6.1 Supervision tree
One new `:permanent` child (`Athanor.Store.Recorder`). Resumed sessions are ordinary
`Athanor.Agent` children under the **existing** `Athanor.AgentSupervisor` — no new supervisor. This
keeps the `:one_for_one` isolation guarantee (a Recorder crash does not kill agents; an agent crash
does not kill the Recorder).

### 6.2 PubSub
Store is a **pure subscriber** on `"deck:events"` plus one new publisher method
`Bus.publish_message/3` (also on `"deck:events"`). It introduces **no** new topic and therefore no new
wildcard/subscription life-cycle. Existing topics (`"agent:<id>:inbox"`,
`"agent:<id>:events"`, `"conductor:<id>:children"`) are untouched, so the TUI, blocking `wait: true`
callers, and the `[DONE]` parent-wakeup path are unaffected.

### 6.3 Daemon (§7.7)
The Recorder lives on **whichever node owns the agents** (normally the daemon) because it consumes
that node's Bus. TUI client nodes never write to `~/.athanor`. Resume is exposed to clients as thin
`:erpc` wrappers:
```elixir
Daemon.resume_session(target_node, id)      # -> :erpc.call(node, Orchestrator, :resume_session, [id])
Daemon.resume_all(target_node, opts)        # -> :erpc.call(node, Orchestrator, :resume_all, [opts])
```
`Mix.Tasks.Athanor.Daemon` already calls `Daemon.ensure_main_conductor_and_hydrate/2`; a `--resume`
variant routes that through resume.

### 6.4 TUI
No new rendering. `/resume <id>` is a new `handle_key/2` clause returning `{:resume, id, tui}`, handled
in `loop/2` by `Daemon.resume_session/2` + `ensure_session/3`. `/resume` (no arg) lists resumable
sessions from disk. Viewport restore reuses `TUI.hydrate_sessions/2` /
`Daemon.messages_to_tui_entries/1` verbatim.

### 6.5 Agent loop
Only additive: a `:messages` pre-seed opt, a `record_messages/2` choke point, `session_id` in
`get_state/1`/`snapshot_meta/1`, and an optional post-turn compaction check. The turn state machine,
tool execution, `parse_done_sentinel/1`, and `maybe_publish_child_done/2` are unchanged — §7.2's
trust-but-verify invariant (a goal worker's `===ATHANOR_DONE===` must not wake the conductor) is
untouched because Store only *reads* those events.

  already covers the transport separately.)

### 9.9 Simulated crashes
- (a) **Partial trailing line** (C7) — §9.2.
- (b) **Torn `meta.json`** — write `meta.json.tmp` then kill; assert `load/1` uses the intact
  `meta.json`; delete `meta.json` and leave only `.tmp`; assert `load/1` returns `{:error, :corrupt}`
  and the sweep skips (no crash).
- (c) **Recorder killed mid-append** — start a write of a large record, `Process.exit(recorder, :kill)`;
  assert the transcript is still readable and ends either on a complete line or a tolerated partial.
- (d) **Agent killed mid-turn** — assert only the *appended* messages are on disk; the in-flight
  assistant message is absent, and resume yields a consistent (tool-call/result-balanced) history.

Every milestone must leave `mix format --check-formatted`, `mix compile --warnings-as-errors`, and
`mix test` green. All new public functions get `@doc` + `@spec`; new modules get `@moduledoc` citing
their design-§7.4 role. `tools_test.exs` and `orchestrator_test.exs` must stay green **unchanged**
except for the additive new tests described above.

## 10. Risks, Edge Cases & Open Questions

### Risks / edge cases
1. **Two writers, corrupt files (C10).** No lock guards `~/.athanor`. Two daemons (or a daemon +
   foreground `mix athanor`) writing the same session dir interleave appends and race renames.
   Mitigations: document single-owner; a `flock`/lockfile in `sessions_root`; refuse to start a second
   Recorder if the lock is held. **[OPEN]** whether to hard-fail or warn.
2. **Fire-and-forget write loss.** `Bus.broadcast/2` is drop-on-dead-subscriber. If the Recorder is
   momentarily down, records are missed. Mitigations: `:permanent` restart; `Store.reconcile/1` (M6)
   diffing `Agent.get_state` against the transcript tail; the Agent's in-memory `messages` remains the
   working set regardless.
3. **Token estimate accuracy (C11).** `byte_size/4` can be off by 2–3× for dense code/JSON. Bias low
   (fire the trigger early) and keep a `reserve_tokens` headroom. Real fix = capture provider `usage`
   (touches `Athanor.LLM`, **[OPEN]**).
4. **Compaction correctness (C5).** The single highest-severity correctness bug would be splitting a
   tool-call pair. The `user`-boundary snap + the pairing-invariant test (§9.4) are the guard rails.
5. **Secrets in transcripts.** Tool `bash` output and file contents may contain credentials, and are
   written verbatim to `~/.athanor` with default permissions. Mitigations: document; recommend
   `chmod 700` on the root at creation; redaction is a future add (**[OPEN]**). Do **not** put the
   store under a repo (it lives in `$HOME`, so it is not accidentally committed).
6. **`cd` no longer exists on resume.** A worktree (§7.1) may have been pruned. Resume should still
   rehydrate the session but log a warning and keep `cd` as-is; tools will error at call time as they
   do today.
7. **Resume of an interrupted turn (C12).** We cannot resume a partially streamed LLM call or a
   half-run tool. Status is neutralised to `:idle`, `current_task: nil`, and `HANDOFF.md` records the
   interruption. The model may re-issue the interrupted tool call — acceptable, but note it can
   duplicate side effects (e.g. a second `git commit`). **[OPEN]** whether to mark such sessions
   "needs review" in the TUI.
8. **Clock / timestamps.** On-disk `ts`/`created_at`/`updated_at` use `DateTime.utc_now/0` for human
   readability only; **no** maths depends on them (an NTP step would otherwise reorder sessions). Any
   monotonic comparisons (debounce, ordering fallback) use `System.monotonic_time/1`.
9. **Large transcripts.** A long-lived conductor's `transcript.jsonl` can grow unbounded (compaction
   shrinks the *working set and HANDOFF*, not the log — by design). Mitigations: `meta.json#compaction.transcript_bytes`
   visibility; optional rotation into `transcript.<n>.jsonl` is a future add (**[OPEN]**; would need
   reader support for multiple parts).
10. **Open file-descriptor pressure.** The Recorder keeps an append handle per hot session. With many
    sessions this approaches the VM fd limit. Mitigation: LRU cap (e.g. 64 open handles), close-on-idle,
    lazy reopen on next record. Mentioned in M6.
11. **Ordering across `meta.json` and transcript (§5.2).** Meta is a cache; if it lags, `last_status`
    is reconciled from the transcript tail. Never trust meta alone for correctness.
12. **Schema drift.** Adding a field to message maps (e.g. an `:usage` field) must not break the
    reader: unknown fields are preserved in `payload` verbatim (we store the whole message map), so
    round-trip is robust to additive changes.
13. **Interaction with §7.2 (Goal).** `GoalManager` receipts/status/`close_evidence` are exactly the
    state §7.4 should carry. v1 records goal events as `kind: "event"`; a resumed goal must be
    re-created (or marked `:failed`) rather than silently trusted — flagged in §7.2 risk 13 and here.
14. **Interaction with §7.5 (Memory).** `HANDOFF.md` is session-local; Memory is cross-session. The
    boundary must stay explicit or the same facts get stored twice. Post-session distillation (§7.5.4)
    is the intended bridge.

### Open questions (require Conductor/user decision before coding)
- **OQ1 — meta field naming.** `"session_id"` (= OpenCode Go id, per design.md) vs
  `"opencode_session_id"` (clearer; used in §3.3's example). Pick one before M1 freezes the format.
- **OQ2 — Root index.** Ship `~/.athanor/sessions/index.json` for O(1) listing, or always glob-scan?
  (Scan is simpler and fine for hundreds of sessions; index adds a second source of truth to keep
  consistent.)
- **OQ3 — CLI grammar.** `mix athanor --resume` (all) + `--session <id>` (one)? Or
  `--resume [id]`? `OptionParser` `strict:` can't express an optional value cleanly, so the two-flag
  form is recommended.
- **OQ4 — Compaction thresholds.** `context_limit_tokens: 128_000`, `threshold: 0.8`,
  `keep_fraction: 0.4` are guesses; needs a real model limit and a real `usage`-based calibration.
- **OQ5 — Summarisation source.** Deterministic `HANDOFF.md` synthesis (proposed, cheap, testable) vs
  an LLM summarisation pass (more faithful, costs tokens/latency, non-deterministic) vs both behind a
  `summarizer_fn`. Recommendation: deterministic v1 + seam.
- **OQ6 — Provider usage.** Adopt capturing `usage.prompt_tokens` in `Athanor.LLM` (accurate) or keep
  the heuristic (no transport change)? The SSE `usage` frame shape is unverified from the code.
- **OQ7 — Single-writer enforcement (C10).** Lockfile-and-refuse, lockfile-and-warn, or document-only?
- **OQ8 — Does resume auto-restart child workers** that were mid-turn, or leave everything `:idle`
  awaiting a human nudge? Recommendation: `:idle` (never re-run work implicitly).
- **OQ9 — Transcript rotation** for very long sessions (multi-file transcripts) or unbounded growth?
- **OQ10 — Does closure/`cancel` delete or archive a session dir?** `Store.delete/1` exists; whether
  the TUI/CLI exposes it and whether it's soft (archive) or hard is undecided.
- **OQ11 — Config location.** Introduce `config/config.exs` or keep the `Athanor.Config`
  module-attribute + env-var idiom? (Recommend the latter; the tree has no `config/` today.)

implement the filtering rules (§4.4) and fsync/atomic writes (§5.2). Tests: §9.6 + crash cases (a)/(c).

the Agent's post-turn trigger + `{:compaction, _}` publish, and the Recorder's `HANDOFF.md` rewrite +
`kind: "compaction"` record + meta bump (§5.4). Tests: §9.4.

`Store.reconcile/1`, fd LRU, lockfile decision (OQ7), full fault-injection suite (§9.9 (b)/(d)),
migration fixtures, and the `docs/design.md` §7.4 status update (done by implementers — this plan
