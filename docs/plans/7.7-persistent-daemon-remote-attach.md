# Implementation Plan — §7.7 Persistent Daemon & Live Remote Attach (`Athanor.Daemon`)

> **Status: partly implemented — this plan closes the gap.**
> Planning artefact. Every *existing* module, function, task, flag, topic and message shape named below
> was verified against the current tree (`lib/athanor/{daemon,bus,agent,orchestrator,application,config,tui,llm,tools}.ex`,
> `lib/mix/tasks/{athanor,athanor.daemon}.ex`, `mix.exs`, `test/athanor/*.exs`, `docs/design.md`).
> Everything that does **not** yet exist in the tree is marked **[PROPOSED]**. There is **no `config/`
> directory** — all configuration goes through the `Athanor.Config` module-attribute + env-var idiom (§7).
>
> **Already realised** (see `docs/design.md` §7.7 "Implemented subset"): the `Athanor.Daemon` bridge,
> `mix athanor.daemon` (run / `--status` / `--stop` / `--restart`), thin TUI attach/detach,
> multi-client mirroring via per-client relay processes, build-marker version checking, and full
> session hydration on attach.
> **Still planned**: standalone `athanor` / `athanor attach` entry points, `systemd --user` auto-start,
> the native OTP `:ssh.daemon/2` subsystem, a non-constant cookie, graceful drain, and node-down
> handling in the client loop. The realised node name is `athanor_daemon@127.0.0.1`, **not**
> `athanor@127.0.0.1` as written in §7.7 (recorded drift, see §9 OQ1).

## 0. Hazard / self-review pass

Reading the realised daemon against the rest of the tree surfaced the following concrete defects and
gaps. These are not hypothetical; each was observed in the source. The plan below is shaped by them.

| # | Defect / gap (verified in the tree) | Consequence | Fix proposed here |
|---|---|---|---|
| H1 | `Athanor.TUI.loop/2` (`lib/athanor/tui.ex`) `receive`s only on the Termite reader ref and `{:agent_event, …}` — it never calls `:net_kernel.monitor_nodes/1` and has no `{:nodedown, …}` clause. | If the daemon dies, the attached client freezes silently on stale state: keystrokes still render, `Daemon.send_session/3` fails inside `:erpc` with a raised exit, and the user gets no error. | Add `monitor_nodes/1` + a `{:nodedown, node}` clause that flips the TUI to a "daemon lost" banner (§5.3, §6.2). |
| H2 | `Daemon.spawn_detached_daemon/1` calls `Port.open(...)` and **discards the port**, with no `:exit_status`, no pid file, and no output capture; `cd:` is `File.cwd!()` of the *attaching client*. | Auto-start can fail invisibly (bad `PATH`, epmd refused, compile error) and `connect_or_start_daemon/1` can only report the generic `:daemon_start_timeout`. The daemon inherits the client's cwd, so `bash`/`read_file`/`write_file` tools in every session run against whatever directory the user happened to attach from. | Capture stdout/stderr to a log, write a pid file, and pin `cd` to a configured workspace root (§3.4, §6.1, §7). |
| H3 | `@default_cookie :athanor_local_secret_cookie` is a **compile-time constant committed to the source tree** (`lib/athanor/daemon.ex`). | Any local process (and any user on the box) can trivially attach to the daemon, read every session transcript, and inject prompts via `Orchestrator.send_session/2`. Distribution authentication is effectively absent. | **[PROPOSED]** `Athanor.Daemon.Cookie`: generate a random cookie on first run, persist `~/.config/athanor/cookie` mode `0600`, and refuse to start with the source-tree default unless `ATHANOR_ALLOW_INSECURE_COOKIE=1` (§5.1, §6.7). |
| H4 | `@build_marker "athanor-0.1.0"` is a hand-maintained literal that duplicates `mix.exs`'s `version:`; nothing asserts they agree. | The version guard (a genuinely good feature) silently rots: bumping `mix.exs` without bumping the marker lets an incompatible client attach. | Derive from `Application.spec(:athanor, :vsn)`, add a test asserting `build_marker() == "athanor-" <> version` (§3.5, §8). |
| H5 | `Daemon.ensure_distributed_node/1` returns `:ok` when `Node.alive?()` is already true, regardless of the **name the VM was actually started with**. | A client launched as `elixir --name someother@host` silently attaches as `someother@host`; `@default_daemon_node` comparisons and the "one client per TUI" assumption break, and `mix athanor.daemon` can *become* the daemon under the wrong name. | Validate the live node name and fail loudly with an actionable error (§5.1). |
| H6 | `Mix.Tasks.Athanor.Daemon.stop_daemon/0` uses `:erpc.cast(target, :init, :stop, [])` — an immediate VM kill. | `--stop` and `--restart` destroy every live Conductor/Sub-Agent **mid-turn**, discarding unpersisted message history. `--restart` then reports success having destroyed work. That is the opposite of the section's promise ("detach without stopping active agents"). | Add a graceful drain path and make `--stop` warn/refuse while sessions are busy unless `--force` (§6.1, §10 phase 4). |
| H7 | `Athanor.Config` is the house idiom for runtime config (`lib/athanor/config.ex`), but `Athanor.Daemon.daemon_node/0` and `cookie/0` read `System.get_env/1` + `Application.get_env(:athanor, …)` **inline**, duplicating the pattern and bypassing `Config`. | New daemon knobs would scatter across two modules and two idioms; `Config`-shaped tooling/tests cannot see them. | Move resolution into `Athanor.Config` accessors; keep `Daemon.daemon_node/0` / `cookie/0` as thin delegators so existing callers and tests are untouched (§7). |
| H8 | `Athanor.Bus` is backed by a **node-local** `Registry` (`{:Registry, keys: :duplicate, name: Athanor.PubSub}` in `lib/athanor/application.ex`); `Bus.broadcast/2` does `Registry.dispatch/3`. | Cross-node fan-out is *not* a property of `Bus` — it is provided entirely by the per-client relay in `Daemon.start_remote_relay/1`. Any new consumer that subscribes directly on the client node would receive nothing. | The relay must remain the **only** cross-node transport in §7.7, and this must be stated as an invariant (the cluster-wide bus is §7.8's problem) (§2.4, §4.1). |
| H9 | There is **no `athanor` executable**: `mix.exs` declares no `escript:` and no `mix release`; `Mix.Tasks.Athanor.run/1` starts with `Mix.Task.run("app.start")` and requires the project directory as cwd. | §7.7 bullet 2's "SSH in and run `athanor`" does not work today: the user must `cd` into the source tree and have Elixir + deps compiled. | **[PROPOSED]** an escript (`athanor`) plus `mix athanor.attach`, with `mix escript.install` documented (§6.2, §11). |
| H10 | In the `local:`/`{:local_fallback, _}` branches `TUI.run/1` sets `target_node = Node.self()` and *still* calls `Daemon.attach_subscriber/2`, which spawns an extra same-node relay process whose only job is `Bus.subscribe("deck:events")` + forward to the TUI pid — even though the TUI could subscribe directly. | One wasted process hop per local client; harmless, but it means the "local" path exercises the remote relay code by accident, so relay bugs hide in local mode and local bugs hide in remote mode. | Keep the relay for remote mode; add a direct-subscribe fast path for `mode == :local` (§4.2, §6.2). |

## 1. Scope & Non-goals

### In scope
- **Long-lived background node (`athanord`)**: harden and complete the existing
  `Athanor.Daemon` daemon node that owns `Athanor.AgentSupervisor`, `Athanor.AgentRegistry`,
  `Athanor.PubSub`/`Athanor.Bus`, and every live Conductor/Sub-Agent.
- **Daemon lifecycle**: `start / stop / status / restart` with a real pid file, log capture, graceful
  drain, crash-restart, and a `systemd --user` unit installer.
- **Thin TUI attach/detach client**: the entry points `mix athanor` (exists), `mix athanor.attach`
  **[PROPOSED]**, and an `athanor` escript **[PROPOSED]**; explicit `--server`/`--local` target
  selection; subscribe-then-hydrate; node-down detection; reconnect.
- **Multi-client mirroring**: several attached clients (desktop + SSH laptop + SSH phone) watching the
  same daemon in sync, with an attachment registry and `Daemon.status/0`.
- **Safe detach**: `Ctrl+Q`, `/detach`, `/quit`, `/exit`, `Ctrl+C`, `Ctrl+D`, and abrupt SSH drop all
  leave the daemon's sessions running.
- **Optional native OTP `:ssh` subsystem** **[PROPOSED]**: `:ssh.daemon/2` on a dedicated port,
  spawning a `Athanor.TUI` session per SSH channel.
- **Security posture**: non-constant cookie persisted `0600`, localhost binding by default, documented
  trust model, and an explicit "insecure by default is refused" behaviour.
- **Version-mismatch handling**: build-marker compatibility gate, actionable errors, and a
  `--restart` recovery path.
- **Multi-node testing** and a phased rollout.

### Non-goals (explicitly excluded)
- **Not** §7.8 Multi-Host Distributed BEAM Clustering. The `Athanor.Bus` `Registry` stays node-local
  (H8); events cross exactly one hop — from the daemon node to each attached client — via the relay
  process. Cross-node session visibility, distributed PubSub and remote worker placement belong to
  `docs/plans/7.8-distributed-beam-clustering.md`.
- **Not** a TLS/`-proto_dist inet_tls` distribution transport. v1 requires a trusted host plus a
  strong cookie (§6.7); TLS distribution is flagged as an open question (§9 OQ5).
- **Not** multi-user / multi-tenant daemons. One daemon per Unix user; isolation between users is the
  OS's job.
- **Not** a web UI, not a headless JSON stream, not an HTTP API.
- **Not** session persistence across daemon restarts. Transcripts live in
  `Athanor.Agent.messages` in memory; `--stop` loses them today and this plan does **not** fix that
  (that is §7.4's store). H6 mitigation is "warn, don't silently destroy".
- **Not** changes to `Athanor.Agent`, `Athanor.Orchestrator`, `Athanor.Bus`, `Athanor.LLM` or
  `Athanor.Markdown` semantics. The only edits to existing runtime modules are `Athanor.Daemon`,
  `Athanor.TUI.run/1`'s attach section, `Athanor.Config`, `Athanor.Application`, and the two Mix tasks.
- **Not** Windows support. `epmd`, `systemd --user`, and `~/.erlang.cookie` semantics are assumed Unix.
- **Backward compatibility is a requirement**: `mix athanor --local`, `mix athanor.daemon` with no
  flags, and every existing public function of `Athanor.Daemon` keep their current signatures and
  return shapes; `test/athanor/daemon_test.exs` must pass **unchanged**.

### 2.3 Supervision placement

Today (`lib/athanor/application.ex`) both modes run one identical tree. §7.7 keeps that property: the
daemon node is *the same application* with distribution started and a lifecycle owner present.

```text
# ── Daemon node: athanor_daemon@127.0.0.1  (mix athanor.daemon) ──────────────
Athanor.Supervisor (:one_for_one)
├── Athanor.AgentRegistry     (Registry, :unique)        # existing — session id → pid
├── Athanor.PubSub            (Registry, :duplicate)     # existing — topic → pid
├── Athanor.AgentSupervisor   (DynamicSupervisor)        # existing — ALL Conductors/Sub-Agents
├── Athanor.Daemon.Server     (GenServer)        [NEW]   # owns pid file, attachments, drain
└── Athanor.SSH               (GenServer)        [NEW]   # only if Config.ssh_enabled?()

   Distribution: :longnames, node = Daemon.daemon_node(), cookie = Daemon.cookie()
   Outbound relay per client: plain spawn/1 (NOT supervised) — see §2.4

# ── Client node: athanor_tui_<hex>@127.0.0.1  (mix athanor) ─────────────────
Athanor.Supervisor (:one_for_one)
├── Athanor.AgentRegistry     (Registry, :unique)        # present but empty in daemon mode
├── Athanor.PubSub            (Registry, :duplicate)     # present; relay is the cross-node link
└── Athanor.AgentSupervisor   (DynamicSupervisor)        # present but empty in daemon mode
   + the TUI process (Termite reader + loop/2) — not a supervised child today (see risk R6)
```

`Athanor.Daemon.Server` must start **after** `Athanor.AgentRegistry`/`Athanor.PubSub`, because on
boot it registers its own `"daemon:clients"` subscription and may immediately publish a
`{:daemon_started, …}` event.

> **Invariant.** `Daemon.start_remote_relay/1` deliberately does **not** use the supervisor: the relay
> is owned by (and dies with) the client it mirrors. It is a plain `spawn/1` that
> `Process.monitor/1`s the client pid. Do not "tidy" this into a `DynamicSupervisor` child — a
> supervised relay would survive its client and leak a `"deck:events"` subscriber per SSH reconnect.

### 2.4 PubSub topics / message handlers

The full topic set lives in `Athanor.Bus`'s moduledoc. §7.7 uses exactly one of them for streaming
and does not add new `Bus` topics in v1 (H8); daemon-lifecycle notifications get a **separate**
**[PROPOSED]** topic on the daemon node that clients subscribe to *through the relay*.

| Topic | Owner | Direction | Exists? |
|---|---|---|---|
| `"deck:events"` | `Athanor.Bus` | daemon → all clients (via relay) | **exists** |
| `"agent:<id>:events"` | `Athanor.Bus` | daemon-local per-session stream | **exists** |
| `"agent:<id>:inbox"` | `Athanor.Bus` | client → agent commands (`send_session/3` → `Orchestrator.send_session/2` → `Bus.send_command/2`) | **exists** |
| `"conductor:<id>:children"` | `Athanor.Bus` | daemon-local child lifecycle | **exists** |
| `"daemon:clients"` | `Athanor.Daemon.Server` **[PROPOSED]** | daemon-local attachment announcements, relayed to clients | PROPOSED |

**Handler map (client side).** The relay forwards raw `{:agent_event, session_id, event}` tuples; the
client's `TUI.handle_agent_event/3` already handles every event the daemon emits
(`{:session_started, meta}`, `{:user_message, text}`, `{:status, status}`, `{:text_delta, chunk}`,
`{:turn_complete, content}`, `{:tool_start, name, args}`, `{:tool_end, name, {:ok|:error, _}}`,
`:cancelled`, `{:error, reason}`, `{:child_done, report}`). **No new handlers are required for
streaming** — the work is transport and lifecycle, not vocabulary.

**Handler map (daemon side).** `Athanor.Agent` handles `{:bus_command, {:prompt, t}}`,
`{:bus_command, {:enqueue_prompt, t}}` and `{:bus_command, :cancel}` on its inbox; `Athanor.Bus`
handles nothing. `Athanor.Daemon.Server` **[PROPOSED]** additionally handles `{:bus_command, …}` on
`"daemon:clients"` only for its own control commands.

defmodule Athanor.Daemon.Attachment do
  @moduledoc "One attached TUI client mirrored by a relay on the daemon node."

## 4. Message & PubSub Protocol

### 4.1 Delivery contract (what actually holds today)

| Property | Reality | Evidence |
|---|---|---|
| Transport | One **relay process per attached client**, spawned *on the daemon node*. | `Daemon.start_remote_relay/1` |
| Ordering | Preserved per relay: Erlang signals between two processes are ordered, and the relay forwards 1:1. | `relay_loop/2` body |
| Fan-out | `Bus.broadcast/2` → `Registry.dispatch(Athanor.PubSub, …)` reaches **local subscribers only**; the daemon node's subscribers are all local, so fan-out to N clients is N relays. | `lib/athanor/bus.ex`, H8 |
| Delivery | **At-most-once, no replay.** There is no buffer, no sequence number, no ack. Events published after a client's process dies are lost (correct — nothing is watching). | `send/2` in `relay_loop/2` |
| Snapshot vs stream | `TUI.run/1` calls `attach_subscriber/2` **before** `ensure_main_conductor_and_hydrate/2`, i.e. **subscribe-then-snapshot**. | `lib/athanor/tui.ex` |
| Teardown | Relay unsubscribes on `{:DOWN, …}` for the client pid **or** on an explicit `:detach` message; `TUI.run/1`'s `after` block sends `:detach`. | `relay_loop/2`, `run/1` |

> **Invariant to preserve.** Subscribe-before-snapshot is what makes hydration gap-free: any event
> emitted while `fetch_full_sessions/1` is in flight is already queued at the client, and the
> idempotent `ensure_session/3` / `handle_agent_event/3` handlers absorb the duplicate. Reversing the
> order would silently drop tokens for sessions created during hydration. Any refactor (including
> `Athanor.Daemon.Client.attach/1`) **must keep this order** and should assert it in a test.

### 4.2 Command / event catalogue

### 4.3 RPC discipline

`Daemon.rpc/4` short-circuits to a direct `apply/3` when `node == Node.self()`; every wrapper
(`send_session/3`, `cancel_session/2`, `launch_subagent/5`, `start_conductor/2`,
`fetch_full_sessions/1`, `ensure_main_conductor_and_hydrate/2`) goes through it. New wrappers
**must** do the same — an `:erpc.call/5` to a node that never loaded the target module raises a bare
`:undef`, which is precisely the bug fixed in commit `66d647e`. New RPCs must also carry an explicit
`:erpc.call/5` timeout (existing ones rely on the default `:infinity`; §6.6 proposes making it
configurable).

## 5. Behavioral Flow

### 5.1 Start

1. `mix athanor.daemon` (no flags) → `Daemon.start_as_daemon/0`.
2. `ensure_epmd/0` runs `epmd -daemon` (stderr folded into stdout, rescues if `epmd` is missing).
3. `ensure_distributed_node/1`: if `Node.alive?/0` is false, `Node.start(node_name, :longnames)`;
   `{:error, {:already_started, _}}` is treated as success. **[PROPOSED]** if already alive, compare
   `Node.self/0` to the requested name and `{:error, {:node_name_mismatch, actual, wanted}}` (H5).
4. `Node.set_cookie(cookie())`. **[PROPOSED]** the cookie comes from `Daemon.Cookie.resolve/0`, which
   errors with `{:error, :insecure_default_cookie}` unless `ATHANOR_ALLOW_INSECURE_COOKIE=1` (H3).
5. **[PROPOSED]** write `Daemon.Paths.pid_file/0` (`System.pid/0`) and open the log.
6. `Mix.Task.run("app.start")` → `Athanor.Application` boots `AgentRegistry`, `PubSub`,
   `AgentSupervisor`, `Daemon.Server`, and (if enabled) `Athanor.SSH`.
7. `Daemon.ensure_main_conductor_and_hydrate/2` starts `"conductor-main"` if absent, then
   `Mix.shell().info/1` prints the node name and the attach hint, and `Process.sleep(:infinity)`.
8. Auto-start path (client side): `connect_or_start_daemon/1` finds the target unreachable, calls
   `spawn_detached_daemon/1`, then polls `usable?/1` every 150 ms until `:timeout` (default 15 s).
   **[PROPOSED]** the spawn keeps a port handle, redirects output to `Daemon.Paths.log_file/0`, and
   sets `cd:` to `Config.daemon_workspace/0` instead of `File.cwd!()` (H2).

### 5.2 Steady state (attach → mirror → act)

1. Client: `mix athanor` → `Config.model/0`, `local? = Keyword.get(opts, :local, false)`.
2. `Daemon.connect_or_start_daemon(opts)` → `{:ok, daemon}` (or `:local` / `{:local_fallback, reason}`).
   Internally: `ensure_epmd/0`, `Node.start(:"athanor_tui_<hex>@127.0.0.1", :longnames)`,
   `Node.set_cookie/1`, then `usable?/1` → `{:ok, target}`.
3. `Daemon.attach_subscriber(target_node, self())` → relay on the daemon → `{:ok, relay_pid}`.
4. `Daemon.ensure_main_conductor_and_hydrate(target_node, main_id: "conductor-main", model: model)`
   → `{:ok, "conductor-main", sessions}` where each session already carries `:messages`.
5. `Terminal.start() |> Screen.alt_screen() |> Screen.clear_screen()`; `TUI.new/1` with
   `hydrated_sessions:` → `TUI.hydrate_sessions/2` rebuilds `entries` via
   `Daemon.messages_to_tui_entries/1`.
6. `TUI.loop/2` renders `render_frame/1`, receives `{:agent_event, id, event}` from the relay, and
   applies `handle_agent_event/3`.
7. User actions dispatch through `Daemon.send_session/3`, `Daemon.launch_subagent/5`,
   `Daemon.start_conductor/2`, `Daemon.cancel_session/2` — all `:erpc` to the daemon, all executing on
   the daemon's `AgentSupervisor`.
8. **N clients**: each has its own relay; `Bus.broadcast/2` is local to the daemon so all N relays are
   local subscribers and each forwards to its own client. Identical ordering for all N → "in sync".

### 5.3 Failure paths

1. **Daemon dies / node down** — **[PROPOSED]** `TUI.loop/2` gains `:net_kernel.monitor_nodes(true)`
   and a `{:nodedown, node}` clause when `node == tui.daemon_node`: append
   `{:error, "daemon #{node} went down"}` to the active session and set `status: :error`; do not
   crash. `{:nodeup, node}` clears it. Today this case is silent (H1).
2. **Client dies / SSH drops** — the relay's `Process.monitor/1` fires `{:DOWN, …}`, the relay calls
   `Bus.unsubscribe("deck:events")` and exits `:normal`. Verified by
   `test/athanor/daemon_test.exs` ("cleans up relay on client exit"). Daemon sessions are untouched.
3. **Client detaches explicitly** — `TUI.run/1`'s `after` block `send(relay_pid, :detach)`; relay
   demonitors, unsubscribes, exits. Idempotent with (2).
4. **Version mismatch** — `usable?/1` returns false while `Node.connect/1` returns true →
   `connect_or_start_daemon/1` returns `{:error, {:incompatible_daemon, target}}`; `TUI.run/1` falls
   back to `{:local_fallback, reason}` and prints
   `mode_banner({:local_fallback, …})` → "…running stand-alone; agents stop when you quit. Fix with
   `mix athanor.daemon --restart`". `mix athanor.daemon --restart` detects the same case and
   `Mix.raise/1`s with `epmd -names` / `pkill -f` guidance.
5. **Daemon never comes up** — `{:error, :daemon_start_timeout}` (poll loop) or
   `{:error, :daemon_unreachable}` (`auto_start: false`). `--status` prints
   "Athanor daemon is not running (#{node})".
6. **RPC target vanished mid-session** — `:erpc.call/4,5` exits; the client process crashes today. **[PROPOSED]** wrap the `Daemon.rpc/4` remote branch in `try/catch` and return `{:error, {:node_down, node}}`, so a lost daemon degrades the TUI instead of killing it.
7. **epmd refuses / missing** — `ensure_epmd/0` swallows the failure; `Node.start/2` then errors and
   `connect_or_start_daemon/1` returns `{:error, {:cannot_start_distribution, reason}}` **[PROPOSED]**
   with a message naming `epmd` and `-name`/`-sname`.

## 6. Feature detail

### 6.1 Long-lived background node (`athanord`)

- **Identity.** `Daemon.daemon_node/0` resolves `ATHANOR_DAEMON_NODE` → `:athanor, :daemon_node` →
  `@default_daemon_node` (`:"athanor_daemon@127.0.0.1"`). **[PROPOSED]** move this into
  `Config.daemon_node/0` and keep `Daemon.daemon_node/0` as a delegator (H7).
- **What it owns.** The daemon node is where `Orchestrator.spawn_session/1` actually runs, i.e. where
  `DynamicSupervisor.start_child(Athanor.AgentSupervisor, spec)` puts the agent. Therefore all
  `Athanor.Agent.messages` state, all `Athanor.AgentRegistry` registrations, and all tool execution
  (`bash`/`read_file`/`write_file`/`edit_file`, which resolve against `state.cd`) live on the daemon.
  The client is genuinely thin.
- **Lifecycle verbs.** `mix athanor.daemon` = run in foreground (`run_foreground_daemon/1`);
  `--status`; `--stop`; `--restart`. **[PROPOSED]** `--foreground` for explicitness, `--logs` (tail
  the log), `--json` (machine-readable `Daemon.status/0`), `--install-service`/`--uninstall-service`.
- **Graceful stop (H6).** **[PROPOSED]** `--stop` calls `Daemon.drain(timeout_ms)`:
  1. publish `{:daemon_draining, ms}` on `"daemon:clients"`;
  2. enumerate `Orchestrator.list_sessions/0`; if any `status in [:streaming, :executing_tools]` and
     `--force` was not passed, print the busy session ids and **abort** with a non-zero exit;
  3. optionally `Orchestrator.cancel_session/1` per session;
  4. `:erpc.cast(target, :init, :stop, [])` (the existing mechanism) and `wait_until_stopped/2`.
- **Crash restart.** **[PROPOSED]** the systemd unit uses `Restart=on-failure` with
  `RestartSec=2`, giving supervised restarts without the client ever having to auto-start.
- **Workspace pinning (H2).** **[PROPOSED]** `spawn_detached_daemon/1` sets
  `cd: Config.daemon_workspace()`, which defaults to the project root when the daemon is started by a
  Mix task and to `File.cwd!()` for the foreground path (preserving today's behaviour for
  `mix athanor.daemon`).

### 6.2 Thin TUI attach/detach client

- **Entry points.** `mix athanor` (**exists**: `--model`, `--local`, `--restart`/`-r`, `--theme`/`-t`).
  **[PROPOSED]** `--server <node>` and `--no-auto-start`; a `mix athanor.attach` alias task; and an
  `athanor` escript (H9) so a remote user can `athanor --server athanor_daemon@<host>` without a
  source checkout. `--local` stays exactly as-is for offline debugging.
- **Node naming.** Clients are `:"athanor_tui_#{Base.encode16(:crypto.strong_rand_bytes(3), case: :lower)}@127.0.0.1"`.
  The 3-byte random suffix gives 16.7M names, so collisions are unlikely but possible; **[PROPOSED]**
  `Daemon.client_node_name/0` retries with a longer suffix when `Node.start/2` returns
  `{:error, {:already_started, _}}`.
- **Attach sequence.** Unchanged and order-critical (§4.1): connect → relay → hydrate → `TUI.new`.
- **Local fast path (H10).** **[PROPOSED]** when `mode == :local`, subscribe the TUI process directly
  (`Athanor.Orchestrator.subscribe/0` / `Bus.subscribe("deck:events")`) instead of spawning a
  same-node relay. Behaviour is equivalent — same message shape, same ordering — but the code path
  stops lying about being remote. Consequence to handle: `relay` is then `nil` (§3.3), so the
  `TUI.run/1` `after` block must call `Daemon.detach(relay_pid)` (a no-op on `nil`) rather than
  `send(relay_pid, :detach)` directly, and the direct subscriber should `Bus.unsubscribe("deck:events")`
  on exit.
- **Detach keys.** `handle_key/2` already maps `<<3>>` (Ctrl+C), `<<4>>` (Ctrl+D) and `<<17>>`
  (Ctrl+Q) → `{:quit, tui}`, and the input line maps `/quit`, `/exit`, `/detach` → `{:quit, …}`.
  `TUI.run/1`'s `after` restores the cursor, leaves the alternate screen, and stops the terminal.
- **Detach semantics.** Detach destroys **only** the client node. The daemon keeps running; the relay
  is reaped by `{:DOWN, …}`. This is the section's headline promise and is already true — §7.7's work
  is to keep it true while adding SSH and systemd paths.

### 6.3 Multi-client mirroring

- Every client has an independent relay (H8), so N clients see identical, identically-ordered
  `{:agent_event, …}` streams. There is no shared renderer state on the daemon — the daemon is
  oblivious to how many clients watch.
- **Independent client state.** Each client keeps its own `Athanor.TUI` struct: its own
  `active_id`, `scroll_offset`, `focus`, and `theme`. `README.md` already advertises this ("an SSH
  client can pick a different theme from a local one while both watch the same daemon") and it holds.
- **Prompting from any client.** `Daemon.send_session/3` → `Orchestrator.send_session/2` →
  `Bus.send_command(id, {:enqueue_prompt, text})`. `Athanor.Agent` handles `{:bus_command,
  {:enqueue_prompt, text}}` by queueing when busy, so two clients typing simultaneously interleave
  safely rather than erroring. `{:prompt, text}` (used for the *initial* sub-agent prompt in
  `Orchestrator.spawn_session/1`) may reply `{:error, :busy}` — `send_session/2` avoids that by using
  `:enqueue_prompt`.
- **Attachment visibility [PROPOSED].** `Daemon.Server` registers each attachment, publishes
  `{:client_attached, attachment}` on `"daemon:clients"`, and `Daemon.status/0` returns the list. A
  **[PROPOSED]** `/clients` TUI command lists "who else is watching" — genuinely useful when a phone
  and a desktop are both attached.

### 6.4 Safe detach / SSH drop

Already correct for `Ctrl+Q` and `/detach`. The abrupt case relies on distribution detecting the
peer's death: when the client VM exits, `Process.monitor/1` on the *remote* pid delivers
`{:DOWN, ref, :process, pid, :noconnection}` on the daemon node, which the `relay_loop/2`
`{:DOWN, ^ref, :process, ^client_pid, _reason}` clause matches (the reason is not pattern-matched).

**[PROPOSED] hardening**: add an inactivity sweep in `Daemon.Server` that reaps relays whose
`client_pid` fails `Node.list/0` membership and whose `client_node` is no longer connected; belt-and-
braces against a wedged dist connection. Also reap relays whose `client_pid` is remote but whose
`client_node` has been down for longer than `Config.attach_reap_after_ms/0`.

### 6.5 Optional native OTP `:ssh` subsystem [PROPOSED — entirely new]

- **Enable.** `Config.ssh_enabled?/0` (default **false**), `Config.ssh_port/0` (default `2222`),
  `Config.ssh_host_key/0`. `Athanor.SSH` is added to `Athanor.Application`'s children **only** when
  enabled — no effect on existing behaviour.
- **Start.** `:ssh.daemon(port, opts)` with
  `opts = [system_dir: Path.dirname(host_key), key: {:file, host_key}, subsystem: …, ssh_cli: {Athanor.SSH.Handler, []}, auth_methods: "publickey", user_dir: …, pwdfun: …]`.
  `:ssh.daemon/2` returns `{:ok, ref}`; `Athanor.SSH` stores `ref` and stops with
  `:ssh.stop_daemon(ref)`.
- **Per-channel session.** `Athanor.SSH.Handler` (an `:ssh_server_channel` implementation) spawns one
  `Athanor.SSH.Session` per channel. The session:
  1. calls the **same** `Athanor.Daemon.Client.attach/1` used by `mix athanor`, so the SSH path gets
     relay + hydrate + version-check for free and cannot drift from the local path;
  2. drives `Athanor.TUI` with `Termite`'s raw-terminal mode rather than `Terminal.start()` (the
     channel is already a byte stream; there is no controlling tty to take over);
  3. negotiates window size from `:ssh_client` `pty_req`/`window_change` messages instead of
     `Terminal.resize/1`;
  4. on channel close, `send(relay_pid, :detach)` — identical detach semantics (§6.4).
- **Host key.** Generate an ed25519 key on first enable with `:public_key.generate_key/1` (or `ssh-keygen` if absent), mode `0600`, and print the fingerprint on start so users can pin it.
- **Why bother, given `mix athanor` over SSH already works?** The `:ssh` subsystem removes the
  requirement for an Erlang client VM, the source tree, and correct cookie placement on the remote
  box: any `ssh` binary works. It is the "phone/laptop from anywhere" path.
- **Explicit non-goal:** `:ssh` in v1 does **not** expose a shell — only the Athanor TUI channel
  (§6.7).

### 6.6 Version-mismatch handling

- Mechanism (**exists**): `Daemon.build_marker/0` + `Daemon.usable?/1`. `usable?/1` first proves
  connectivity with `:erpc.call(node, :erlang, :node, [])` (a BIF every node has) and only then asks
  for `build_marker/0`, all inside `rescue`/`catch`.
- States: `{:ok, target}` (compatible), `{:error, {:incompatible_daemon, target}}` (reachable, wrong
  build), `{:error, :daemon_unreachable}` (`auto_start: false`), `{:error, :daemon_start_timeout}`.
- **[PROPOSED]** `--json` `--status` reports `build` and `compatible: true|false`; `mix athanor
  --server <node>` refuses to attach on mismatch with the message "daemon <node> runs
  <remote_build>; this client is <local_build>. Run `mix athanor.daemon --restart` on <host>."
- **[PROPOSED]** make the RPC timeout configurable (`Config.attach_rpc_timeout_ms/0`, default e.g.
  5_000) and thread it through `Daemon.rpc/4`, so a hung/wedged peer fails fast instead of blocking
  the TUI's `receive` loop forever.
- **Residual gap**: the gate checks a *string*, so a compatible marker with an incompatible wire
  shape (e.g. a changed `Attachment` struct) is undetectable. Mitigation: include the marker in the
  hydration payload and re-check after attach (§9 OQ3).

### 6.7 Security posture

| Concern | Today | Proposed |
|---|---|---|
| Cookie value | Constant literal in the source (H3). | Random 32-byte hex, generated on first run, stored `0600` in `Daemon.Paths.cookie_file/0`; `ATHANOR_COOKIE` still overrides for CI/containers. |
| Cookie on disk | n/a | `0600` file, never logged, never printed; `--status` reports `cookie_source` only. |
| Binding | `Node.start(name, :longnames)` binds to whatever the host resolves; the default name is `@127.0.0.1`. | Document loopback as the default; when `ATHANOR_DAEMON_NODE` names a non-loopback host, warn that distribution is plaintext. |
| Trust model | Any process with the cookie can attach, read every transcript, and inject prompts. | Document as the explicit model; note that `send_session/2` is a **remote code-prompting** primitive — an attacker with the cookie gets tool execution (including `bash`) as the user. |
| Insecure default | Silently accepted. | Refuse to start with the source-tree default cookie unless `ATHANOR_ALLOW_INSECURE_COOKIE=1`; `--force` prints a loud banner. |
| SSH | n/a | `:ssh` uses port 2222, publickey only, no shell, no port forwarding, host key persisted `0600`. |
| Logs | none | `Daemon.Paths.log_file/0` at `0600`; redact cookie-like tokens. |

### 6.8 systemd `--user` unit [PROPOSED]

Installed by `mix athanor.daemon --install-service` to
`~/.config/systemd/user/athanor.service`:

After=network.target

[Service]
Type=simple

`ExecStart` must be rendered with the **absolute** `elixir`/`mix` path resolved via

`systemctl --user enable --now athanor`; uninstall disables and removes. `loginctl enable-linger` is
**suggested, not performed** — it changes the user's session policy and should stay explicit.

start the peer with `-name athanor_daemon_test_n@127.0.0.1 -setcookie <test cookie>`;
`Node.connect/1`; `:erpc.call(peer, Application, :ensure_all_started, [:athanor])` — which requires

publish; assert. Because `:peer` needs a build path, the harness lives in `test/support/multinode.ex`
and **requires `elixirc_paths/1` in `mix.exs`** (§2.2) — the file has none today, so alternatively the
helper is `Code.require_file/2`'d from `test/test_helper.exs`. Prefer `elixirc_paths/1`; it is the
conventional fix and keeps `test/support` out of `:prod`.

**Guard rails.** `@tag :multinode` tests are excluded by default on machines without `epmd`
(`ExUnit.configure(exclude: [:multinode])` in `test_helper.exs`, run with `--include multinode`).

and the support-path require is part of phase 2.

registered **before** the teardown trigger — the pattern already established in
`test/athanor/daemon_test.exs` after commit `b3e1a29`.

## 9. Risks, Edge Cases & Open Questions

### Risks

| # | Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|---|
| R1 | Cookie is a committed constant (H3) → any local process reads transcripts and injects prompts with `bash` tool access. | high | critical | `Daemon.Cookie` random `0600` cookie; refuse insecure default (§6.7), phase 1. |
| R2 | `--stop`/`--restart` kills sessions mid-turn, discarding in-memory transcripts (H6). | certain | high | Graceful drain + refuse-when-busy + `--force` (§6.1), phase 4. Until then, document loudly. |
| R3 | Auto-start inherits the client's cwd, so a session's `bash`/file tools run in an unexpected directory (H2). | high | high | Pin `cd` to `Config.daemon_workspace/0`; surface the workspace in `Daemon.status/0` and in the TUI title (§6.1). |
| R4 | Client silently freezes when the daemon dies (H1). | medium | medium | `monitor_nodes/1` + `{:nodedown, node}` clause (§5.3). |
| R5 | Leaked relay on a wedged dist connection keeps a `"deck:events"` subscriber alive for a dead client. | low | low | `{:DOWN, :noconnection}` already handles the normal case; add the inactivity sweep (§6.4). |
| R6 | The TUI process is not supervised; a crash in `render_frame/1` takes down the client VM and the alternate screen is left dirty. | low | medium | The `after` block already restores the screen on *normal* exit; add a `try/catch` around `loop/2` **[PROPOSED]**, or supervise the TUI. |
| R7 | Node-name mismatch (VM started with a foreign `--name`) silently mis-identifies the daemon (H5). | medium | medium | Validate and error (§5.1). |
| R8 | Build marker rots relative to `mix.exs` (H4). | medium | medium | Derive from `Application.spec(:athanor, :vsn)`; assert in a test. |
| R9 | 15 s auto-start timeout is too short on a cold `mix run` with uncompiled deps. | medium | low | `Config.attach_timeout_ms/0`; `mtime`-aware error text pointing at the log file. |
| R10 | Each attached client costs one extra daemon-side process plus one message copy per event (`relay_loop/2` forwards every `{:agent_event, …}` to a remote pid), so fan-out work and memory grow linearly with N. | low | low | Accept for v1 (N is small and human-driven); expose `attachments/0` via `Daemon.status/0` so N is observable, and revisit if watchers (§7.3) attach programmatically. |
| R11 | The `:ssh` subsystem opens a second, less-audited authentication path (host keys, `pwdfun`, port forwarding defaults). | medium | high | Publickey-only, no shell, no forwarding, default-off, explicit opt-in (§6.5, §6.7); tag-gated tests. |
| R12 | `:longnames` with `@127.0.0.1` is a loopback-only topology; §7.7's "SSH in from anywhere then attach" implies a *client* on the same host, which is fine, but users will try to attach across hosts. | medium | medium | Document that cross-host attach is §7.8's cluster work; the `:ssh` subsystem is the supported cross-host path. |
| R13 | `erl_crash.dump` at the repo root shows crashes are possible in this workspace; a daemon crash without systemd means silent death. | low | medium | pid file + log + systemd `Restart=on-failure`; `--status` detects a stale pid file. |

### Open Questions
- **OQ1 (must resolve).** §7.7 writes `athanor@127.0.0.1`; the code uses `athanor_daemon@127.0.0.1`.
  Fix the doc, or rename the node (which breaks any existing `.erlang.cookie`-pinned setup and
  `ATHANOR_DAEMON_NODE` overrides)? Recommendation: keep the code name, correct `docs/design.md` —
  the `_daemon` suffix is self-documenting and avoids colliding with a cluster node name in §7.8.
- **OQ2.** Should `--stop` default to graceful-with-refusal, or always drain and cancel? Refusing is
  safer but script-hostile; a `--force` flag covers scripted paths.
- **OQ3.** Is a build *string* a sufficient compatibility gate, or should the handshake also exchange a
  protocol version and the `Attachment`/`session_view` shapes? A string cannot detect a wire-format
  change.
- **OQ4.** Should the daemon persist a session manifest so `--stop` / crash does not lose the deck?
  This is §7.4 territory; until then `--stop` is genuinely lossy.
- **OQ5.** Is plaintext distribution acceptable for the SSH-anywhere story, or must the `:ssh`
  subsystem become the *only* remote path (i.e. clients never cross hosts)? TLS distribution
  (`-proto_dist inet_tls`) is one answer, `:ssh` is another.
- **OQ6.** Should the `athanor` escript ship as a Mix archive, an escript, or a `mix release`? Each has
  different install ergonomics for "SSH in and run `athanor`".
- **OQ7.** Is one daemon per user right, or should a shared system daemon with per-user sessions be
  designed now (it changes the cookie-per-user model)?
- **OQ8.** Does `mix athanor --local` remain supported long-term? It loses multi-client mirroring and
  detach-safety by construction (`docs/design.md` §8 OQ3 asks the same).

## 10. Suggested Incremental Milestones

Each milestone ends green: `mix test` passes, `mix format --check-formatted` passes, and the stated
manual check succeeds.

1. **M1 — Config unification (no behaviour change).** Move `daemon_node`/`cookie` resolution into
   `Athanor.Config`; add the new accessors and the env-var ledger; `Daemon.daemon_node/0` /
   `cookie/0` delegate. *Green:* existing `daemon_test.exs` unchanged; new
   `daemon_config_test.exs`.
2. **M2 — Security floor.** `Athanor.Daemon.Cookie` + `Athanor.Daemon.Paths`; refuse the source-tree
   default unless `ATHANOR_ALLOW_INSECURE_COOKIE=1`; `--status` prints `cookie_source`. *Green:*
   `daemon_cookie_test.exs`, `daemon_paths_test.exs`; manual `mix athanor` works with a generated
   cookie.
3. **M3 — Robust lifecycle.** pid file + log capture + `cd:` pinning + node-name validation + the
   `{:nodedown, node}` TUI clause + `Daemon.rpc/4` `try/catch`. *Green:* `tui_attach_test.exs`,
   extended `daemon_relay_test.exs`, `daemon_status_test.exs`; manual: kill -9 the daemon and watch
   the attached TUI report it instead of freezing.
4. **M4 — Graceful stop.** `Athanor.Daemon.Drain`; `--stop` refuses while busy, `--force` cancels;
   `--restart` composes stop→start and reports honestly. *Green:* `daemon_drain_test.exs`; manual:
   `--stop` during a streaming turn prints the busy session and exits non-zero.
5. **M5 — Attachment registry.** `Athanor.Daemon.Server` + `Athanor.Daemon.Attachment`,
   `"daemon:clients"` topic, `/clients` command, `Daemon.status/0`. *Green:* `daemon_status_test.exs`;
   manual: two terminals show each other.
6. **M6 — Entry points.** `mix athanor.attach`, `--server`/`--no-auto-start` on `mix athanor`, the
   `athanor` escript + `escript:` in `mix.exs`. *Green:* task I/O tests; manual:
   `./athanor --server athanor_daemon@127.0.0.1`.
7. **M7 — systemd `--user`.** `Athanor.Daemon.Systemd` + `--install-service`/`--uninstall-service`,
   absolute `ExecStart`, `Restart=on-failure`. *Green:* rendering tests (unit, no `systemctl`); manual
   install on the dev host.
8. **M8 — Multi-node test harness.** `test/support/multinode.ex`, `elixirc_paths/1` in `mix.exs`,
   `@tag :multinode` plumbing, `daemon_multinode_test.exs`. *Green:* `mix test --include multinode`.
9. **M9 — Native `:ssh` subsystem.** `Athanor.SSH`, `Athanor.SSH.Handler`, `Athanor.SSH.Session`,
   host-key generation, default-off config. *Green:* `ssh_handler_test.exs`; manual:
   `ssh -p 2222 -i key user@localhost` lands in the deck.
10. **M10 — Docs + drift.** Update `README.md`, `docs/architecture.md`, and correct `docs/design.md`
    §7.7's node name (OQ1); close OQ2/OQ3 with decisions.
